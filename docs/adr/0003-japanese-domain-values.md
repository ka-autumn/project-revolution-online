# ドメイン用語は型名を英語、値を日本語で表記する

型名・関数名・変数名は英語で書くが、総合ルールが定義する語はそのまま日本語のリテラル値として保持する（`type Zone = '山札' | 'プランゾーン' | 'スクエア' | ...`）。総合ルールは語を精密に使い分けており、英訳すると区別が潰れてルールバグになるため。

## 検討した選択肢

**全て英語に訳し、対訳表を正とする** — 最も慣習的だが、以下の 3 点が英訳で壊れる。

- **ゾーンとエリア** — 総合ルールは「エリアはゾーンではない」と明記している。Zone / Area と当てると、英語では自己矛盾した文がコードベースの中心に居座る。
- **味方 / 敵 / 仲間** — 「味方」はプレイヤーから見た関係、「仲間」はユニットから見た関係。英語の ally / friend はどちらにも読める。カードテキストが大量に参照するため、取り違えると効果範囲がずれる。
- **登場 / 置かれる** — 「登場」は「スクエアに置かれる」の一部でしかない。enter / put / place のどれを当てても、この包含関係は英語の語感から復元できない。

**ドメイン語も含めて全て日本語の識別子にする** — 訳の問題は完全に消えるが、外部ライブラリとの境界で表記が混ざる。

## 影響

- 裁定でもめたとき、総合ルールの語でそのまま grep できる。対訳表を引く手間が発生しない。
- 用語の正は `CONTEXT.md` に置く。同義語は `_避けるべき_` として明示的に禁じる。
