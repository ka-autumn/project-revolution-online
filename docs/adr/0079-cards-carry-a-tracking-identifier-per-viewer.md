# カードには、見る人ごとにサーバが振る追跡の識別子を持たせる

決定日: 2026-11-27。Issue #165（#134 の前提として）。開発者と決定した。

この文書は設計として先に書いた。実装した後で、実装で決定した名前を末尾の「実装」の節に書き足す。

## 背景

#165 と #134 は、カードがゾーンを移る時に、前の位置から次の位置へ動いて見えることを求めている。そのためには、画面が「前の盤面のこのカードと、次の盤面のこのカードは同じ 1 枚だ」と分かる必要がある。

今の通信では、見る人に見えているカードは、エンジンのカードの識別子（`CardInstance.id`）ごと届く（`perspective.ts` の `VisibleCard` の `見えている`）。見えていないカードは、向きだけが届き、識別子を持たない（`見えていない`）。そのため、次の場面で、画面は前後のカードを結び付けられない。

- 相手が引いたカード（山札でも手札でも見えていない）
- 裏向きでトラップゾーンに置かれたカード
- 自分の山札の上から手札へ来たカード（山札では見えていない）

一方、エンジンの識別子は、ゾーンを移っても変化しない。見えていないカードにまでそのまま付けると、見る人に届いていない情報が漏れる（#95）。例えば、相手の手札の 1 枚が、さっき手札に戻ったカードと同じかどうかが分かってしまう。

## 決定事項

### 見る人ごとに、追跡の識別子を振る

- サーバは、盤面を見る人ごとに、すべてのカードへ追跡の識別子を振って送る。見えていないカード（裏向きのカード・相手の手札・山札）にも振る。
- 追跡の識別子は、その人が目で追える間だけ同じものにする。目で追えるかの基準は、実際の卓で、その人がそのカードを他のカードと見分け続けられるかである。
  - 同じ識別子のままにする例: スクエアからスクエアへの移動、手札からトラップゾーンへ裏向きで置く、山札の上から手札へ引く
  - 振り直す例: 見分けの付かないカードの中へ混ざる時（相手の手札に入る、山札・束をシャッフルする）
- 画面は、カードを結び付けるのに追跡の識別子だけを使う。前の盤面にあった識別子が次の盤面の別の位置にあれば、そこへ動かす。前の盤面に無い識別子は、新しく現れたものとして扱う。

### どこで振るか

- 追跡の識別子は、サーバが部屋ごと・見る人ごとに持つ対応表で振る。置き場には書かない。
- 入り直した時（ADR-0009）とサーバが立て直した時は、対応表を作成し直してよい。どちらも、演出を見せずに最新の盤面を表示する場面なので（ADR-0080）、識別子が前と違っても困らない。
- 途中の盤面（ADR-0081）も、同じ対応表で振る。

### ルールは変更しない

- エンジンのカードの動き・判定の順番は変更しない。変更するのは、盤面を見る人ごとに落としたビューと、通信の形式だけである。

### デプロイの順番

- 盤面のビューに、追跡の識別子のプロパティを追加する。
- サーバを先にデプロイする。古い画面は、知らないプロパティを無視する（`connection.ts` の `parse`）ので、今のまま動く。
- 新しい画面が古いサーバにつながった時は、追跡の識別子が無い。画面は、カードを結び付けられないものとして、動かさずに最新の盤面を表示する（今の見え方と同じ）。
- どちらの順番でも壊れないが、演出を見せるにはサーバのデプロイが要る。

## 検討した選択肢

- **エンジンの識別子を、見えていないカードにも付けて送る。** 結び付けは簡単になるが、相手の手札のどれが、前に見えていたカードかが分かってしまう（#95）。採用しない。
- **識別子を持たせず、画面が位置の変化から推し量る。** ゾーンごとの枚数の増減から、どこからどこへ動いたかを推し量る。同時に複数のカードが動く場面（ルールエフェクトで複数を捨札に置くなど）で、取り違える。ゾーンの移り方を画面で判定することは、ルールの再実装に近づく（ADR-0010）。採用しない。
- **見る人ごとに、目で追える間だけ同じ識別子を振る。** 見えていないカードも動かせ、届いていない情報は識別子からも漏れない。採用した。

## 既存の決定との関係

- ADR-0010 は変更しない。画面は、識別子を突き合わせるだけで、ルールを判定しない。
- 「身元」は、ADR-0019 でログインした人のことを指す用語である。カードのこれは、紛らわしくならないよう「追跡の識別子」と呼ぶ。

## この決定が決定していないこと

- 今の通信は、見えているカードにエンジンの識別子を付けて送っている。表向きに見えていたカードが相手の手札に戻り、もう一度プレイされた時、同じ識別子で届くので、同じカードだと分かる。これを止めるかは、この決定では扱わない（別に報告する）
- 対応表のデータの形式と、プロパティの名前

## 影響

- サーバとエンジンの射影（`perspective.ts`）と、通信の形式を変更する。ルールは変更しない。
- 描き直し方の移行（ADR-0078）と並行して、別の PR で進める。演出（ADR-0080）より前に済ませる。
