# 決着には、誰がどの条件で敗北したかを持たせる

決定日: 2026-11-27。Issue #165。開発者と決定した。

この文書は設計として先に書いた。実装した後で、実装で決定した名前を末尾の「実装」の節に書き足す。

## 背景

#165 は、決着の演出で、なぜ決着したかを見せることを論点に挙げていた。

敗北の条件は 2 つある。スマッシュが 7 枚以上になること（総合ルール 第3部 第3章 1、第4部 第14章 4-1）と、山札にあるカードが 0 枚以下になること（同 第3章 2、第14章 4-2）である。両方のプレイヤーが同時に敗北した場合は、引き分けになる（同 第3章 4）。1 人のプレイヤーが、2 つの条件を同時に満たすこともある。

エンジンは、ルールエフェクトの中で、プレイヤーごとにこの 2 つの条件を判定している（`rule-effect.ts` の `isDefeated`）。しかし、決着のデータ（`DuelResult`）は `{ kind: '勝利', winner }` か `{ kind: '引き分け' }` だけで、どの条件で敗北したかを持っていない。

## 決定事項

### 決着のデータに、敗北したプレイヤーごとの条件を持たせる

- 決着のデータに、敗北したプレイヤーごとに、満たした敗北の条件（スマッシュ・山札）を持たせる。1 人が 2 つの条件を同時に満たした時は、両方を持たせる。引き分けでは、2 人分を持たせる。
- エンジンは、判定した時点で条件を知っているので、それを書き留めるだけにする。判定の順番・敗北の条件は変更しない。
- ログのできごと `決着した` は、決着のデータを含むので、同じく条件を含む。
- 決着の演出では、この条件を見せる（「山札が 0 枚になった」など）。言い回しと見た目は、対戦画面の仕様書で決定する。

### デプロイの順番

- 盤面のビューの決着のデータに、プロパティを追加する。
- 古い画面は、知らないプロパティを無視するので、今のまま勝敗だけを表示する。新しい画面が古いサーバにつながった時は、条件が無いので、勝敗だけを表示する。どちらを先にデプロイしても壊れない。
- 決着のデータは置き場に書いていない（打ち直せば同じ決着になる）ので、記録の移行は要らない。

## 検討した選択肢

- **理由を見せない。** 決着の演出は勝利・敗北・引き分けだけにする。エンジンを変更しない。しかし、山札が尽きたのかスマッシュで負けたのかは、プレイヤーが知りたいことである。採用しない。
- **画面が、最後の盤面から理由を推し量る。** スマッシュの枚数と山札の枚数を画面で比べることになり、敗北の判定を画面で再実装することになる（ADR-0010）。採用しない。
- **エンジンが、判定した条件を決着のデータに書き留める。** 理由を一番よく知っているのは判定したエンジンである。採用した。

## 既存の決定との関係

- ADR-0010 は変更しない。画面は、届いた条件を表示するだけである。

## この決定が決定していないこと

- 決着の演出の言い回しと見た目（仕様書に書く）
- プロパティの名前と値の形式
- 投了（同 第3章 7）は、まだ実装していない。実装する時に、条件の値として追加する

## 影響

- エンジンの決着のデータと、通信の形式を変更する。ルールは変更しない。
- 演出の本体とは別の PR にする。決着の演出を作成する段階より前に済ませる。

## 実装

- 敗北の条件の型は `DefeatCondition`（`'スマッシュ' | '山札'`）。敗北したプレイヤー 1 人分は `Defeat`（`{ player, conditions }`）。どちらも `packages/engine/src/duel.ts` に定義し、エンジンから公開する。
- `DuelResult` は、`勝利` と `引き分け` の両方に `defeats: readonly Defeat[]` を持つ。敗北したプレイヤーごとに 1 つで、引き分けでは 2 つになる。
- `defeats` の並びは先攻・後攻の順、`conditions` の並びは `スマッシュ`・`山札` の順に固定する。
- `rule-effect.ts` の `isDefeated` は `defeatConditionsOf` に置き換えた。満たしている条件の並びを返し、空なら敗北していない。条件の中身と判定の順番は変更していない。
- 画面が受け取る型は、`packages/engine/src/wire.ts` の `WireDuelResult`。`DuelResult` の `defeats` だけを省略できる（古いサーバからは届かないため）。盤面の `result` と、ログの `決着した`（`WireDuelEvent`・`WireLoggedEvent`）の両方がこの型になる。`toWire` の戻り値の型では、`defeats` を省略できないままにしている。
- 画面の表示は変更していない。
