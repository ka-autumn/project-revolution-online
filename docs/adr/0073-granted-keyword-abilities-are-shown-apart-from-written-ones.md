# 与えられたキーワード能力は、書かれたものと見分けて表示する

決定日: 2026-11-14。開発者と決定した（#335）。

## 背景

プランゾーンのカードに「夢」を与える効果は、作成された継続効果として実装できる（ADR-0036）。ADR-0070 で、常在型能力としても実装できるようになる（EB1.0 の 026）。ADR-0036 は、与えられたキーワード能力を、書かれたものと同じアイコンで表示すると決定した。

その結果、プランゾーンのカードに書かれていない「夢」のアイコンが表示されても、プレイヤーには、そのカードが「夢」を持っているのか、何かに与えられたのかが分からない。書かれていない能力でプランゾーンからプレイできる理由を、プレイヤーが読み取れない。

## 決定事項

- **与えられたキーワード能力は、書かれたものと見分けて表示する。** ADR-0036 が決定した、与えられたキーワード能力を書かれたものと同じアイコンで描くことを、この決定で変更する（アイコンを作成する関数は同じで、与えられた分に「＋」の宝石を追加する）。
- **プランのカードのアイコン:** アイコンの右下に、同じ質感の小さな「＋」の宝石をはめ込む。宝石の色は、そのアイコンと同じで、どの地の上でも読めるよう、白い縁取りを付ける。小さい画面でも、十字がつぶれない大きさにする。読み上げでは「夢（与えられた能力）」と伝える。
- **カードの詳細:** 書かれたテキストの末尾に、与えられたキーワード能力 1 つにつき 1 行を追加する。行頭は「●」ではなく太い十字の「＋」で、色はアイコンの宝石と合わせ、暗い地（黒いカードなど）でも読めるよう、白い縁取りを付ける。続けて、そのキーワード能力のテキスト（「夢（プランゾーンからプレイできる）」）を表示する。「与えられた能力」という注記は目には表示せず、読み上げにだけ伝える。
- **与えられた分は、画面が差分で取得する。** 盤面が送る、適用した後のキーワード能力の並び（`effectiveKeywords`）から、カードに書かれたキーワード能力の並びを引いた残りを、与えられた分とする。通信のデータの形式は変更しない（ADR-0070 の決定を維持する）。
- **書かれたものと同じキーワード能力が与えられた場合は、強調しない。** 並びに含まれる項目が 1 つのままで、書かれた分と区別がつかない。アイコンも詳細も、書かれた「夢」と同じ見た目のままにする。

## 検討した選択肢

**アイコンを赤い輪で囲む** — 目立つ。しかし赤は、BP・SP が上がったときの色と、相手の枠の色に使っていて、意味が重なる。採用しない。

**アイコンを金の輪で囲む・点線の輪にする** — アイコンの外に飾りが付き、アイコンと一体に見えない。採用しない。

**宝石を内側から光らせる** — すっきりするが、何が追加されたかが伝わりにくい。採用しない。

**通信に、与えられた能力の並びを追加する** — 画面の処理が単純になる。しかし通信のデータの形式が変更され、古い画面・サーバとの互換を考える必要がある。画面はカードに書かれた能力を知っているので、差分で足りる。採用しない。

**カードの詳細に、「与えられた能力」の注記を、目に見える形で表示する** — 行頭の「＋」で、与えられたことは伝わるので、不要と判断した。読み上げにだけ、注記を残す。

## 既存の決定との関係

- **ADR-0036。** 与えられた能力を、書かれたものと同じアイコンで描く決定を、この決定で変更する。与えられた能力を適用した後のデータに含める仕組みは、そのまま使う。
- **ADR-0070。** 通信のデータの形式は変更しない。決定どおり、仕様書とモックは、この決定で変更する。
- **ADR-0044。** 見た目を変更するので、仕様書（`docs/screens/duel/spec.md`）とモックを先に直した。

## この決定が決定していないこと

- **スクエアのユニットに与えられた能力の見え方。** 今、スクエアのユニットに能力を与える実カードが無い。
- **手札・捨札のカードに与えられた能力の見え方。** ADR-0070 が、そのテキストを実装する時に決定すると定めている。
- **「夢」以外のキーワード能力が与えられた場合の文。** 与えられるのは「夢」だけで、ほかの種類は、与えられるようになる時に追加する（`view-model.ts` の `grantedKeywordText`）。

## 影響

- 与えられたキーワード能力を持つプランのカードの、アイコンとカードの詳細が変更される。書かれたキーワード能力だけを持つカードの表示は変化しない。
- 古いサーバは `effectiveKeywords` を送らないので、その場合は、与えられた分が無いものとして扱う。

## 実装

- 与えられた分: `CardView` の `grantedKeywords`（`view-model.ts` の `faceUpView` が、適用した後の `keywords` から、カードに書かれた `keywords` を引いて取得する）。
- 詳細に追加する行の文: `grantedKeywordText`（`view-model.ts`）。与えられる種類は「夢」だけで、ほかの種類は、キーワードの名前だけを返す。
- アイコン: `keyword--与えられた`（`render.ts` の `keywordElement`）。右下の「＋」の宝石は、`style.css` の `::after` で描く。読み上げの `aria-label` は、「夢（与えられた能力）」。
- 詳細の行: `card__granted`（`render.ts` の `grantedParagraphs`）。行頭の十字は `card__granted-mark`（SVG）、読み上げにだけ伝える「与えられた能力」の注記は `card__granted-reading`。
