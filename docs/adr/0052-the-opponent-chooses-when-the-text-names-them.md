# テキストが相手を指定した選択は、相手に聞く

決定日: 2026-10-24。Issue #335。開発者と決定した。

この文書は設計として先に書いた。実装した後で、実装で決めた名前を末尾の「実装」の節に書き足す。

## 背景

この文書を書いた時点では、効果の中で選ぶのはいつも能力の支配者だった（`resolve.ts` の `選ぶ`）。効果が選ばせる命令に、相手に選ばせる形が無い。

総合ルールは、解決の時に必要な選択を「テキストが指定したプレイヤー」が行うと書いている（総合ルール 第4部 第8章 2-3）。テキストが相手を指定する形は、ブースターの弾「EB1.0」に 12 枚ある。うち 9 枚は、この形が無いことだけで書けない。形は 2 つある。

- 相手が自分の手札から選んで捨てる。キーワード能力「才気」（総合ルール 第5部 第10章 2「このカードが登場した時、相手は手札を１枚選んで捨てる」）を含む
- 相手が、支配者の手札を見て選び、捨てる

後の弾まで数えると、相手が自分の手札から選んで捨てる形が 40 枚ほど、相手が手札以外の自分のカード（エネルギー・スクエアのユニット・スマッシュ・山札）を選ぶ形が 13 枚、相手が支配者の見えないカードを見て選ぶ形がもう 1 枚、相手が自分の手札から残すカードを選び、残りを捨てる形が 1 枚ある。通信で相手に答えを求める流れは、どの形でも同じである。EB1.0 だけを見て形を決めると、後の弾で作り直すことになるので、これらもまとめて設計の対象にした。

相手の手札は非公開の情報で（総合ルール 第2部 第23章 2-1）、効果からは読めないことを型で保証している（`effect.ts` の `DuelView.hand`、ADR-0004）。この保証は崩さない。

### いまの仕組みで、すでに足りているもの

- 選ばせる手立て（`resolve.ts` の `Chooser`）は、誰に聞くか（`player`）を受け取る。サーバは選択の要求をその人にだけ送り、答えもその人からだけ受け付ける（`room.ts` の `advance`・`answer`）。行動している側ではない人に、行動の途中で聞く流れは、いまでも流れている（トラップの効果で、トラップの支配者が選ぶ場面）。
- CPU は、自分に聞かれた選択に自分で答える（`room.ts` の `cpuStep`）。
- 記録に残すのは行動と答えの番号の並びで、誰が答えたかは残さない（ADR-0008・ADR-0018）。誰に聞くかは、打ち直すたびにエンジンが同じに決める。

## 決めたこと

### 誰が選ぶか

- **テキストが相手を指定した選択は、相手が選ぶ。** 「才気」も、ルールのとおり相手が自分の手札から選ぶ。相手は自分の手札の中身を知っているので、ランダムに捨てる効果とは違う。ランダムに捨てると読み替えると、相手が手放すカードを選べなくなり、原本より強いカードになる。

### 効果の命令

候補を効果に見せてよいかどうかで、命令を 2 本に分ける。

- **(i) 候補を効果が作れる形は、いまの `選ぶ` 命令に「選ぶ人」を足して書く。** 選ぶ人は支配者か相手で、既定は支配者である。支配者の手札・支配者の山札の上のカード（相手が支配者の見えないカードを見て選ぶ形）と、公開されている相手のカード（エネルギー・スクエアのユニット）がこれにあたる。支配者の見えないカードを相手に見せる時は、ADR-0041 の見せる一覧を、向きを逆にして相手へ届ける。
- **(ii) 候補を効果に見せられない形は、エンジンが候補を作り、選んだ後の処置まで 1 つにした命令にする。** 効果は候補に触れない。EB1.0 で要るのは「相手が自分の手札から N 枚選んで捨てる」の 1 本だけである。相手のスマッシュ・相手の山札・相手の手札から場へ出す形は、そのテキストを書く時に、同じ形で命令を足す。
- **(ii) の命令は、効果に何も返さない。** 捨てたカードを効果が読むテキストは、後の弾まで見ても無い。要るテキストが出たら、その時に捨札へ置いたカード（公開されたもの）を返す形を足す。公開されたカードなので、足しても見えない情報は漏れない。

### N 枚を選ぶ時

- **答えは 1 枚ずつ N 回、捨てるのは N 枚を選び終えてから同時に。** 選んだカードは、次の候補から外れる。途中で盤面は変わらない。答えと記録の形は、今のまま（候補の番号を 1 つずつ）である。
- **手札が N 枚以下なら聞かない。** 選ぶ余地が無いので、あるだけ捨てる（総合ルール 第4部 第10章 の【例】）。0 枚なら何も起きない。
- **画面は N 枚をまとめて選ばせる。** 選択の要求に「N 枚続けて選ぶうちの何枚目か」を表す、省略できる項目を足す。画面はこれを見て、手札の一覧で N 枚に印を付けさせ、「決定」で 1 枚目の答えを送る。続きの選択の要求が届いたら、印を付けたカードを識別子で候補から引き直し、人の操作なしに送る。答えの形は変えずに、相手の操作を 1 回にまとめるためである。
- 1 枚目を送った後に回線が切れて繋ぎ直した時は、続きの選択の要求だけが届く。画面は 1 枚目を知らないので、残りの枚数を選ぶ形で出す。選んだカードは候補から外れているので、正しく選び直せる。

### 戻る・取り消す

1 つの行動の途中で選ぶ人が入れ替わる時は、次のとおりにする。

- **行動していない側は、自分が続けて答えた分の中だけ戻れる。** 行動そのものは取り消せない。
- **行動した側は、行動していない側が 1 つでも答えた後は、それより前へ戻れない。**
- 新しく見えたものがあれば戻れない、という今の決まり（`protocol.ts` の `describeChoice`）は、そのまま重ねてかかる。

相手の誤操作は直せて、相手の答えを見てから行動を取り消してやり直すことはできない形である。いまは選んでいる人なら誰でも、直前の答えを戻し、行動そのものを取り消せる。相手の答えで新しく見えるカードが無い時（エネルギーをフリーズする時など）、行動した側は相手の選び方を見てから取り消せてしまう。トラップの効果で行動していない側が選ぶ場面にも、この決まりがかかる。

### 見え方とログ

- **(ii) の選択には、選択の目的 `捨てる手札` を足す。** 相手の画面は、何を選んでいるのか（自分の手札を捨てる）を見出しで伝える。(i) の選択は、今までどおり `効果の対象` のままにする。何のための対象かはテキストが決めるためで、画面は「相手のカードの効果で選ぶ」として、発生源のカードを添える。画面の文言は `docs/screens/` の仕様書で決める。
- **捨てたカードの名前は、ログに出す。** 捨札に表向きで置かれ、2 人に見えるためである。行の持ち主は能力の支配者で、今の「命令を実行した」と同じ形で積む。
- **相手が支配者の手札を見たことは、ADR-0041 と同じく、ログに 1 件積み、2 人に同じ名前で出す。** 見られた側にとっては自分の手札なので、新しく知る情報は無い。支配者の手札が 0 枚なら、選択を出さず、ログだけを積む。

### 「才気」

- **「気合」と同じく、誘発型能力を 1 つ使い回す形で持つ**（`ability.ts` の `spirit` と同じ形）。中身は「登場した時、相手は自分の手札から 1 枚選んで捨てる」で、(ii) の命令を使う。能力として持つ・与える・得る、のどれも、ほかの誘発型能力と同じ道を通る。表記に載せることは #227 で扱う。

## 検討した選択肢

- **「才気」など、相手が自分の手札から捨てる形を、ランダムに捨てると読み替える。** 相手の操作が挟まらない。しかし、総合ルールでは選ぶのは手札を知っている相手で、読み替えると原本より強くなる。採らない。
- **EB1.0 にある 2 つの形だけを対象にする。** 設計は短く済む。しかし、後の弾で 2 番目に多いのは相手が手札以外の自分のカードを選ぶ形で、それが出た時に選択の要求の形と記録の扱いを見直すことになる。採らない。
- **形ごとに専用の命令を足す。** EB1.0 のためには最小で済む。しかし、後の弾の形が出るたびに命令が増え、「選ぶ人」が命令ごとにばらばらに書かれる。採らない。
- **汎用の命令を 1 本にする（候補の置き場・絞り込み・選んだ後の処置を項目で持つ）。** 1 本で済む。しかし、置き場と処置の組み合わせを項目で表すことになり、相手の手札を候補にして選んだカードを効果に返す、という組み合わせが型の上で書けてしまう。採らない。
- **相手が選ぶ選択では、戻る・取り消すを一切出さない。** 作るのは簡単だが、相手は N 枚を選ぶ途中の押し間違いを直せない。採らない。
- **一度に N 枚を選ぶ選択を作る。** 操作は 1 回で済む。しかし、答えの形（番号の組）・通信・CPU の答え方・打ち直しの記録のすべてに、新しい種類の答えが要る。画面の側でまとめて選ばせ、1 枚ずつ送れば、同じ操作を答えの形を変えずに得られる。採らない。
- **(ii) の命令が、捨札に置いたカードを返す。** 後でテキストが出ても、命令を変えずに済む。しかし、使う人のいない返り値で、何を返すか（カードか、枚数か）を推測で決めることになる。採らない。
- **(ii) の選択にも目的を足さず、すべて `効果の対象` にする。** 作るものは少ない。しかし、自分の手札を捨てるという重い選択で、何を選んでいるのかが見出しから分からない。採らない。

## 既存の決定との関係

- **ADR-0004・ADR-0041。** 効果から相手の手札を読めない、という型の保証は残る。(ii) の命令は、相手の手札を候補にするが、候補も選ばれたカードも効果に返さない。選択の要求は、選ぶ人（相手）にだけ届く。相手にとっては自分の手札である。
- **ADR-0008。** 選択を「候補の中から 1 つ選ぶこと」とし、要求を選ぶプレイヤーにだけ送る、という枠は変えない。選択の要求に、N 枚続けて選ぶうちの何枚目かを表す項目が加わる。戻れるかどうかに、選ぶ人が入れ替わった時の決まりが加わる。同 ADR の冒頭に、この 2 点を知らせる 1 行を足す。
- **ADR-0018。** 記録の形は変えない。誰に聞くかはエンジンが決めるので、答えの番号の並びだけで同じところへ打ち直せる。戻る・取り消すの決まりは、対戦の最中の操作にだけかかる。記録に残るのは行動が終わって確定した答えだけ（`room.ts` の `advance`）なので、打ち直しには関わらない。
- **ADR-0038。** 古い画面には、知らない選択の目的と、知らない項目として届く。知らない目的は「選んでください」と出て、知らない項目は捨てられ、N 枚を 1 枚ずつ選ぶ形で動く。

## この決定が決めていないこと

- **相手の手札の枚数を、効果が読むこと。** 「相手の手札が N 枚以上なら、相手は自分の手札を 1 枚選び、捨てる」のような形と、捨てる枚数が相手の手札の枚数から決まる形は、相手の手札の枚数を読む口が要る。別の決定になる。
- **支配者が、相手の手札を見てその中から選ぶこと。** 選ぶのは支配者で、相手の手札のカードを候補にする形が要る（ADR-0041 が決めていないこととして残したもの）。別の決定になる。
- **相手が、手札以外の自分のカードを選ぶ形と、残すカードを選ぶ形の、具体的な命令。** (i) と (ii) のどちらで書けるかの見込みは上に書いた。命令の形は、そのテキストを書く時に決める。
- **相手自身の行動に付く代償**（「敵が移動する時、相手はエネルギーを選んでフリーズする。そうできないなら移動できない」など）。移動の追加コストとして書けている（総合ルール 第4部 第6章 2-2）。この決定の対象ではない。

## 影響

- 効果の命令が 1 つ増え、`選ぶ` 命令に項目が 1 つ増える。選択の目的が 1 つ増え、選択の要求に省略できる項目が 1 つ増える。
- 戻れるかどうかの判定に、誰が答えたかが加わる。サーバは今までどおり、エンジンの判定を尋ねて従う。
- 相手の画面に、相手の手番の途中で、自分の手札を捨てる選択が届くようになる。画面の仕様書とモックを、実装の段で先に直す（ADR-0044）。
- CPU と、ランダムに手を選ぶ自己対戦は、特別扱いなしで進む。候補から 1 つずつ答える形が変わらないためである。
- **この決定で書けるようになるカード（EB1.0 の番号）。** 031 042 053 058 060 063 070 086 095。052・055・075 は、相手に選ばせる部分は書けるようになるが、ほかの不足（相手の手札の枚数を読む、支配者が相手の手札を見て選ぶ）が残る。

## 実装

- `選ぶ` 命令の項目: `picker: '支配者' | '相手'`（省略すると `支配者`）。相手が選ぶ形は `letOpponentChooseFromMyHand` だけが出す
- 相手に自分の手札から捨てさせる命令: `相手に手札を捨てさせる`（項目は `count`）。効果に書く関数は `discardOpponentHand`
- 支配者の手札を相手に見せて 1 枚まで選ばせる関数: `letOpponentChooseFromMyHand`。見せたことは、ログの `相手に手札を見せる` に積む（項目は `count` と `cards`）。捨てたカードは、ログの `相手に手札を捨てさせる` に積む（同じく `count` と `cards`）
- 選択の目的: `捨てる手札`
- 「才気」: `ability.ts` の `wit`
- `WireChoice` の変更
  - `answered` は、いま選んでいる人が続けて答えた数に変えた。選ぶ人が替わると 0 から数え直す。数えるのは `applyWithAnswers`
  - `mayCancel`: 行動そのものを取り消せるか。選んでいる人が行動した側で、行動していない側がまだ 1 つも答えていない時だけ真
  - `series?: { nth: number; of: number }`: N 枚続けて選ぶうちの何枚目か（`nth` は 1 から数える）。1 枚だけ選ぶ選択には載せない
- 戻る・取り消すの断り方（`room.ts` の `rewind`）は、エンジンの `answered`・`mayCancel`・`mayGoBack` に従う。断る理由に `戻せる答えが無い` と `相手が答えたので戻れない` を足した
- `Chooser` に、8 番目の引数 `series` を足した
