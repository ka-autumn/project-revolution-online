# クリックモードで、行える手を盤面の行き先とダイアログで出す

対戦画面の「操作のしかた」が「クリック」のとき（以下クリックモード）、カードを選んだあとの手は、パネルにボタンとして並んでいた（Issue #94）。カードを選んでから別のボタンを探して押すことになる。ここでは、**ボタンを優先権の放棄くらいまで減らし、何をしようとしているかが操作の流れで分かる形にする**（Issue #248・#249）。

**変えるのは、届いた手を「どこで押させるか」だけである。** どの手を行えるかを決めるのはサーバで、画面は届いた手から並べる（ADR-0010）。通信の形・サーバ・ボタンモードは変えない。選択（コストや効果の対象など）の中の能力の候補をダイアログにすること（Issue #250）と、クリックモードのキーボード操作（Issue #251）は、この ADR の範囲外である。

## 用語

- **ボタンモード**: 行える手をすべてボタンとして並べる、「操作のしかた」の「ボタン」。
- **行き先**: カードを選んだあとに、盤面で押す場所。スクエアと、自分のトラップゾーン。山札は、カードを選ばずに押して始める入口なので含めない。
- **選びかけ**: カードか山札を選んだが、まだ手を送っていない状態。効果の解決などで求められる「選択」とは別のもので、何も送らない。
- **聞く**: 確認ダイアログか選ぶダイアログで、行う手を尋ねること。
- **確認ダイアログ**: 画面の中に重ねて、手を 1 つ行うかを尋ねるもの（「〇〇する」「キャンセル」）。
- **選ぶダイアログ**: 画面の中に重ねて、選んだカードで行える手が 2 つ以上あるときに、どれを行うかを選ばせるもの。

## 決めたこと

### 手ごとの流れ

カードを押して選んだあと、そのカードで行える手によって出方が変わる。

| 手 | 流れ |
|---|---|
| ユニットのプレイ・移動 | スクエアを押す（今のまま） |
| トラップとしてプレイする | 自分のトラップゾーンを押す（新しく行き先にする） |
| エネルギーを置く・ストラテジーのプレイ・トラップの発動と廃棄・スマッシュ・「勇気」・起動型能力 | 確認ダイアログ |

- **行える手が 1 つで行き先のある手なら、行き先が光る。** 行き先の無い手が 1 つだけなら、確認ダイアログで聞く。
- **行える手が 2 つ以上なら、選ぶダイアログで聞く。** 行き先のある手を選んだら、そのあと行き先が光る。聞き直さない。
- **手札のユニットは例外。** 行える手が「スクエアにプレイする」「トラップとしてプレイする」だけなら、ダイアログを出さず、スクエアと自分のトラップゾーンを同時に光らせる。ほかの手が混じるなら選ぶダイアログを出す。
- **手札のストラテジーも、行える手が 1 つなら同じ決まりに揃える。** 「トラップとしてプレイする」だけならトラップゾーンが光り、「プレイする」だけなら確認ダイアログが出る。2 つ以上なら選ぶダイアログである。
- **同じスクエアを指す手が 2 つ以上あり、押した場所だけで決まらないときも、選ぶダイアログで聞く。** 見分けがつくよう、手の呼び名に行き先を添える。

### プラン

- 「プランする」ボタンをやめ、**山札（プランゾーンにカードがあれば、山札の場所に見えているそのカード）を押して始める。**
- **山札を押したら、毎回「プランする」の確認ダイアログを出す。** コストが 1 枚だけで自動で選ばれるかどうかは、届く手（`プランする`）から分からない。画面の側で数えれば、ルールの判断を写すことになる（ADR-0010）。通信に載せるのは今回の範囲を超える。押した瞬間に実行されないようにする、という目的は毎回の確認で足りる。
- プランゾーンのカードをプレイすることもできるときは、選ぶダイアログ「プレイする」「プランする」を出す。
- プランする手はカードを指さないが、**山札の場所に見えているものを押す**ので、そのカードの手の 1 つとして聞く。プランゾーンのカード以外を選んだときは混ぜない。

### カードを選んでいる間

- **そのカードに関係ない手を出さない。優先権の放棄のボタンも出さない。** Issue #94 では、カードに紐づかない手を「いつでも押せる」としていた。これを反転させる。選んでいる間に出ていると、押すつもりのない手が目に入り、選びかけの手と見分けにくい。**画面に出すかどうかだけを変えていて、送れる手は変わらない。** 選択を外せば戻る。
- 選択を外すボタンは残し、文言を「選ぶのをやめる」から**「カードの選択をやめる」**にする。選択中（効果の解決など）の「この行動をやめる」は、始めた行動を取り消す別のものなので、紛らわしくならないようにする。こちらは押す前の選びかけを外すだけで、何も送らない。
- 次のどれでも、選ぶ前に戻る: そのボタン・選んでいるカードをもう一度押す・Esc・**押せるもの以外のどこかを押す**。押せるものは、押せるカード・光っている行き先（スクエア・トラップゾーン）・押せる山札・ボタン（ボタンのように振る舞うもの全般。捨札・リムーブの束を開くものを含む）・カードの一覧（捨札・リムーブを見る一覧と、効果で選ぶ一覧）・ダイアログ・**右の列（カードの詳細）**である。右の列を押しても外さないのは、文字を選ぼうとしたり、詳細を読もうと触れたりしただけで選びかけが閉じないようにするため。押せないカードを押したときは外れる。**ほかの押せるカードを押したときは、外さずにそのカードに選び直す**（今のまま）。
- ダイアログの「キャンセル」・Esc・暗くしたところを押す、は、ダイアログを閉じてカードを選んでいない状態に戻す。
- **パネルの案内文は「選択」の言い回しで書く。** カードだけが押せるなら「操作するカードを選択してください」、山札だけなら「プランするには、山札を選択してください」（「プランする」ボタンをやめたので、案内文が入口を示す）、両方なら両方を、行き先が光っているなら「置く場所を選択してください」と出す。押せるものが無いときは、相手が優先権を持つ間は「相手の操作を待っています」、自分が持つ間は「選択できるカードがありません」と出す（相手が優先権を持つ間は、自分の手は空で届く）。ダイアログが聞いている間は、ダイアログ自身が聞くので出さない。

### ダイアログの作り

- **対戦画面専用の部品を新しく作る。** デッキ構築の確認ダイアログ（ADR-0028、`confirmElement`）は広げず、そちらには手を入れない。使い回すと、画面全体を覆って右の列のカードの詳細まで暗くなる。迷ったときにカードのテキストを読みながら決めたいので、**重ねる範囲は、効果で選ぶ一覧（ADR-0027）と同じ**にする（右の列は覆わない）。デッキ構築の確認ダイアログは戻せないことを聞くので「決める」側を赤くして、最初の手をキャンセルに置くが、ここは手を行うために出しているので、そうしない。
- 見た目の基準（色・枠・角丸・影・見出しの字）は、デッキ構築・対戦の既存のものから引く。**効かせる場所は対戦画面の外枠（`.duel`）の内側だけ**で、ほかの画面・ボタンモードには及ばない。
- **見出しはカード名**（山札なら「山札」）、その下に何を聞いているか（確認なら「プランしますか？」「エネルギーとして置きますか？」のように手ごとの文、選ぶなら「どの手を行いますか？」。手の呼び名は言い切りの形で、「を行いますか」に当てはめると不自然になるので、確認の文は手ごとに持つ）を書く。読み上げでは、見出しを名前に、聞いていることを説明に結び付ける。
- 確認は、左にキャンセル・右に手（金の主ボタン）を置く。選ぶは、手を縦に同じ重みで並べ、**キャンセルを最後に右寄せ**で置く。最初に手を置くのは、確認なら手、選ぶなら先頭の手である。
- **手を送ったあとは、返事が届くまで、ダイアログのボタンをすべて押せなくし、「通信中…」を出す。** 手を送っても、返事（盤面など）が届いて描き直されるまで、ダイアログは古い画面のまま残る。その間に押されると 2 通目が送られ、サーバに断られて「行えませんでした」が出る。送った手は取り消せないので、キャンセル・Esc・暗くしたところを押す、も効かせない。回転する表示（スピナー）は使わない（描き直しで作り直されるため、ADR-0027）。行き先を絞るだけの選択肢は何も送らず、すぐ描き直されるので、待たせない。
- 手が多く、低い窓で箱が画面より高くなるときは、箱の中でスクロールさせる（ダイアログの層は動かないので、はみ出した上下に届かなくなるため）。
- ブラウザ標準のダイアログ（`window.confirm` など）は使わず、画面の中に重ねる。

### 押せない手を出さない・繋がっていない間は答えを送れない

- ダイアログに並べる手・光らせる行き先は、サーバから届いた手だけから作る。画面の側で「ここに置けるはず」を計算しない（ADR-0010）。
- **選びかけとダイアログは、行える手が入れ替わる時に捨てる**（盤面・選んでほしい・席についた）。届いた手は入れ替わっていて、その手がまだ行えるとは限らない。選び終えた手の種類も同じに捨てる。`相手の繋がり` のように行える手を変えないものでは捨てない（ダイアログを読んでいる途中で閉じないため）。
- **切断したら、何も送らずに閉じる。** 繋ぎ直した先で、その手がまだ行えるとは限らない（ADR-0016）。演出が出ている間（#115）はそもそも開かない。
- 押せることは色だけで区別させない。行き先（スクエア・自分のトラップゾーン）と山札は、名前と「押せます」の状態を読み上げに出す（今のカードと同じ）。スクエアとトラップゾーンは、押したら何が起きるか（手の名前）も添えて「（押せます: 手の名前）」とする。選んでいる山札は「選択中」とする。
- 山札とトラップゾーンは、Enter・Space でも押せる。カードとスクエアを含む、盤面のキーボード操作の全体は Issue #251 で扱う。

## やらないこと

- 選択の中の能力の候補をダイアログで選ぶこと（Issue #250）。
- クリックモードのキーボード操作の全体（Issue #251）。山札とトラップゾーンの Enter・Space だけは、新しく足した押す先なので今回入れた。ダイアログは最初から手を置く先と Esc を持つので、後から盤面のキーボード操作を足せなくなる作りにはしていない。
- ボタンモードの流れ。ボタンモードを残すかどうかは、クリックモードがキーボードで操作できるようになったあとに、改めて決める。
- 通信の形・サーバ・ルールの判断。

## 影響

- **カードを選んだあとに「クリック」でパネルに出る手のボタンは、優先権の放棄だけになる。** カードを選んでいる間は、それも出ず、「カードの選択をやめる」だけが出る。
- 既存のテスト「カードに紐づかない手は、カードを選んでいる間も押せる」は、反転した決まりに合わせて書き換える。
- `input-model.ts` の `pickView` が、選びかけ（カード・山札・聞いて選び終えた手）から、行き先とダイアログを返す。`index.ts` はそれを描き、押されたものを送る。
