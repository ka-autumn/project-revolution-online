# ロビーで相手を決め、CPU はその部屋に座る

対戦を始めるところを**ロビー**にする。合言葉を決めるのはサーバで、打つ前に相手と申し合わせるものを無くす。CPU との対戦は、**繋がっていない参加者が部屋に座っている**形で行う。

これまで対戦を始めるには、2 人が同じ合言葉を決めておき、それを URL に手で付けて開く必要があった（ADR-0009）。立て方を知っている人にしか使えず、1 人では始められもしなかった。**足りなかったのは対戦の仕組みではなく、そこへ入る道である。**

## 決めたこと

- **部屋の合言葉はサーバが決める。** ロビーに並んだものから選んで入るので、人が覚えて伝えるものが無い。合言葉を直に指して入る道（`?room=`）は残す。合言葉を知っている相手と待ち合わせるのに要る。
- **合言葉はシャッフルのシードと別に引く。** ロビーに並ぶ合言葉は全員に見えるので、シードから作ると山札の並びが読み取れる（ADR-0005）。
- **ロビーには部屋の名前だけを出す。** そこにいる人の名乗りは出さない。名乗りは認証ではなく、知っている人がその席に座れる合言葉である（ADR-0009）。一覧に出すと、居合わせた誰でも他人の席に着ける。
- **ロビーはどの部屋にもいない人に押し出す。** 尋ねる仕組み（購読・問い合わせ）を作らない。部屋の様子が変わりうるたびに、部屋にいない接続へ送り直す。誰かが部屋を作れば、ほかの人の一覧にすぐ出る。
- **名乗りは画面が作り、ブラウザごとに覚える**（`localStorage`）。アカウントは作らない（ADR-0009 のまま）。**閉じても同じ席に戻れることを優先する。** 画面が作った名乗りは人が控えられないので、忘れると自分の席へ戻る手立てが無くなる。そのぶん同じブラウザの 2 つのタブは同じ人になるので、手元で 2 人ぶん試すときは `?participant=` で名乗り分ける。
- **相手が繋がっていない対戦からは、打っている途中でも抜けられる。** 相手が画面を閉じるとその席には誰も戻ってこない。残された側が永久に待たされ、その部屋もロビーに残り続けることになる。**回線が切れただけなら相手は戻ってくる**（ADR-0016）ので、抜けるかどうかは人が決める。サーバは口を開けるだけである。
- **相手が繋がっているかを画面に伝える。** 相手が閉じると、待っている側の画面は相手の優先権のまま動かなくなる。**止まっている理由が読めないままにしない。** 誰が繋がっているかを知っているのは接続を持つ側（`server` の `serve.ts`）なので、部屋にはそれを渡す。
- **CPU は部屋に座る参加者である。** 別のプロセスとして繋ぎに来るのでも、部屋の外から盤面を進めるのでもない。部屋から見れば人と変わらない 1 人で、**違うのは繋がっていないことだけ**である。宛てたメッセージは届く先が無いので捨てる。
- **CPU も人と同じ道筋で打つ**（`server` の `room.ts` の `advance`）。CPU のために別の進め方を作らない。人が打ち終わったところで、CPU の優先権が続く限り打たせ、人に戻ってから送る。
- **CPU が選ぶ候補からは、選ばない手を外す。** いまのところ「トラップ以外のカードをトラップゾーンに置く」だけである（総合ルール 第2部 第20章 3-1 で行えるが、同 3-6 により発動できない）。**合法手そのものは狭めない。** ファザは合法手すべてを引き続き引く（ADR-0005）——選ばせない手を作ると、その手が通る道筋がテストされなくなる。
- **CPU との対戦は打っている途中でも投げ出せる。** 人が相手のときに抜けられないのは相手の対戦を消さないためであり（#92）、CPU の側には消えて困るものが無い。抜けられないままだと、1 人で始めた対戦を終えるまでロビーに戻れない。
- **どこにいるかを知っているのはサーバである。** 繋いできた人がすでに部屋にいるなら、入り直しとして今の様子を送る。画面を読み込み直すと、繋ぐ側は自分がどの部屋にいたかを忘れている（合言葉を決めたのはサーバなので、URL にも無い）。

## 影響

- サーバは、部屋の一覧を人に見せるようになった。**部屋の名前という、対戦の決まりごとに関わらない値**を持つ。
- CPU が座っている部屋には人が入れない。席は 2 つのままで（ADR-0004）、観戦は相変わらず扱わない。
- CPU が続けて打てる手数に上限を置いた。エンジンの穴で終わらない手順に落ちても、サーバが回り続けないようにするためである。**上限に届いたら盤面は止まる。** 止まって見えるほうが、応答を返さないよりましである。
- 部屋はサーバのメモリにしか無い（ADR-0009）ままである。ロビーもそこから作るので、立て直すと消える。**対戦の記録は残らない。** 決着した部屋も、そこにいる人が出ればロビーから消える。過去の対戦を見返す仕組みは、盤面をどこかに残すことを決めてからになる。
- 部屋の決まりごと（`room.ts`）が、繋がりを受け取るようになった。**それでも接続は持たない。** 渡されるのは「いま繋がっている人」という値だけで、ソケットを持つのは今までどおり `serve.ts` だけである。
- ブラウザに名乗りを覚えさせておくのは、身元をアカウントで持つようになれば要らなくなる。**置き換わる前提の作りである**（#177）。
