# 画面のモックをリポジトリに置き、見た目の決まりの図版にする

各画面の見た目（ADR-0027〜0031）は、HTML のモックで見比べながら決めてきた。そのモックはリポジトリの外に置かれていて、バージョン管理されていなかった。そのため、次のことが起きていた。

- モックと実装のどちらが正なのかが決まっておらず、食い違いが出たときに判断できなかった（#255 はその一例）。
- 新しい画面やダイアログを作るたびに、管理されないモックが増えていた。
- 見た目を大きく変える前の状態が、どこにも残らなかった。

採用したモックをリポジトリに置き、ADR との関係を決める（Issue #259）。

## 決めたこと

### 正は ADR、モックはその図版

**見た目の決まりの正は、ADR の文章である。** モックは、言葉では書ききれない配置・寸法・色の組み合わせを見せる図版として置く。

- ADR とモックが食い違ったら、ADR が正。モックを直す。
- ADR に書かれていない細部は、モックを見本にする。ただし、その細部が後から判断の分かれ目になったら（実装と食い違ったときなど）、決めた結果を ADR に書き足す。
- 実装とモックが食い違ったら、どちらに揃えるかを開発者が決める。実装に揃えるならモックを直し、モックに揃えるなら実装の Issue を起こす。

### 見た目を変えるときは、同じ変更の中でモックも直す

**実装の見た目を変える変更（モックと違う見た目にする変更を含む）では、同じ変更の中で、対応するモックも直す。** 決まりそのものを変えるなら、ADR も同じ変更で直す。別の変更に分けると、その間にモックと実装が食い違い、どちらが正かを決めた意味が無くなる。

新しい画面・ダイアログのモックも、採用が決まったらここに置く。途中の案はリポジトリの外で試し、持ち込まない。

### 置き場と分け方

`docs/mocks/` の下に、画面ごとのディレクトリを置き、`index.html` を 1 つずつ置く。今のモックより細かく、利用者が別の画面として見るものは分ける。

| モック | 画面 | ADR |
| --- | --- | --- |
| `duel/` | 対戦画面 | ADR-0027 |
| `duel-dialogs/` | 対戦の確認ダイアログ・選ぶダイアログ | ADR-0031 |
| `deck-list/` | デッキ一覧 | ADR-0028 |
| `deck-builder/` | デッキ構築 | ADR-0028 |
| `lobby/` | ロビー | ADR-0029 |
| `naming/` | 名前を決める画面 | ADR-0030 |
| `waiting/` | 待機中の画面 | ADR-0030 |

- 複数の画面で使う部品（カードの面の CSS、見本のカード、レベル・スターのアイコン、2 つの画面で共有する CSS と JS）は `docs/mocks/shared/` に 1 つだけ置く。同じものを二重に持つと、片方だけ直す事故が起きる。
- 1 つの画面の中の状態（名前を決める画面の「断られた」、対戦画面の「決着」など）は分けず、モックの中の切り替え（本番には無い部分）で見る。
- **実装に画面の移動があるところは、そのボタンでモックの間を移れるようにする。** 移った先は、その画面の最初の状態で開く（前の画面の選択は引き継がない）。押すものの無い移動（相手が来ると待機中の画面から対戦画面へ移る）は、モックの中の切り替えにリンクを置く。

### 公開リポジトリだけで開ける

モックは、公開されているリポジトリだけを clone した状態で、ブラウザでファイルを直接開いて見られるようにする（`file://`）。

- `private/` を読まない。カードのデータもここに置いた見本だけを使う。
- サーバを立てずに開けるよう、`fetch` や ES モジュールを使わない（`file://` では読み込めないため）。CSS・画像・ふつうの `<script src>` だけで組む。
- アプリのコード・テスト・ビルドの対象にはしない。

### カードは架空の見本にする

モックにも、カードの名前・能力テキスト・作品名は置かない（ADR-0002）。架空のカード（見本）に差し替える。

- **見本のカードの名前は「見本・」で始める。** 実在のカードと取り違えないため。
- 種類・レベル・色・スター・BP・SP・ムーブアイコン・トリガーアイコンは、実際のカードの値の幅を残す（長い名前・長い能力テキストも含める）。レイアウトの確認に使うためである。
- 能力テキストは自前の文にする。キーワード能力の名前（夢・希望など）のような総合ルールの語は、ADR-0007 の扱いどおり使ってよい。キーワード能力の注釈も自前の文にする。
- 属性・作品名・ブロック（出版元）・エキスパンションも架空にする。出版元のロゴは使わない。
- **実際のカードで見るための仕組みは作らない。** 作れば、実際のカードのデータを公開側に置く経路ができてしまう。
- モックを足す・直す変更では、コミットする前に、実際のカードの名前・作品名・属性などでモックの置き場を検索し、当たらないことを確かめる。公開側への push は取り消せない。

## やらないこと

- Storybook のような、モックに代わる仕組みの導入。
- スクリーンショットを置くこと。モックから撮り直せる。
- モックの見た目・作りを、実装に合わせる以外の理由で手直しすること（見た目を変えるなら、それは ADR とモックをあわせて直す変更になる）。

## 影響

- ADR-0027〜0031 から、対応するモックへ辿れるようにする。
- `AGENTS.md` の規約に、見た目を変えるときはモックも直すことを足す。
- モックの開き方・見本のカードの作り方は `docs/mocks/README.md` に書く。
- 置いた時点で、モックと実装の違いを突き合わせ、モックを正とした違いは Issue にした（#255・#260・#261 と、画面だけでは作れない機能の Issue）。実装を正とした違いはモックに反映済み。
