# CPU は、効果を射影の盤面で空回しして損得を判定する

決定日: 2026-11-03。開発者と決定した（#366）。

## 背景

ADR-0060 の段階 2 で、CPU は場面ごとに手へ点数を付けて選ぶ。選択には効果の損得で答え、効果の損得は `Effect` のデータから判定し、カードを名指ししない（ADR-0002）と決定していた。

`Effect` は、命令（`Instruction`）を順に出すジェネレータ関数である。値として中身を参照できるデータではない。効果が選ばせる場面の `purpose` は、どれも `効果の対象` になる（`resolve.ts` の `ChoicePurpose`）。CPU が受け取るのは、候補と、選ばせている発生源のカードだけである。候補を選んだ後に何が起きるかは、効果を回さないと分からない。

エネルギーを何枚まで置くかも決定する必要があった。プレイに要るのはレベルの枚数のエネルギーなので（総合ルール 第1部 第2章 3-1）、自分のデッキのカードの最大レベルまで置けば足りる。しかし、CPU が受け取る射影の盤面（`ActionView`・`ChoiceView`）には、自分のデッキの中身が含まれていなかった。

## 決定事項

### 効果の損得は、空回しで判定する

- **射影の盤面から、効果に見せる問い合わせ（`DuelView`）を作成し、効果を回して、出てきた命令の並びに点数を付ける。** 盤面は変更しない。ユニットを倒す命令は、そのユニットの値打ちを、味方なら減点、敵なら加点する。ダメージは同じユニットへの分を合計し、BP に届けば倒したものとする。
- **選択は、答えの並びを決定して回し直すことで比べる。** ジェネレータは途中から複製できないので、最初から回し直す。支配者が選ぶ所は支配者の得が最も大きい答えを、相手が選ぶ所は最も小さい答えを選ぶ。1 回の見積もりで回す回数には上限を設ける。
- **見せるのは、射影の盤面にあるものだけにする。** 支配者が相手の効果を回す時は、相手の手札を空として見せる。山札を読む命令には、空の山札を返す。見えていないカードには、通信の「見えていない」候補と同じ位置から作成した識別子を付け、候補と突き合わせる。
- **回せない時は、候補が味方か敵かで決定する。** 射影の盤面には無いものを効果が参照した場合などである。候補に味方と敵が混ざっていれば敵を選び、混ざっていなければ差を付けない。
- 空回しは、ストラテジー・起動型能力・トラップの損得、登場した時に誘発する能力の損得、効果の対象への答え、相手のプランの希望で起きることの見積もり（スマッシュの順番）に使う。

### CPU に自分のデッキの中身を渡す

- **`ActionView` と `ChoiceView` に、自分のデッキのカードの並びを追加する。** ADR-0060 の「自分のデッキの中身は知っていてよい」にあたる。渡すのは中身だけで、名前の順に並べ直す。山札の並びも、カードの識別子も含めない。
- エネルギーは、自分のデッキのカードの最大レベルの枚数までは必ず置く。それを超えた後は、エネルギーを 1 枚増やす得が、そのカードを手札に持っておく値打ちを上回る時だけ置く。

## 検討した選択肢

- **候補が味方か敵かだけで決定する。** 効果を回さずに済み、実装が軽い。しかし、味方を強化する効果、味方をリリースする効果などで、選び方を誤る。回せない時の代わりとしてだけ使い、これを主にはしない。
- **カードの実装に、効果の損得のデータ（「敵に向けた効果」など）を追加する。** 回さずに分かる。しかし、カードを実装するたびに書く量が増え、効果の中身とずれても確認する手立てが無い。採用しない。
- **engine の効果を解決する関数（`resolveEffect`）で回す。** 命令の解釈が engine と同じになる。しかし、完全な盤面（`DuelState`）が要る。射影の盤面から仮の盤面を作成するのは段階 3 以降の仕事である（ADR-0060）。採用しない。
- **デッキの中身を渡さず、エネルギーの目標を 7 枚に固定する。** ほとんどのカードはレベル 7 以下である。しかし、最大レベルが低いデッキでは、要らないエネルギーを置いて手札を減らす。採用しない。

## 既存の決定との関係

- **ADR-0060。** CPU は射影の盤面だけを受け取る、という決定はそのまま。空回しに使うのも射影の盤面である。デッキの中身は、ADR-0060 が知っていてよいとしたものを渡す。
- **ADR-0002。** 損得は効果の出す命令から判定し、カードを名指ししない。
- **ADR-0061。** この CPU は、ランダムな CPU に勝ち越したことを確認して採用した。

## 影響

- 新しい命令を engine に追加した時は、CPU の点数の付け方（`scoreInstructions`）にも追加する。追加しなければ、その命令は損得 0 として扱われる。
- 効果が `DuelView` に問い合わせられることを増やした時は、空回しの問い合わせ（`viewFrom`）にも追加する。

## 実装

- 空回し: `packages/cpu` の `probe.ts`。問い合わせの作成が `viewFrom`、損得の見積もりが `probeEffect`、効果の対象の候補ごとの点数が `probeChoice`、命令の並びの点数が `scoreInstructions`
- デッキの中身: `player.ts` の `ownDeckOf`。`ActionView`・`ChoiceView` の `deck`
- 段階 2 の CPU: `scored-cpu.ts` の `scoredCpu`。スマッシュの順番は `smash-order.ts` の `nextSmasher`、バトルの予測は `forecast.ts` の `forecastBattle`
