# 山札を読む口とシャッフルの命令を分け、乱数列の続きは盤面が持つ

「自分の山札を見て、条件に合うカードを 1 枚まで選び、〜する。残りの山札をシャッフルする」というテキストを書けるようにする。山札の中身は、持ち主も見てはならず、順序を変えてもならない（総合ルール 第2部 第21章 2-2）。engine は、山札の中身を持ち主にも見せず、効果が読む口も、意図して置いていない。シャッフルが起きるのは対戦の開始時だけで、盤面は乱数列を持っていない。効果のテキストが「見る」「シャッフルする」と書いている時だけが、例外になる。

この文書は設計として先に書く。実装はこの後に行う。コード上の名前は実装の時に決める。

## 決めたこと

### 山札を読む

- **命令を 2 つに分ける。「自分の山札を読む」と「山札をシャッフルする」である。** テキストの文が、そのまま命令の並びになる。選んだカードをどうするか（スクエアに置く、など）は、既にある命令で書く。
- **読む口は、自分の山札のカードを、中身つきで効果に渡す。並び順は渡さない。** 山札の上からの順ではなく、順序と関係のない並びで返す。効果が山札の順序を読む経路は作らない。効果は、そこから条件に合うものを絞り、既にある「1 枚まで選ぶ」で選ばせる。
- **プランゾーンのカードも、読む対象に含む。** プランゾーンにあるカードは、同時に山札の 1 番上にあるカードである（総合ルール 第2部 第21章 3-1）。
- **選ぶ本人には、山札の全体を見せる。選べるのは、条件に合うカードだけである。** テキストが「山札を見て」と書いているためで、開発者が決めた形である。選択の要求に、見せるカードの一覧（ADR-0041）として山札の全体を載せ、条件に合うカードを候補にする。一覧も、順序と関係のない並びで出す。届くのは、選ぶ本人にだけである（ADR-0008）。
- **選ばないことが、常にできる。** 効果が非公開情報の特定の一部を公開するよう求めている時、支配者は、見つけられなかったことを選べる（総合ルール 第2部 第23章 3）。「1 枚まで選ぶ」の、選ばない選択肢として出す。
- **相手に届くのは、「山札を見た」「シャッフルした」というログ（カードの名前なし）と、公開のゾーンに置かれたカードだけである。**

### シャッフルする

- **シャッフルの命令は、支配者の山札を混ぜる。** プランゾーンにカードがあれば、裏向きにしてから混ぜる。混ぜた後は、プランゾーンは無くなり、山札の 1 番上のカードは裏向きのままである（総合ルール 第2部 第21章 3-5）。
- **乱数列の続きを、盤面が持つ。** 開始時のシャッフルで使った乱数列の続きを、盤面の中に持つ。途中のシャッフルは、そこから乱数を取り、進めた続きを盤面に戻す。対戦は、デッキとシードと「行動と答えの並び」から作り直せなければならず（ADR-0018）、行動は、選択のたびに同じ盤面から最初からやり直す（ADR-0008）。乱数列の続きが盤面の一部であれば、やり直しても、保存から作り直しても、同じ並びになる。engine に渡す入力は増えない。
- **乱数列の続きは、画面へ送る盤面に載せない。** 山札の並びと同じ種類の隠れた情報（これから先の並びを決めるもの）として扱い、視点ごとの射影で必ず落とす。落とし忘れを防ぐテストを置く。

## 検討した選択肢

**命令を 1 つにまとめる（「山札から、条件に合うカードを 1 枚まで探す」。解決の終わりに必ずシャッフルする）** — 「見たら、必ず混ぜる」を engine が保証できる。しかし、「探して、シャッフルしない」「シャッフルだけする」というテキストに使えず、シャッフルの時点が engine に固定される。

**選ぶ本人に、条件に合うカードだけを見せる** — 選択の要求が、いまの形のままで足りる。しかし、テキストの「山札を見て」より、見える範囲が狭くなる。

**サーバが、行動のたびに乱数を作って、入力として渡す** — 盤面は乱数を持たないままになる。しかし、保存する入力の種類が増え、やり直しのたびに同じ乱数を渡し直す管理が、サーバに要る。シードだけからの再現（ADR-0005）ができなくなる。

**乱数を、選択の「答え」の 1 つとして扱う** — 保存の形にそのまま乗る。しかし、「選択は、選ぶプレイヤーが候補の番号で答える」（ADR-0008）の意味が濁り、シードだけからの再現もできなくなる。

## 既存の決定との関係

- **「盤面にシードや乱数列を持たない」という、いまの決まりを変える。** `duel.ts` は、持たない理由を「それを送ると、先の山札が読めてしまうから」と書いている。理由はそのまま生きていて、守り方を、「持たない」から「持つが、送らない」に変える。盤面は、山札の並びという隠れた情報を、既に持っている。
- **ADR-0018・ADR-0005・ADR-0008 は変えない。** 保存する形も、シードからの再現も、やり直しも、そのままである。
- **敵のいるスクエアへ、効果でユニットを置くこと**は、既にある命令でできる。置けばバトルが発生し、相手のトラップの侵入と「勇気」の起動条件も確かめられる（ADR-0039）。

## この決定が決めていないこと

- **山札の順序を見るテキスト**（「山札の上から 3 枚を見る」など）。順序つきで読む口が、別に要る。
- **相手の山札を読む・シャッフルするテキスト。**
- **「読んだのに、シャッフルしない」効果を、engine が止めること。** 止めない。テキストどおりに書く責任は、カードの側にある。
- **この決定を実装まで進めるか。** 1 枚のために、隠れた情報の境目と乱数の持ち方に手を入れる。開発者は、可能な限り実装する、と決めた。実装の途中で決められない点が出た時は、その時に見送りを相談する。

## 影響

- **盤面の欄が 1 つ増える。** 通信の形は変わらない（載せないため）。
- **山札の中身を、選ぶ本人に見せる経路ができる。** 効果のテキストが求めた時だけである。
- **この決定で書けるようになる形（BR1.0 の番号）。** スマッシュのトラップで、山札から条件に合うユニットを探して、スクエアに置き、残りをシャッフルする効果（59）。発動条件ときっかけは ADR-0039、条件の絞り込みは ADR-0035 のメーカーシンボルを使う。

## 実装で決めたこと

単位 8 の実装（#302）で、上の設計に名前と形を与えた。設計の方向は変えていない。

- **命令は `自分の山札を読む` と `山札をシャッフルする`（`effect.ts`）。** どちらも項目を持たない。読むのもシャッフルするのも能力の支配者の山札で、相手の山札を指す形は書けない。
- **読む口は、`DuelView` の問い合わせではなく、命令にした。** 命令であれば、読んだ時に「山札を見た」のログを積める。読むと、山札とプランゾーンのカードが、中身つき（`CardInZone`）で効果に返る。並びはカード名の順、同じ名前の中は識別子の順で、山札の持ち順は返さない。識別子はシャッフル前のデッキの並びから決まる（`setup.ts` の `library`）ので、山札の順序を表さない。読んだカードは、効果が命令の対象にできる。
- **選択の命令（`選ぶ`）に、見せる一覧 `shown` を省略できる項目として足した。** 渡された時は、候補が 1 枚も無くても聞く（選ばないことだけを選べる）。一覧が空（読める山札が無い、読んだカードが山札を離れた）なら、見せるものが無いので、一覧なしの選択として扱う。選択の目的は新しい種類 `山札から選ぶ` になる。**一覧つきの選択を出せるのは `chooseAtMostOneFromLibrary` だけ**で、`chooseAtMostOne` には一覧の引数を足していない。山札以外のカードを一覧に載せる口を作らないためである。
- **山札から選ぶテキストは、`chooseAtMostOneFromLibrary` で書く。** 「読む → 条件で絞る → 見せる一覧つきで 1 枚まで選ぶ」をまとめた記述用の関数で、一覧の付け忘れを防ぐ。命令は 2 つに分けたままである。選んだカードをどうするか、残りをシャッフルするかは、既にある関数（`placeInZone`、`shuffleLibrary`）で書く。
- **シャッフルの乱数は、盤面の `random` から取り、進めた続きを盤面に戻す。** 準備で使った乱数列から切り出した、別の起点の列にする（`random.ts` の `splitRandom`）。乱数列の内部状態は 1 回引くたびに一定の値が足されるだけなので、「1 つ取った後の列」にすると、元の列を 1 つずらしただけの同じ列になる。そのため、状態を混ぜて遠い起点から始める。`prepareDuel` が外へ返す乱数列（CPU・自己対戦が手を選ぶ列）は変えず、同じ値を引かないようにしている。準備を通さない空の盤面（`emptyDuelState`）は、固定のシード 0 から始める。画面へ送る盤面には載せない（`perspective.ts` の `projectBoard` が欄を選んで写すので、足しただけでは載らない。載らないことのテストを置いた）。
- **通信の形は、決めた時点の「変わらない」から、選択の目的（`山札から選ぶ`）とログの種類（`自分の山札を読む`・`山札をシャッフルする`）が 1 つずつ増える形になった。** 乱数列の続きを送らない点は変わらない。
- **乱数列の続きは盤面の一部なので、対戦の作り直し（`room.ts` の `replay`）も、選択のたびのやり直しも、同じ並びになる。** 保存の形（デッキとシードと行動と答えの並び）は変えない。
- **選ぶ本人に届く山札の全体は、見せる一覧（ADR-0041）の `shown` で届く。** 一覧は、選べるカードを先に、見えるだけのカードを後に並べ、それぞれの中はカード名の順、同じ名前の中は識別子の順にする（`protocol.ts` の `orderShown`）。渡された並びに依らず、中身だけで決まるので、持ち順が漏れない。選べるカードが無い一覧（相手の手札を見る確認）も同じ並べ方で、カード名の順になり、同じ名前の中は手札の持ち順ではなく識別子の順になる（単位 7 の「持ち順」からの変更）。「相手の手札を見た」ログの名指しも、同じ順にそろえた。
- **見せる一覧に載ったカードの候補は、その選択の中では `見えている` として送る。** 選ぶ本人は一覧で全体を見ていて、選択の要求はその人にしか届かないので、どの札が条件に合うかが新しく漏れることは無い。`WireCandidate` の `見えていない` の注記は、これに合わせて書き直した（見えていないカードを中身で絞り込んで候補にはしない）。
- **見せる一覧つきの選択は、盤面から押せない。** プランゾーンのカードは盤面にも描かれているので、候補に入ると盤面から押せる扱いになりうる。押すと「これに決める」を経ずに答えが送られ、一覧の中の流れと食い違う。見せる一覧つきの選択では、盤面から押せる候補を空にし、答える口を一覧だけにする（`input-model.ts` の `choicePicking`）。
- **ログは 2 種類。** `自分の山札を読む`（枚数だけ。山札とプランゾーンの合計）と、`山札をシャッフルする`（プランゾーンのカードも混ぜたかどうかだけ）。カードの名前は、読んだ本人のログにも、相手のログにも載せない。プランゾーンのカードは公開されているので、混ぜたことは言うが名前は出さない（既にある `プランを裏返す` と同じ言い方）。
- **山札を見た後は、同じ行動の中で戻れない。** 本来見えないものを見せたことのログ（相手の手札を見た・山札を読んだ）が行動の中にあれば、戻る・取り消すを断る。判定は `perspective.ts` の `isRevealingHidden` の 1 か所で、見せる操作を足す時はここに加える。0 枚なら何も見えていないので戻れる。
- **画面の見出しは「山札（N）から選択する」。** N は山札とプランゾーンの合計。見た目の仕様は `docs/screens/duel/spec.md` に書いた（ADR-0044）。
- **互換は軽く扱う（まだ公開していないため）。** 新しい仕組みは足していない。古い画面には、知らない目的・ログの種類として届き（ADR-0038）、候補は番号で答えられるので、対戦は続けられる。新しい画面に古いサーバがつながる場合は、新しい目的もログも届かないだけである。公開後はこの扱いをやめる。
- **途中のシャッフルの結果は記録しない。実装の時に、結果だけを記録する案も比べた。** 上の「検討した選択肢」は、乱数を入力や答えとして残す形を比べたもので、シャッフルの結果（山札の並び）を残す形は比べていなかった。山札の並びは 1 回で数百バイトなので、大きさでは、ADR-0018 が盤面を残さない理由にした 3 桁の差を払わずに済む。しかし、守れるのは乱数の作り方（`random.ts`）や引く順番を変えた場合だけで、ルールやカードの直しによる再生の失敗は防げない（ADR-0018 が受け入れた「エンジンとカードが変われば同じところへ再生されなくなる」）。開始時のシャッフルの結果も一緒に残さなければ、乱数の作り方を変えた場合すら守れない。そのため、いまは取らない。乱数の作り方を変える必要が出たら、開始時のシャッフルを含めて、記録の形ごと見直す。
