# 作成された誘発型能力は、捨札のカードも対象にできる

決定日: 2026-11-03。開発者と決定した。

## 背景

「このカードがスクエアから捨札に置かれた時、そのターンの終わりに、捨札にあるこのカードを手札に加える」のようなテキストを実装したい。後半は、作成された誘発型能力（総合ルール 第4部 第3章 4）で、その対象は捨札にあるカードである。

いまの engine は、作成された誘発型能力の対象をスクエアにいるユニットとして扱う。誘発する時に対象がスクエアにいなければ誘発せず、効果に渡す対象もスクエアのユニットのビュー（`UnitOnSquare`）に限られている。このため、捨札のカードを対象にできない。

作成された誘発型能力の対象がスクエアの外のカードになるテキストは、後のエキスパンションまで探しても、EB1.0 の 015・069 の 2 枚だけだった。どちらも対象は捨札のカードである。

## 決定事項

### 捨札のカードを対象にする誘発型能力は、別の関数で作成する

- **スクエアのユニットを対象にする、いまの関数（`createTriggeredAbility`）は変更しない。** 捨札のカードを対象にする誘発型能力は、別の関数で作成する。
- **対象がどこにあるかは、作成に使った関数で決まる。** 捨札のカードを対象にした能力は、誘発する時に対象が捨札にある場合だけ誘発し、効果には捨札でのカードのビュー（`CardInZone`）を渡す。カードを実装する側は、効果が受け取る対象の型を、関数の型から知ることができる。
- **作成された後、誘発する前に対象が捨札を離れれば、能力は消滅する**（同 4-1）。いまの消滅の処理（ADR-0036 の「カードが動いた時」と同じ場所）をそのまま使う。捨札へ戻ってきたカードは新しいカードとして扱い、能力は戻らない。

### 対象にできるのは、捨札のカードだけにする

- **新しい関数の対象は、型で捨札のカードに限る。** ほかのゾーンのカードは、それを対象にするテキストが出た時に、ゾーンごとに追加する。
- 作成された誘発型能力の対象は、両方のプレイヤーに送られる（`VisibleCreatedAbility.affecting`）。捨札は公開情報なので、送ってよい。手札のような非公開のゾーンを対象にする時は、送る内容をその時に決定する（ADR-0004）。

## 検討した選択肢

### 捨札のカードを対象にする書き方

- **1 つの関数のまま、渡したビューの種類で対象の場所を決める。** 関数が増えない。しかし、トライアルデッキ G のトラップのように、選んだ時のビュー（エネルギーゾーン）を、スクエアに置いた後で渡すカードがある。このカードは、置いた後のユニットを取得し直して渡すように書き換える必要がある。同じ渡し方をすると能力が黙って誘発しなくなり、気づきにくい。採用しない。
- **1 つの関数のまま、効果がスクエアのユニットか捨札のカードかを受け取って、効果の側で判別する。** 対象を参照するカードが増えるたびに、同じ判別を書くことになる。採用しない。

### 対象にできるゾーン

- **公開されているゾーン（捨札・エネルギーゾーン・プランゾーンなど）。** 送る内容の問題は起きない。しかし、捨札以外を対象にするカードが無く、カードで動きを確認できない。採用しない。
- **スクエアの外のすべてのゾーン（手札・山札を含む）。** 非公開のゾーンの対象を相手に送らないように、通信を見直す必要がある。採用しない。

## 既存の決定との関係

- **ADR-0036。** 作成された継続効果は、スクエアの外のカード（プランゾーンのユニット）も対象にしている。作成された誘発型能力も、同じく対象がスクエアにいるとは限らなくなる。消滅の処理の場所は変更しない。
- **ADR-0004。** 作成された誘発型能力の対象は、両方のプレイヤーに送る。対象を公開のゾーン（スクエアと捨札）に限ることで、送ってよい情報のままにする。
- **ADR-0018・ADR-0053。** いまの関数の動きは変更しない。新しい関数を使うのは、今回実装するカードだけである。このため、記録済みの対戦を打ち直した結果は変化しない。

## 影響

- engine に、作成された誘発型能力を作成する関数が 1 つ追加され、誘発の処理が捨札の対象を扱うようになる。通信のデータと画面は変更しない。
- 015 は、この決定と ADR-0058 で実装できるようになる。069 も同じ 2 つを使うが、スクエアの外にあるカード自身の誘発型能力を、捨札に置かれた時に誘発させる仕組みが要る。これは別に決定する。
