# 起きたできごとは盤面に積んで、盤面と一緒に届ける

エンジンが実行した命令や、ルールが起こしたことを、**盤面（`DuelState.log`）に積む**。射影
（ADR-0004）がそれを視点ごとに落とし、通信では盤面の一部として毎回まるごと送る。

盤面は「その時点の姿」しか持たない。そこへ至る道筋——相手が何を行ったか、なぜダメージが増えた
のか、効果が何を選んだか——は、2 つの盤面を見比べても分からない。操作ログ（#95）も、効果の
カットイン（#104）も、スマッシュ判定の説明（#102）も、そこを要る。

**できごとを外へ知らせる口はエンジンに生やせない。** エンジンは I/O を持たない（ADR-0001）。
受け取り口（コールバック）を渡す形は、純粋な関数という性質をその引数ぶんだけ削る。盤面に積んで
おけば、盤面を返すだけで道筋も返ることになり、エンジンは純粋なままでいられる。

**やり直しと噛み合う。** 行動は答えの並びを足しながら適用し直す（ADR-0008）。積んだ先が盤面な
ので、やり直しの起点である行動前の盤面には何も積まれていない。**同じ盤面と同じ答えからは同じ
ログが積まれる**ので、選択のたびにやり直しても二重にならない。

## 影響

- 通信の形式も、サーバの覚えることも増えない。ログは `盤面` メッセージに乗って届き、入り直した
  人にはいまの盤面ごと送り直される（ADR-0009）ので、追いつかせる仕組みが要らない。
- **できごとはカードを識別子でしか指さない。** カードそのものを持つと、効果が関数なので通信に
  載らなくなる。名前を出したい側は、同じ盤面から引き直す。
- **見え方の決まりは射影ひとつのまま。** ログから落とすカードは、射影した盤面から表側が見えて
  いるかどうかで決まる（`perspective.ts` の `visibleIds`）。`seesFace` を読み直す経路を作らない。
  作れば、片方だけ直した時に漏れる。
- 落とすのは「いま」の見え方で決まる。そのできごとの時に見えていても、いま見えないカードは落ちる。
  **少なく見せる側に倒している。**
- ログはデュエルの間ずっと積まれ、盤面を送るたびに全部を送る。差分で送る仕組みは持たない。増え
  すぎて困るようになったら、その時に切り方を決める。
- **ルールの判断には使わない。** 読むのは射影だけで、ログを見て盤面が変わることは無い。積むのを
  やめてもデュエルの進み方は変わらない。
