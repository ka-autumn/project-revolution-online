# お知らせの中身の窓の「一覧へ」は、パネルから開いた時にも出す

ロビーのお知らせの窓の動きは ADR-0029 で決めた。中身の窓は、全件の窓から開いたときだけ、左上に「一覧へ」を置き、パネルから開いたときは見出し「お知らせ」を置く、という決めだった。この文書を書いた時点（2026-10-18）では、お知らせを取りに行って出す部分（ADR-0045、#320）の実装がほぼ済み、検証環境で実際の動きを触れるようになっていた。そこで、パネルから開いた中身の窓に「一覧へ」が出ないことが、使いにくいと分かった。

- パネルに並ぶのは新しい順の 5 件までで、それより古い件は、全件の窓を開かないと辿れない。パネルから開いた中身の窓から、全件を見渡す口が無かった。
- 中身の窓の左上は、開き方で「一覧へ」の戻る口と、見出しに分かれ、同じ窓なのに役目が変わっていた。

## 決めたこと

**中身の窓の左上には、全件の窓から開いたときも、パネルから開いたときも、「一覧へ」を置く。**

- 全件の窓から開いたなら、これまでどおり、開いた時の絞り込みの全件の窓へ戻り、開いていた件へ手を戻して、一覧のスクロールの位置も戻す。
- パネルから開いたなら、「すべて」の全件の窓を開き、いま読んでいる件へ手を置く（一覧の中でその件が見える位置へ送る）。
- パネルから開いて「一覧へ」で全件の窓を開いた後に閉じたら、手は開いた元のパネルの件ではなく、全件の窓を開く口の「すべて見る」へ戻る。
- パネルから開いた中身の窓に、見出し「お知らせ」は置かない。

今の見た目の仕様は `docs/screens/lobby/spec.md` に、見本はモックにある（ADR-0044）。

## 検討した選択肢

- **全件の窓から開いたときだけ出す（ADR-0029 の決定）。** 戻る先が開いている時だけ戻る口を出す、という筋は通っている。しかし、パネルから開いたときは、全件を見渡す口が無く、5 件より古い件を読むには、いったん閉じて「すべて見る」を押し直すことになる。左上の役目が開き方で変わる点も残る。
- **常に出す（この決定）。** 戻る先が開いていないときの「一覧へ」は、戻るではなく開くになるが、押した結果は同じ全件の窓で、迷わない。
- **パネルから開いたときは、「一覧へ」の代わりに「すべて見る」を置く。** 出す口は増えるが、同じ動きに 2 つの名前ができる。

## この決定が決めていないこと

- パネルから開いて「一覧へ」で全件の窓を開いた後、その窓の「絞り込み」を、最後に見ていた種別から始めるか。ここでは「すべて」から始める。

## 影響

- ADR-0029 の「全件の窓から開いたときだけ『一覧へ』を置く」は、この文書で変わる。ADR-0029 の冒頭に、そのことを 1 行で書く。
- 窓から手を戻す先が、「パネルの件」「すべて見る」「全件の窓の件」の 3 つになる。窓の外へ戻る先は、窓を開いた口で決まる。
