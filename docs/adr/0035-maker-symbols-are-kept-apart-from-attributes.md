# メーカーシンボルは、属性と別の並びでカードが持つ

総合ルールは、属性にメーカーシンボル・メディアシンボル・詳細属性の 3 種類を含めている（第2部 第13章 1）。ところが engine のカードは、詳細属性だけを `attributes` に持ち、メーカーシンボルを持っていなかった。メーカーシンボルを参照するテキスト（「他の、あるメーカーシンボルを持つ味方のＢＰを＋Ｎ」の形）を書けるようにするため、カードがメーカーシンボルを持つ形を決める。

## 決めたこと

- **カードは、属性とは別の項目 `makerSymbols` として、メーカーシンボルの並びを持つ。** 種別によらず全カードが持てる。`defineUnit` などの記述では省略でき、省略すれば空になる。
- **型は属性と同じく閉じていない文字列（`MakerSymbol`）にする。** 総合ルールがメーカーシンボルの一覧を定義していないためで、綴りの揺れを engine 側では検出できない。
- **効果と常在型能力が見るのは、その並びにあるシンボルを含むかどうかだけである。** `hasMakerSymbol(card, symbol)` か、`card.makerSymbols.includes(...)` で見る。「他の、あるメーカーシンボルを持つ味方のＢＰを＋Ｎ」は、属性で絞る常在型能力と同じ書き味で書ける。
- **あるシンボルを別のシンボルとして扱う決まりは片方向であり、並びに両方を書くのは、別のシンボルとして扱われるシンボルを持つカードだけである。** 総合ルール 第2部 第13章 1-1-1 は、あるシンボルを別のシンボル「として扱う」と決めている。実際の運用も片方向で、扱われる側のシンボルを持つカードだけが、もう一方としても数えられる（逆は成り立たない）。そうしたカードは、カードの側が並びに両方を書く。扱われる先のシンボルしか持たないカードは、先のシンボルだけを書く。どのシンボルがどのシンボルとして扱われるかは engine に持たせない。
- **メーカーシンボルを加える・失わせる効果を持つカードは無い。** 開発者が確認した事実で、総合ルールが属性一般の変更・追加を認めていること（第2部 第13章 3・4）と食い違うものではない。したがって、書かれた並びがそのまま継続効果を適用した後の姿でもあり、`continuous.ts` を通す必要が無い。そうした効果を持つカードが出てきた時に、属性と同じ形（`view.ts` の写しを通す）にする。
- **どのカードがどのシンボルを持つかは、カードのデータの側の話であり、ここには書かない。** engine は実在のメーカー名を 1 つも知らない（ADR-0001・ADR-0002）。
- **通信には載せない。** 通信に載るカードの表記は項目を列挙して写している（`wire.ts` の `written`）ので、勝手には載らない。画面に出す必要が出てきた時に、足すかどうかを決める。

## 検討した選択肢

**属性の並びに混ぜる** — 項目が増えず、いちばん手軽である。しかし属性を数える・属性を加える効果が、メーカーシンボルまで巻き込む。「属性を 1 つ加える」効果のあとに、メーカーシンボルと詳細属性のどちらを数えるのかが並びからは読めなくなる。総合ルールは 3 種類を属性として一括りにしている（第2部 第13章 1）が、それは総合ルールの分類であり、カードが持つ並びを 1 つにしなければならない理由は条文からは読み取れない。

**カードの外に、番号とメーカーの表を持つ** — カードのデータ（カード番号）からメーカーを引く。しかし、別名のカードやコピーのカードで判定が揺れる。そもそもカードの外に表を持つと、engine からはその表を読めない（カードの実装は engine の内部状態に触れない、ADR-0002）。カードに書かれていることは、カードが持つ。

## この決定が決めていないこと

- **画面に出すときは、「印刷された表記」と「数えられる表記」の区別を改めて決める。** 別のシンボルとして扱われるシンボルを持つカードは、並びに 1 つの印刷されたシンボルに対して複数の値が書かれる（上の決めたこと）。そのまま出すと、カードに印刷されたものと食い違う。画面に出すことになった時に、印刷された表記を別に持つか、並びの先頭だけを出すかを決める。
- **メディアシンボルは持たない。** 参照するテキストがまだ無い。出てきた時に、`makerSymbols` と同じように別の並びとして足す。

## 影響

- **カードのデータを作る側は、メーカーシンボルを `makerSymbols` に書く。** 詳細属性の並びに書かない。
- **既存のカードは何も変えなくてよい。** 省略すれば空になる。
- **メーカーシンボルを参照するテキストが、属性を参照するテキストと同じ形で書ける。** ただし、どちらの並びを見るかを取り違えても型では見つからない（どちらも文字列の並びである）。
