# 手を送ったら、返事か切断が来るまで次の手を送らない

決定日: 2026-11-01。Issue #253。開発者と決定した。

## 背景

対戦画面は、手を送っても、返事が届いて描き直されるまでは送る前のままである。その間もボタンは押せるので、素早く 2 回押すと同じ手が 2 通送られる。サーバの関門（`room.ts` の `act`）は「今の盤面で行える手か」しか見ないので、2 通目も合法なら通る。優先権の放棄では、1 通目でエネルギーフェイズが終わって自分の優先権のままメインフェイズに入り、2 通目がメインフェイズの放棄として通って、メインフェイズを飛ばす。

ダイアログ（確認・選ぶ）と効果で選ぶ一覧は、#249 と ADR-0031 で、送った時点でボタンを押せなくし「通信中…」を出すようにしていた。ただし、送ったかどうかを、1 回の描画で作った要素の中にしか持っていなかった。対戦画面は描き直すたびにダイアログを作り直すので、返事より先に別の理由（`相手の繋がり` の受信、演出の待ち行列のタイマー）で描き直されると、新しいダイアログは送る前の状態で作られ、また押せるようになる。パネルの優先権の放棄のボタン、光ったスクエア・トラップゾーン、ボタンモードの手のボタン、選択中のボタンには、止める仕組みがそもそも無かった。

## 決めたこと

- **画面の側で止める。** 対戦の手（`行動する`・`選ぶ`・`ひとつ戻る`・`取り消す`）を送ったら、返事が来るまで、次の手の送信を空振りにする。通信の形とサーバは変えない。
- **返事は `盤面`・`選んでほしい`・`行えなかった` である。** どれかが届いたら、また押せる。`席についた` も解く（対戦が始まり直したところで、前の盤面に送った手の返事は待つものではなくなる）。`相手の繋がり` では解かない。
- **切れたら解く。** 切れる前に送った手の返事はもう来ず、切れている間は手を出さない。
- **繋ぎ直して入り直す部屋があるときは、繋がった時点では解かず、入り直しの返事が届くまで待つ。** 繋がると画面は `部屋に入る` を送り、サーバはいまの盤面を送り直す（ADR-0009、ADR-0016）。その返事が届くまで、画面には切れる前の盤面と行える手が残っており、そこで押した手は入り直しのすぐ後にサーバに届いて、いまの盤面で合法なら通ってしまう。入り直しの返事は `席についた`（入り直せた）・`行えなかった`（断られた）・`相手を待っている`（部屋がもう無く、新しく開いた）のどれかで、繋いだ時点でサーバが先に送る `ロビー`・`名前を決めてほしい` も、入り直す先の盤面がもう無いことを言っているので、どれでも解く。手を送っていなくても、繋ぎ直した直後は同じく待つ。入り直す部屋が無ければ、繋がった時点で解く。
- **時間では解かない。** 返事が来なければ、切断（繋ぎ直し）まで待ち続ける。解いた直後に押すと、直したい二重送信と同じことが起きるためである。
- **送ったかどうかは、描き直しをまたぐ画面全体の状態として持つ。** ダイアログ・一覧の止め方もここへ寄せ、描き直しで作り直しても、送ったあとの止めた形で作る。
- 人の操作なしに送る手（放棄しか行えない場面の自動の放棄、N 枚をまとめて選ぶ続きの答え）も、同じく返事を待つ。

画面にどう見せるかは `docs/screens/duel/spec.md`・`docs/screens/duel-dialogs/spec.md` に書く（ADR-0044）。

## 検討した選択肢

### 止める場所

- **A: 画面の側で止める。** 採る。通信の形・サーバに手を入れずに済む。止める判断は「返事が来たか」だけで、ルールの判断を画面に持ち込まない（ADR-0010）。返事が来ない場合に操作が止まるが、下の「待ち方」のとおり、来ないのは切断の時に限られる。
- **B: 手に、いまの盤面の通し番号を付けて送り、古い番号の手はサーバが断る。** 確実で、画面の作りに左右されない。しかし通信の形とサーバの両方を変える。画面の側で止めても 2 通目は送られなくなり、B を足して得るのは、画面の止め方に穴があった時の備えである。まず A で足りると判断した。採らない。要るとなった時に、この決定の上に足せる。

### 返事が来ない場合

- **切断まで待ち続ける。** 採る。
- **一定の時間で解く。** 操作が止まり続けることは無くなるが、返事が遅れているだけの時に解くと、解いた直後の 1 押しが二重送信になる。採らない。

## 前提

この決定は「サーバは手に必ず返事を返すので、返事が来ないのは通信が切れた時に限られる」という前提に立つ。決めた時点のコードで確かめたことを書く。

- 手を受けるのは `room.ts` の `receive` で、`act`・`answer`・`rewind` のどの道も、送り主に `行えなかった` を返すか（`refuse`）、`盤面`（`boards`、席の両方へ）か、`盤面` と `選んでほしい`（`advance`）を返す。部屋の外・席の外・優先権が無い・選ぶところでない、のどれも断りとして返る。CPU の手は同じ受け取りの中で打たれ、自分の手の盤面の後に続けて届く（`withCpu`）。
- 名前が決まっていない時は `名前を決めてほしい` を返すが、対戦の席に着いている時は名前が決まっている。
- 繋ぎ直したときの `部屋に入る` には、`room.ts` の `enter` が `席についた`（`rejoin`）・`行えなかった`・`相手を待っている` のどれかを返す。
- **通信の形では、どの送信への返事かを見分けられない。** `行えなかった` は、対戦の手ではない送信（「やめてロビーに戻る」など）を断ったときにも返る。手の前に送ったそれが断られた `行えなかった` でも、待ちは解ける。例えば、相手が切れた対戦で「やめてロビーに戻る」を押し、直後に相手が戻ってサーバが断り、その返事が届く前に放棄を押すと、先の `行えなかった` で待ちが解け、もう一度押せば 2 通目が送られる。窓はとても狭いので、直さずに受け入れる。
- エンジンが例外を投げた場合（範囲外の番号など、正しい画面からは送られないもの）は、受け口（`serve.ts` の `message`）に受け止めが無く、プロセスごと落ちる。画面から見れば切断になる。
- **前提が成り立たない場面が 1 つある。** 同じ参加者が 2 つ目の接続を張ると、サーバは新しい接続だけを覚え（`sockets.set`）、古い接続を閉じない。古い接続から送った手は処理されるが、返事は新しい接続へ届き、古い接続には何も届かず、切れもしない。古い画面は返事を待ったまま止まる。古い画面はそれまでも盤面が届かなくなっていた（以後のものはすべて新しい接続へ届く）ので、この決定で新しく壊れるものではない。

## 既存の決定との関係

- **ADR-0010。** 画面が止める判断は「返事が来たか」だけで、何を行えるかは今までどおりサーバが決める。
- **ADR-0016。** 繋ぎ直しで送れなかった手を貯めて流し直さないことは変えない。切れる前の手を繋ぎ直した先で押させないことを、繋ぎ直した直後にも効かせる（入り直しの返事が届くまで待つ）。押し直すのは、繋ぎ直した先の盤面からである。
- **ADR-0031。** ダイアログ・一覧の「送ったら押せなくし、通信中…を出す」止め方は変えず、送ったかどうかを持つ場所だけを画面全体へ移す。

## 影響

- 素早く 2 回押しても、送られる手は 1 通になる。パネル・盤面・ダイアログ・一覧・ボタンモードのどれから送っても同じである。
- 返事が届くまでの間（ふつうは一瞬）、パネルのボタンが薄くなり「通信中…」が出て、盤面の行き先は光らない。
- 同じ参加者が 2 つの画面で開いた時、古い画面で手を送ると、その画面は繋ぎ直すまで止まる（上の「前提」）。
- 「通信中…」のまま止まったときの戻り方は 3 つある。返事を待つ。繋ぎ直しを待つ（切れれば解け、繋ぎ直せば入り直しの返事で解ける）。2 つの画面で開いた古いほうは、再読み込みする。

## 実装

- 待ちの判断は `packages/client/src/reply-wait.ts`（`trySend`・`afterMessage`・`isReply`・`afterLinkChange`）。状態は `index.ts` の `mount` の `replyWait` で持つ。人が押して送る手は `DuelInteraction.move` を通す。人の操作なしに送る手（自動の放棄、N 枚を選ぶ続きの答え）は、`onMessage` で描く前に待ちに入れてから、`connection.send` で直に送る。繋がりの様子が変わったときは、`onLinkChanged` で、入り直す部屋（`connection.ts` の `rejoining` と同じもの）があるかを `afterLinkChange` に渡す。
- パネルを止めた形にするのは `render.ts` の `lockForReply`。ボタンは `disabled` ではなく `aria-disabled` にして、キーボードの手を残す。
- ダイアログ・一覧は、`askElement` の `sentBefore`、`choosePickerElement`・`shownPickerElement`・`chooseZoneListElement` の `sent`、`seriesPickerElement` の `sendingFromStart`、`areaSheetElement` の `sent` に、返事を待っているかを渡す。
