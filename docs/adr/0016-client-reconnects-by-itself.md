# クライアントが自分で繋ぎ直す

WebSocket 1 本で繋ぐ形（ADR-0009）はそのままにして、**切れたときに繋ぎ直す責任をクライアントに置く。** 通信の手立てを別のものに替えることはしない。

不安定な回線で対戦すると、ソケットが繰り返し切れる。切れたあと画面は「繋がっていません」と出したまま止まり、続けるには人がページを再読み込みするしかなかった。**足りなかったのは通信の手立てではなく、切れたあとに何もしていなかったことである。**

## なぜ WebSocket のままでよいか

繋ぎ直したあとに状態を合わせ直す仕掛けが、すでに揃っている。

- 盤面は差分ではなく毎回まるごと送っている（ADR-0011、`wire.ts`）。**追いつかせるものが無い**ので、入り直した人には今の盤面を 1 つ送れば済む。
- 部屋は接続に紐づかず、合言葉に紐づく（ADR-0009）。切れても部屋は残り、同じ合言葉で入り直せば同じ席に戻る（`server` の `room.ts` の `rejoin`）。
- 選択の途中で切れても、貯めた答えの並びで適用をやり直せば同じ「選んでほしい」が再生される（ADR-0008）。**送ったメッセージを覚えておく必要が無い。**
- 何を行えるかを決めるのはサーバである（ADR-0004、ADR-0010）。古い盤面を持ったまま打とうとしても、サーバが断る。

長い投票（long polling）や、切れたところから続きを配り直す仕掛け（SSE の `Last-Event-ID`、メッセージの再送バッファ）に替える理由が無い。**どれも「切れた間に何があったか」を埋めるためのもの**で、まるごと送り直す形には要らない。ターン制で、待っているのはほとんどの時間が人の考える時間であり、押し出しの遅延を詰める必要も無い。

## 決めたこと

- **切れたら間を空けて自分で繋ぎ直す**（`client` の `connection.ts`）。待ちは 250ms から倍々に伸ばし、4 秒で頭打ちにする。10 回で諦める。合わせておよそ 30 秒。
- **繋ぎ直したら `部屋に入る` を送り直すだけ**にする。送れなかった手は貯めない。繋ぎ直した先の盤面では、押そうとした手がもう行えないかもしれない。
- **繋がっていない間は手を出さない。** 押せなくするだけでは足りない。出ている手は切れる前の盤面のもので、そのまま見せていると打てるように見える。
- **繋がりの様子を 1 行で出す。** 繋ぎ直している最中は何回目かまで、諦めたら再読み込みを促す文言を出す。**黙って止まっているように見える時間を作らない。**
- **サーバは 30 秒ごとに生きているかを確かめる**（`server` の `serve.ts`）。回線が黙って死ぬと、切れたことが降りてこないまま残る接続ができる。返事の無い接続は落とす。間に中継を置く構成（ADR-0015）では、黙っている接続を中継が切るのを防ぐ役目も兼ねる。

## 影響

- 繋ぎ直しは**繋ぐのと同じ**であって、専用の入り口を作らない。サーバ側に足したものは、生きているかの確認だけである。
- 諦めたあとは自分では戻らない。人が再読み込みする。**無限に試し続けない**のは、繋がらない理由が回線でない場合（サーバが落ちている、URL が違う）に、待てば戻るのかどうかが画面から読み取れなくなるためである。
- 回線が黙って死んだ場合、クライアントの側はしばらく繋がったままに見える。ブラウザの `WebSocket` に ping は無く、こちらから確かめるにはメッセージの種類を足すことになる。**今回は足していない。** 実際に起きていたのは切れたことが分かる切れ方であり、確かめの仕組みはサーバ側だけで足りている。
- 部屋はサーバのメモリにしか無い（ADR-0009）ままである。サーバを立て直すと対戦は消え、繋ぎ直した 2 人は新しい対戦を始めることになる。**繋ぎ直しが直すのは接続であって、失われた対戦ではない。**
