# 画面は、差分を当てるライブラリで描き直す

決定日: 2026-11-27。Issue #242（#165・#134 の土台として）。開発者と決定した。

この文書は設計として先に書いた。実装した後で、実装で決定した名前を末尾の「実装」の節に書き足す。

## 背景

画面（`packages/client`）は、状態が変化するたびに、根の要素の中身を丸ごと作成し直している（`index.ts` の `draw` が `root.replaceChildren()` を呼ぶ）。この描き方は、どの ADR でも決定していなかった。最初の画面を作成した時の書き方が、そのまま続いていた。

作成し直す前の DOM が持っていたものは、作成し直すと失われる。それを後から戻す手当てが、次のように積み重なっていた。

- スクロール位置とフォーカスを戻す属性（`KEEP_SCROLL`・`KEEP_FOCUS`・`KEEP_FOCUS_INSTEAD`）。属性を付け忘れた要素は、描き直すたびに元へ戻る（#207 で、ロビーのサムネイルの列が左端へ戻った）
- 押している最中は描き直しを待つ仕組み（`pointerHeld`・`redrawOnRelease`）
- 日本語入力の変換中は描き直しを待つ仕組み（`redraw` の `composing`）
- カードの絵・ロゴのちらつきと遅れへの対処（#403・#410 の画像の置き場、#411 の縮小の負荷）
- 描いた後に寸法を測る処理と、描画の例外で画面が白くなるのを防ぐ処理

デッキ構築では、カードの絵・ロゴのちらつきや枚数の表示の遅れ（#402・#409・#411）として現れ、そのたびに描き直し方には踏み込まずに個別に直してきた。

また、#165（演出と盤面の足並みをそろえる）と #134（フェイズの中で連なる変化を段階的に見せる）は、カードが回転し、移動し、光ることを求めている。描くたびに要素を作成し直す描き方では、要素が前の位置を持たないので、これは成立しない。

## 決定事項

### 差分を当てるライブラリを入れる

- 画面は、描きたい状態を毎回宣言し、前の DOM との差分だけを当てるライブラリで描く（Preact などの、仮想 DOM で差分を当てる軽いもの）。要素は描き直しをまたいで残るので、スクロール位置・フォーカス・日本語入力の変換・読み込み済みの画像は、手当てなしで保たれる。
- どのライブラリにするかは、実装に入る前に、候補を比べて開発者と決定する（クライアントに依存を追加するため）。
- 状態から画面を作成する考え方（今の `render.ts` の、状態を受け取って要素を返す関数）は残す。今の要素を作成する関数を、ライブラリの部品へ書き直していく。

### 今の手当ての扱い

| 手当て | 扱い |
| --- | --- |
| スクロール位置・フォーカスを戻す属性（`KEEP_SCROLL`・`KEEP_FOCUS`・`KEEP_FOCUS_INSTEAD`） | 外す。要素が残るので要らない |
| 押している最中は描き直しを待つ仕組み（`pointerHeld`・`redrawOnRelease`） | 外す。押している要素が作成し直されないので要らない |
| 日本語入力の変換中は描き直しを待つ仕組み（`composing`） | 差分を当てる形へ移った画面から、変換が切れないことを確認したうえで外す |
| 意図してフォーカスを移す処理（ダイアログを開いた時など） | 残す |
| カードの絵・ロゴの置き場（#403・#410） | 残す。同じ URL の読み込みを使い回す役目は、描き方と関係なく要る |
| 縮小の負荷への対処（#411） | 要素が作成し直されなくなるので、縮小が起きる理由ごと無くなる |
| 描いた後に寸法を測る処理 | 残す。差分を当てた後に呼ぶ |
| 画面が白くなるのを防ぐ処理 | ライブラリの、例外を受け止める部品で書き直す |

### 移る順番

一度に全部を書き直すと、途中で止まった時に、どちらの描き方でもない画面が残る。どの段階で止まっても画面が筋の通った状態になるよう、次の順に移る。各段階は別の PR にする。

1. 根をライブラリで包む。すべての画面を、毎回作成し直す 1 つのかたまりとして、ライブラリの中に置く。見え方は変化しない
2. カードの面（デッキ構築・対戦画面・ロビーで共通の部品）
3. デッキ構築の画面
4. ロビー
5. 対戦画面
6. 演出と盤面の足並み（#165。ADR-0080）
7. フェイズの中で連なる変化（#134。ADR-0081）

カードの追跡の識別子（ADR-0079）の通信の変更は、この順番と並行して、別の PR で進める。6 つ目の段階より前に済ませる。

各画面の PR では、その画面で要らなくなった手当ても外す。外し残しを後回しにしないためである。

### 確認の方法

画面には、DOM を対象にしたテストが無い（vitest に DOM の環境が無く、本物のブラウザで動かすテストも無い）。次の 2 つを用意する。

- vitest に DOM の環境（happy-dom か jsdom）を追加し、部品ごとの細かいテストを書く
- 本物のブラウザで動かすテスト（Playwright か vitest のブラウザのモード）で、少数の筋書きを確認する。他の人の操作で描き直されても、スクロール位置が戻らないこと、押している最中の要素が失われないこと、日本語入力の変換が切れないこと

本物のブラウザのテストを CI で走らせるかは、実装の段階で決定する。

## 検討した選択肢

- **今のまま丸ごと作成し直し、手当てを続ける。** 依存を追加しない。しかし、手当てを付け忘れた要素が描き直すたびに元へ戻る不具合は、要素を追加するたびに起こりうる。また、カードを回転・移動させる演出（#165・#134）が成立しない。採用しない。
- **変化した領域だけを自前で描き直す（領域ごとに作成し直す）。** 依存を追加しない。しかし、どの領域が変化したかを判定する仕組みを自前で持つことになり、領域の中では同じ問題が残る。演出のためにカードの要素を残すには、結局カード 1 枚ごとの差分が要る。採用しない。
- **差分を当てるライブラリを入れる。** 依存が 1 つ増える。要素が残ることで、手当ての多くが要らなくなり、演出の土台にもなる。採用した。

## 既存の決定との関係

- ADR-0010（クライアントはルールエンジンを動かさない）は変更しない。追加するライブラリは描画だけのもので、ルールを持たない。
- エンジンには依存を追加しない（ADR-0001）。追加するのはクライアントだけである。

## この決定が決定していないこと

- 追加するライブラリの名前と版。実装に入る前に開発者と決定する
- 本物のブラウザのテストを CI で走らせるか
- 部品の分け方と名前

## 影響

- 画面の全体を書き直すことになる。7 つの段階に分けたので、どこで止まっても画面は動く。
- 通信・サーバ・エンジンは変更しない。
- 画面の見た目は変化しない。仕様書とモックは直さない。

## 実装

移る段階の PR ごとに、その PR で決定したことを書き足す。

### テストの土台の PR

- テスト用の依存は、happy-dom 21.0.4 と @playwright/test 1.65.1（版を固定する）。本物のブラウザは Chromium だけを使う。
- DOM が要るテストは、ファイルの先頭の `// @vitest-environment happy-dom` で環境を指定する。ほかのテストの環境は変更しない。
- 本物のブラウザのテストは `pnpm verify` に含めず、`pnpm test:browser` で走らせる。CI で走らせるかは、まだ決定していない。
- ログインは、対戦サーバを立てる前に、使い捨ての置き場へセッションを書き込んでおく形にする（`packages/client/browser-tests/seed.ts`）。サーバには架空の Google の設定を渡し、本物のログインの経路を通す。サーバが動いている間、テストは置き場に書き込まない（置き場は 1 つのプロセスだけが持つ、ADR-0014）。
- 筋書きは `packages/client/browser-tests/redraw.spec.ts`、デッキ構築の計測は同じディレクトリの `deck-measure.spec.ts` に置く。計測は非公開側のカードがある時だけ走らせる。

### 根を包む PR

- ライブラリは Preact 11.2.0（版を固定する）。`packages/client` の `dependencies` に置く。テスト用は @testing-library/preact 3.2.6。
- 部品は JSX（`.tsx`）で実装する。変換は Vite に任せ、`packages/client/tsconfig.json` の `jsx: "react-jsx"` と `jsxImportSource: "preact"` で指定する。Preact の Vite プラグインは入れない。部品のテストは `*.test.tsx` に置く。
- 根の部品は `packages/client/src/screen-root.tsx` の `ScreenRoot` で、`showScreen` が `#board` に描画する。表示するもの（`Screen`）は、組み立てるかたまり（`かたまり`）か、1 行の文（`一行`）である。
- `draw` が作成する DOM は、`ScreenRoot` の下の 1 つの要素（`.screen-chunk`）の中に置く。Preact はこの要素の中身に差分を当てず、`draw` が今までどおり中身を捨てて作成し直す。この要素には `display: contents` を当て、`#board` の縦の箱の子は今までと同じにする。
- `draw` は、かたまりの部品の layout effect の中で呼ぶ。投げたものを、例外を受け止める部品が受け止めるためである。layout effect は `render` が返る前に走るので、`draw` の後に呼ぶ処理の順番は変化しない。
- 画面が白くなるのを防ぐ処理は 2 つに分けた。`draw` で投げたものは `ScreenRoot` が受け止める。`redraw` のうち Preact の外で呼ぶ処理（状態を整える処理、描いた後の寸法の計測・スクロール）は `try` で包んだままにし、`catch` からも `showScreen` で断りの 1 行を表示する。`draw` で投げた時は、後の処理を呼ばない。
- `draw` が投げた時、`console.error` への出力は同期で行われるが、断りの 1 行の表示はマイクロタスク 1 つ分遅れる。Preact 11 が状態の更新を `queueMicrotask` で積むためである。
- 断りの表示の後に画面を渡されたら、組み立て直す。前の描き方でも、次の描き直しで組み立て直していた。
- 寸法を測る処理は、layout effect へ移さず、`redraw` が `showScreen` の後に呼ぶ。Preact の `render` が同期で終わるので順番が保てて、呼ぶ処理と渡すものを今のまま残せるためである。
- 「ログインへ移動しています」も `showScreen` で表示する。`#board` は Preact の外から書き換えない。
- `mount` の後片付けでは `render(null, root)` を呼び（`screen-root.tsx` の `removeScreen`）、`#board` から Preact の木を外す。
- `/share/<鍵>` の公開ページ（`public-share.ts`）も、読み込み中・見つからない・本体の 3 つの表示を、同じ `showScreen` でかたまりとして表示する。要素はかたまりの組み立ての中で作成し、投げたものを `ScreenRoot` が受け止める。
- スクロール位置とフォーカスを戻す属性・押下を待つ仕組み・変換中を待つ仕組みは残す。外すのは各画面の PR である。
