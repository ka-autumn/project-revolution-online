# 行動はやり直して適用し、選択は候補の番号で答える

サーバとクライアントがやりとりするのは、盤面（サーバ → クライアント、視点ごとに射影したもの、ADR-0004）と、行動（クライアント → サーバ）と、その行動の途中で必要になる選択の 3 つとする。

**選択は候補の番号で答える。** 効果の解決やコストの支払いの途中では、候補の中から 1 つ選ぶことが要る（`resolve.ts` の `Chooser`）。サーバが候補の並びを作って選ぶプレイヤーにだけ送り、クライアントはその何番目かを返す。候補を名指ししないのは、**見えないカードを選ぶ場面があるため**である。プランのコストとして自分の裏向きのスマッシュをフリーズできる（総合ルール 第2部 第21章 7-5）が、スマッシュはどちらのプレイヤーにも見えない（同 7-3）ので、番号以外に指す手立てが無い。

**行動はやり直して適用する。** 選択は 1 つの行動の中で何度も起こり、次に何を選べるかは前の選択の結果で変わる。エンジンは同期的な純粋関数であり、途中で止めて答えを待つことができない（ADR-0001）。かわりに、答えが足りなくなった時点で適用をやめ、答えを 1 つ受け取ってから**同じ盤面に対して最初からやり直す**。エンジンが純粋である以上、同じ盤面と同じ答えの並びからは必ず同じところまで進む。

## 影響

- サーバは行動 1 つを適用するのに、選択の回数だけやり直す。1 つの行動あたりの選択は多くて数回なので、やり直しの費用は問題にならない。エンジンを中断できるように作り替えるほうが高くつく。
- **選択の要求は、選ぶプレイヤーにだけ送る。** 候補にはそのプレイヤーだけが見てよいものが含まれる（自分の手札、効果が公開させた山札の中身。同 第23章 3）。相手にも送れば、そこから非公開情報が漏れる。
- 記録に残すのは盤面ではなく「行動と答えの並び」で足りる。同じデッキと同じシードから、そこまでの盤面をいつでも作り直せる（ADR-0005 の再生と同じ性質）。
- やりとりする値の型は、盤面を通信に載せる形（`wire.ts`）と同じくエンジンに置く。サーバとクライアントが共有しているのはエンジンだけであり（ADR-0001）、両側が同じ語彙を持つ場所がほかに無い。
