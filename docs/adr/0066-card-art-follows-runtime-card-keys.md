# ADR-0066: カード画像とフレーバーは既存のカードキーで対応付け、対戦サーバから供給する

- 状態: 決定
- 日付: 2026-11-06
- 決定者: 開発者

## 背景

この決定の時点では、通常のカード描画は画像とフレーバーを扱っていなかった。画像を表記全体で照合する試作では、同名の別カードや継続効果による修整と、カードの同一性を分離する必要があった。カード固有の素材を公開側へ含めず、カードを持たない環境でも検証できることが条件だった。

## 決定事項

- 画像の対応付けには既存のカードキーを使用する。デュエル中の1枚を指す識別子やカード名で代用しない。
- 画像参照とフレーバーを組にした表示情報を、非公開側の表示用データとして管理する。ルール用のカード定義には追加しない。
- 通常の対戦サーバが表示情報と画像を供給する。カードプールと、視点ごとの射影を済ませた表側のカードに、同じ対応付けを適用する。裏向きカードを識別する情報は追加しない。
- 非公開素材を持たない供給元と、表示情報を送らない古い通信も受け入れる。未登録のフレーバーは省略し、画像未登録・読込失敗でも全カードに共通の新しい配置と従来の背景を使用する。
- 元PNGは変更せず、文字やSVGを画像化しない。高品質縮小の失敗時は元画像を使用する。縮小画像の件数・メモリ・同時処理数に上限を設ける。

## 比較した選択肢

| 論点 | 採用した方針と理由 | 採用しなかった方針と理由 |
| --- | --- | --- |
| 識別 | 既存キーを表側の表示へ渡し、盤面とデッキ構築を統一する | 表示専用の画像参照だけを渡す方式では、既存の識別方法と別の受け渡しを管理する必要がある |
| 供給 | 対戦サーバにまとめ、通常起動で使用する | 画面が別カタログを取得する方式は、取得待ちと失敗時の経路が増える |
| 画像なし | 新しい配置を共通化し、読込結果で配置が動かないようにする | 従来配置との併用は、画像の有無で名前やアイコンの位置が異なる |
| フレーバー | 非公開側の表示用データで管理する | カード定義への追加は、表示情報のためにルール用の型の変更範囲を広げる |

## 影響と今回決定していないこと

通信の表示項目とサーバの素材供給設定が増える。表示情報は保存済みデュエルへ焼き込まず、復元時に現在の供給元から解決する。再録を元のカードキーに統一する既存の扱いを維持するため、再録ごとの別イラストには将来追加の設計が必要になる。

今回の確認はローカル環境を対象とする。個々の画像の採用、本番デプロイ、公開配信先、外部ストレージへのアップロードは決定していない。

## 実装

- 通信: `WireCardPresentation`、`CardPresentationOf`、`toWire`。
- サーバ: `CardSupply.artwork`、`presentationOfPool`、`handleArtwork`。画像の供給ディレクトリは起動時の作業ディレクトリを基準に解決し、登録済みPNGだけを `/card-art/<カードキー>` で配信する。
- 表示: `applyCardArtwork`。縮小は同時4件、縮小キャッシュは64件かつ32MiB以下。失敗した画像は128件まで記録して再描画による連続要求を抑える。
- 見た目の正は `docs/screens/shared/spec.md`。モックは架空カードと共通CSSを使用する。
