# サーバとクライアントは WebSocket で繋ぐ

サーバとクライアントの間は WebSocket 1 本で繋ぐ。実装には `ws` を使う。Node に WebSocket サーバの実装は無く、ブラウザ側は標準の `WebSocket` で足りる。

やりとりするメッセージ（ADR-0008）は、どちらの向きも独立した知らせであって、要求と応答の組ではない。サーバは行動の結果を両方のプレイヤーに押し出し、選んでほしいことは選ぶプレイヤーにだけ送る。この形には双方向の 1 本が素直に当てはまる。

**接続 1 本が参加者 1 人に対応する。** 誰であるかは接続する時の URL で名乗り（`?participant=`）、メッセージには載せない。切れたことがそのまま「その人がいなくなった」として分かる。

## 影響

- `packages/server` に実行時依存が入る。**エンジンが実行時依存を持たないこと（ADR-0001）とは別の話である。** あちらはブラウザとサーバの両方で動くための制約であり、`pnpm verify:engine` が検査し続ける。
- 名乗る値は**クライアントが持ち続ける合言葉**であって、認証ではない。最初の完走ではアカウント認証を作らない（#17）ため、これを知っている人がその席に座れる。
- 接続が切れても部屋は残り、同じ合言葉で入り直せば続きから打てる。盤面は差分ではなく毎回まるごと送っている（`wire.ts`）ので、入り直した人には**いまの盤面をもう一度送るだけでよい**。選択の途中で切れた場合も、貯めた答えの並びで適用をやり直せば同じ「選んでほしい」が再生される（ADR-0008）ので、送ったメッセージを覚えておく必要はない。
- 切れても部屋から抜けないぶん、**意図して抜ける口が別に要る。** 違う合言葉で入り直すことがそれにあたる（#92）。抜けられるのは、まだ相手を待っているだけの部屋と、決着した部屋だけである。打っている途中の部屋を抜けられるようにすると、合言葉の打ち間違いで対戦が消えることになる。
- 切れたときに繋ぎ直すのはクライアントの仕事である（ADR-0016）。ここで決めているのは、繋ぎ直した先で状態を合わせ直せることまでである。
- 部屋はサーバのメモリにしか無い。サーバを落とすと対戦は消える。最初の完走では永続化しない。
