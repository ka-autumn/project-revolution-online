# カード自身の「捨札に置かれた時」は、どのゾーンから置かれても誘発する

決定日: 2026-11-03。開発者と決定した。

## 背景

EB1.0 の 069 は、「このカードが捨札に置かれた時」に誘発するユニットである。開発者が確認した運用では、手札・スクエア・山札・プランゾーンなど、どのゾーンから捨札に置かれても誘発する。

総合ルールは、ユニットのテキストは、特定のゾーンで有効になると書かれていない限り、スクエアに置かれている間だけ有効になる、としている（第2部 第10章 3）。条文どおりに読むと、スクエアから捨札に置かれた時にしか誘発しない。実際の運用に合わせる。

いまの engine は、誘発型能力をスクエアにいるユニットの分しか探さない（`trigger.ts`）。スクエアから捨札に置く時だけは、`discardFromSquares` が置く直前の盤面で「あなたのユニットがスクエアから捨札に置かれた時」の能力を探している（同 第4部 第7章 10）。スクエアの外から捨札に置く経路は、次のとおり、どれも `moveToZone` を直接呼んでいて、誘発型能力を探さない。

- 効果で手札を捨てる（相手に捨てさせる場合を含む）
- 効果の「ゾーンへ置く」で、スクエア以外のゾーンから捨札に置く
- 効果の「山札の1番上をゾーンへ置く」で、捨札に置く
- トラップの廃棄
- プランの置き換え（新しくプランする時に、プランゾーンにあったカードを捨札に置く）
- コストで、カード自身を捨札に置く
- 解決が終わったストラテジー・トラップを、リゾルブゾーンから捨札に置く

後のエキスパンションにも、カード自身が捨札に置かれた時に誘発するテキストがある。

- 「このカードが手札かスクエアから捨札に置かれた時」（3 枚）
- 「このカードが相手のカードの効果でトラップゾーンから捨札に置かれた時」（1 枚）
- 「このカードが味方の『努力』の効果で捨札に置かれた時」（1 枚）

## 決定事項

### どのゾーンから捨札に置かれても誘発する

- **捨札以外のどのゾーンから捨札に置かれても、カード自身の「捨札に置かれた時」の能力は誘発する。** スクエア・手札・山札・プランゾーン・エネルギーゾーンに加えて、裏向きのゾーン（トラップゾーン・スマッシュゾーン）も含む。捨札に置かれた後は表向きの公開情報になるので、誘発したことを相手に知らせてよい。
- **誘発イベントを 1 つ追加する。** 名前は「このカードが捨札に置かれた時」とする。この誘発イベントの能力は、スクエアのユニットからではなく、捨札に置かれるカード自身からだけ探す。いまの「あなたのユニットがスクエアから捨札に置かれた時」は、スクエアにいるユニットが、自分か味方が置かれたのを受けて誘発するためのもので、動きを変更しない。
- **きっかけに、置かれる直前にあったゾーンを含める。** 「手札かスクエアから」「トラップゾーンから」のようなテキストは、カードの側の絞り込み（`when`）で、このゾーンを参照して実装する。

### 支配者と、能力を探す時の盤面

- **能力の支配者は、置かれる直前のそのカードの支配者とする。** スクエアの外にあるカードは持ち主のゾーンにあり、支配者は持ち主である（第2部 第21章 1-2）。このため、スクエアの外から置かれた時の支配者は、持ち主になる。
- **能力は、カードを動かす前の盤面で探す**（第4部 第7章 10）。スクエアから置かれる時のきっかけは、いまの「あなたのユニットがスクエアから捨札に置かれた時」と同じく、継続効果を適用した後のデータを持たせる。スクエアの外から置かれる時は、カードに書かれているデータを持たせる。

### 同時に複数枚が置かれた時

- **置かれたカードごとに、そのカード自身の能力が 1 度ずつ誘発する。** 誘発した能力は、同時にバンクに入る（第4部 第7章 3・6）。どのカードの能力も、すべてのカードを動かす前の盤面で探す。

### カードのゾーン移動は、すべて 1 つの関数を通す

以下、カードを動かす前に、行き先のゾーンに置かれた時に誘発する能力を探してから動かす関数を「ゾーン移動の関数」と呼ぶ。ゾーン移動そのものの処理（持ち主のゾーンへ置く、支配者を持ち主に戻す、ダメージや作成された効果を消す、など）だけを行い、誘発を探さない関数を「土台の関数」と呼ぶ。

- **カードをゾーンへ動かす処理は、誘発の有無によらず、すべてゾーン移動の関数を通す。** ゾーン移動の関数は、行き先のゾーンを引数に受け取る。捨札専用の関数にはしない。誘発の無いゾーンへの移動も、同じ関数を通す。
- **ゾーン移動の関数は、動かすカードを複数まとめて受け取る。** 同時に複数枚を動かす時は、すべてのカードを動かす前に誘発を探す必要がある（第4部 第7章 10）。
- **今回、誘発を探すのは行き先が捨札の時だけにする。** スクエアにいるユニットの「あなたのユニットがスクエアから捨札に置かれた時」と、置かれるカード自身の「このカードが捨札に置かれた時」の両方を、置く前の盤面で探す。いまの `discardFromSquares` は、ゾーン移動の関数にまとめる。ほかのゾーンが行き先の時は、誘発を探さずに動かす。
- **ほかのゾーンに置かれた時の誘発を実装する時は、ゾーン移動の関数に、そのゾーンの誘発を探す処理を追加する。** 関数は増やさない。呼び出し側も変更しなくてよい。EB1.0 には「スマッシュゾーンに置かれた時」、後のエキスパンションには「エネルギーゾーンに置かれた時」に誘発するテキストがある。

### 土台の関数は、ゾーン移動の関数だけが呼ぶ

- **いまの `moveToZone` の処理は、土台の関数として `duel.ts` に残す。** ゾーン移動の関数は、誘発を探した後にこれを呼ぶ。ゾーン移動の関数は誘発を探す処理（`trigger.ts`・`continuous.ts`）を使うので、`duel.ts` の外に置く。
- **土台の関数を import してよいのは、ゾーン移動の関数があるファイルだけにする。** 土台の関数は別のファイルから呼ぶので export する必要があり、型だけではほかのファイルから呼ぶことを止められない。ソースの import を照合するテストで確認する。テストのファイルは、盤面を準備するために土台の関数を使ってよい。
- 経路を追加した時に土台の関数を直接呼べば、このテストで検出できる。いまは、経路ごとに `discardFromSquares` を通すことを覚えておく必要がある（`resolve.ts` の「ゾーンへ置く」は、そのために分岐している）。
- **`duel.ts` の中のゾーン移動は、例外として土台の関数を直接呼ぶ。** カードを 1 枚引く処理（山札から手札）と、プランを裏向きにする処理（プランゾーンから山札）である。依存が循環するので、ゾーン移動の関数を呼べない。同じファイルの中の呼び出しは、import を照合するテストでは検出できない。今は手札・山札に置かれた時の誘発が無いので、問題にならない。手札・山札に置かれた時の誘発を実装する時は、この 2 つを `duel.ts` の外に移す。

### 同じターンの終わりに繰り返し誘発すること

- **EB1.0 の 069 が同じターンの終わりに何度も手札に戻ることを、そのまま許す。** ターンの終わりに手札に戻った EB1.0 の 069 を「手札を1枚選び、捨てる」で捨てると、また誘発し、リカバリーフェイズがやり直しになって（第3部 第10章 4）、同じターンの終わりにまた手札に戻る。手札に戻るたびに支配者に「加えてもよい」かを質問するので、支配者は断るか別のカードを捨てて、繰り返しを止められる。プレイヤーの選択で止められるループなので、引き分けにはならない（第4部 第15章 1・2）。engine に特別な処理は追加しない。
- 作成されるたびに別の能力なので、「ターンの終わり」に誘発する能力はそのターン中に 1 度だけ誘発する、という規定（第3部 第10章 5）には当たらない、と読む。

### 原因で絞り込むテキストは、今回は扱わない

- **「相手のカードの効果で」「『努力』の効果で」のように、捨札に置かれた原因で絞り込むテキストは、今回は扱わない。** きっかけに原因の情報を追加すれば、同じ仕組みで実装できる。実装するカードが出た時に、きっかけへ追加する。

## 検討した選択肢

### 誘発イベントの分け方

- **いまの「あなたのユニットがスクエアから捨札に置かれた時」を、どのゾーンからでも満たされる誘発イベントに広げる。** 誘発イベントは増えない。しかし、スクエアにいる味方の能力（「味方が捨札に置かれた時」）まで、手札や山札から置かれた時に誘発するようになる。いまのカードのすべてに、元のゾーンの絞り込みを追加し直す必要がある。また、探す場所が「スクエアのユニット」と「置かれるカード自身」の 2 通りになり、どちらで探すかを誘発イベントの値だけでは決められない。採用しない。

### 経路の取りこぼしを防ぐ方法

- **経路ごとに、誘発を探す処理を呼ぶ。** 経路を追加した時に呼び忘れても、検出できない。採用しない。
- **誘発の無いゾーンへの移動のために、行き先を型で制限した関数を別に残す。** 誘発を探すゾーン（今回は捨札）を引数の型から除いた関数で、誘発の無いゾーンへの移動はこれで行う。捨札へ置くのにこれを使えば、型検査で検出できる。しかし、同じ移動に 2 通りの呼び方ができる。また、新しいゾーンに誘発を実装するたびに、そのゾーンを型から除き、呼び出し側をゾーン移動の関数へ書き換える必要がある。すべてがはじめからゾーン移動の関数を通していれば、呼び出し側の変更は要らない。採用しない。

### ゾーン移動の関数の範囲

- **捨札専用の関数にする。** 今回の変更は小さい。しかし、スマッシュゾーンやエネルギーゾーンに置かれた時の誘発を実装するたびに、ゾーンごとの関数が増え、動かす前に探す処理を、ゾーンごとに実装することになる。スマッシュゾーンの誘発は、同じ EB1.0 にある。採用しない。

### 土台の関数を守る方法

- **ゾーン移動の関数を `duel.ts` に置き、土台の関数を export しない。** テストが要らず、ほかのファイルから土台を呼ぶことが完全にできなくなる。しかし、`duel.ts` はほかのファイルから型だけを import する、いちばん下の層である。誘発を探す処理（`trigger.ts`・`continuous.ts`）はすでに `duel.ts` を import しているので、依存が循環する。また、スクエアから置く時の、継続効果を適用した後のデータを、`duel.ts` が知る必要が出る。採用しない。
- **捨札へ置く時に、ゾーン移動の関数のファイルでしか作成できない値を、土台の関数の引数に要求する。** 型検査だけで止められ、テストが要らない。しかし、仕組みが込み入っていて、読む人に意図が伝わりにくい。採用しない。

### 繰り返しの扱い

- **1 枚のカードが作成した「ターンの終わり」の能力は、1 ターンに 1 度だけ誘発する。** 第3部 第10章 5 を、作成された能力にも当てはめる読み方である。テキストは「してもよい」なので、制限が無くても支配者が止められる。制限を追加すると、作成された誘発型能力の処理に、カードごとの記録が必要になる。採用しない。

## 既存の決定との関係

- **ADR-0057・ADR-0058。** EB1.0 の 069 の後半（そのターンの終わりに、捨札にあるこのカードを手札に追加する）は、この 2 つの仕組みで表現する。この決定は、前半の誘発だけを扱う。
- **ADR-0018・ADR-0053。** 新しい誘発イベントを使うのは、EB1.0 の 069 などこれから実装するカードだけである。捨札へ置く経路をまとめても、いまのカードで誘発する能力と、カードを置く順番は変化しない。このため、記録済みの対戦を打ち直した結果は変化しない。
- **ADR-0004。** 誘発した能力は両方のプレイヤーに送られる。誘発するのはカードが捨札に置かれた後で、そのカードは公開情報になっているので、裏向きのゾーンから置かれた場合も送ってよい。

## 影響

- engine に誘発イベントが 1 つ追加される。カードのゾーン移動が、行き先を受け取るゾーン移動の関数にまとまり、いまの `moveToZone` の処理は土台の関数になる。土台の関数の import を照合するテストが 1 つ追加される。
- 関数の名前は、実装の Issue で決定し、実装した後に「実装」の節に書く。
- EB1.0 の 069 は、この決定と ADR-0057・ADR-0058 で実装できるようになる。実装は別の Issue で行う。

## 実装

- ゾーン移動の関数: `moveToZone`（`zone-move.ts`）。動かすカードの識別子の並びと、行き先のゾーンと、置き方（向き・位置）を受け取る。以前の `discardFromSquares` と `moveFromSquareTo` は廃止した
- 土台の関数: `moveToZoneWithoutTriggers`（`duel.ts`）。誘発を探さないことが名前から読める。以前の `moveToZone` の処理そのもの
- スクエアにあるカードだけを動かしたい呼び出し側（破壊・ルールエフェクト）は、`discardedFromSquares`（`zone-move.ts`）で絞ってから `moveToZone` に渡す。ログに残すのも、絞った結果である
- 誘発イベント: `TRIGGER_EVENTS` の `'このカードが捨札に置かれた時'`。きっかけは `OwnDiscardOccasion`（`kind` が `'自身の捨札'`。`from` は `'スクエア'`・リゾルブゾーン・捨札以外のプレイヤーごとのゾーン）。スクエアのユニットのきっかけ（`TriggerOccasion`）には含めない
- `when` は `OwnDiscardCondition`。置かれたカード自身のきっかけだけを受け取り、`self` は受け取らない。効果は `OwnDiscardEffect` で、第 2 引数に捨札に置かれたそのカード（`CardInDiscardPile`）を受け取る
- 誘発した能力（`TriggeredInstance`）は `placed` を持つ。スクエアの外から置かれたカードには位置が無いので、`self` を省略可能にした。バンクから解決する時（`bank.ts` の `resolveBanked`）に `placed` を効果へ手渡し、命令の対象にできるようにする。解決する時までにそのカードが捨札を離れていても、効果は実行する（そのカードを対象にする命令だけが実行されない）
- 捨札に置く時に積む順は、スクエアのユニットの「あなたのユニットがスクエアから捨札に置かれた時」の能力が先で、置かれるカード自身の能力が後。バンクに入った能力の並びには意味が無い（`bank.ts`）ので、これは既存の能力の並びを変更しないための順である
- 土台の関数の import を照合するテスト: `packages/server/src/zone-move-imports.test.ts`。engine は Node の型を持たない（ADR-0001）ので、ファイルを読むこのテストは server に置いた
- 解決が終わったストラテジー・トラップをリゾルブゾーンから捨札に置く経路（`play.ts`）も、同じ関数を通す
