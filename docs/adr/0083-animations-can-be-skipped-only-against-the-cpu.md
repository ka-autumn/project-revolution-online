# 演出を省略できるのは CPU とのデュエルだけにし、表示しない設定はアカウントごとにサーバへ覚える

決定日: 2026-11-27。Issue #165・#134。開発者と決定した。

この文書は設計として先に書いた。実装した後で、実装で決定した名前を末尾の「実装」の節に書き足す。

## 背景

#165 で、演出の長さは 1 ターンあたり約 7.5 秒に決まった。演出が表示されている間は手を行えない（ADR-0080）ので、そのまま待ち時間になる。#165 と #134 は、演出を省略できるようにするかを、どちらか一方で決定すればよい論点として引き継いでいた。決定することは次の 3 つだった。

- 設定としてずっと表示しないのか、その場で 1 回飛ばすのか
- 飛ばした時に、盤面はすぐ最新へ追いつくのか
- 飛ばしても、見出しの中で終わるはずだった変化は完了しているか（半端に回ったカードを残さない）

人対人のデュエルでは、両者の画面で同じ演出が流れる。片方だけが飛ばせると、飛ばした側が先に手を行えるようになり、演出が相手に「何が起きたか」を伝える役目を果たさなくなる。

画面の好みを、アカウントごとにサーバへ覚えた前例は、まだ無い。置き場（SQLite）にあるのは、デュエル・ログインした人・デッキ・レシピなどで、ブラウザの `localStorage` には、参加者の識別子とデッキの下書きだけを置いている。

## 決定事項

### 人対人のデュエルでは、演出を飛ばせない

- 人対人のデュエルでは、演出をその場で飛ばす操作も、表示しない設定も効かない。両者の画面で、同じ長さの演出が流れる。

### CPU とのデュエルでは、その場で飛ばすことも、表示しないこともできる

- その場で飛ばす操作: 流れている演出を打ち切り、最新の盤面へ追いつく。打ち切った演出が終わらせるはずだった変化は、完了した状態で表示する（半端に回ったカードを残さない）。
- 表示しない設定: CPU とのデュエルで、演出を表示せずに、最新の盤面をすぐ表示する。
- 速さを選ぶ設定（演出を短くする）は、用意しない。
- その場で飛ばす操作の見た目（ボタンかキーか）は、仕様書とモックを作成する段階で開発者と決定する。

### 表示しない設定は、アカウントごとにサーバの置き場で覚える

- 表示しない設定は、ログインした人ごとに、サーバの置き場で覚える。別の端末でも同じ設定になる。
- 置き場に、画面の好みを覚える表か列を追加し、それを読み書きするメッセージを追加する。画面の好みを覚える最初の前例になる。
- 演出の本体とは別の PR で、演出より先に作成する。

### デプロイの順番

- サーバを先にデプロイする。
- 古い画面は、新しいメッセージを送らないので、今のまま動く。
- 新しい画面が古いサーバにつながった時は、設定を保存するメッセージが断られ、設定は保存されない。画面は、既定の値（演出を表示する）のまま動く。

## 検討した選択肢

### どこで省略を認めるか

- **人対人でも、自分の画面だけ飛ばせる。** 飛ばした側だけが先に手を行えるようになり、相手に何が起きたかを伝える演出の役目が崩れる。採用しない。
- **CPU とのデュエルだけで認める。** 待たせる相手がいない。採用した。

### 省略の単位

- **その場で飛ばす操作だけ。** 演出を見たくない人は、毎回押すことになる。採用しない。
- **表示しない設定だけ。** たまに飛ばしたい人が、設定を切り替え続けることになる。採用しない。
- **両方を用意する。** 採用した。
- **速さを選ぶ設定も用意する。** 選択肢が増え、演出の長さを決定した理由（#165 の表）がぼやける。採用しない。

### どこに覚えるか

- **ブラウザの `localStorage` に覚える。** サーバを変更しないが、端末ごとに設定し直すことになる。採用しない。
- **アカウントごとに、サーバの置き場で覚える。** 採用した。

## 既存の決定との関係

- ADR-0019（身元は Google から受け取る）の、ログインした人を単位にして覚える。
- ADR-0080 の「演出は時計どおりに進む」は、人対人のデュエルではそのまま、CPU とのデュエルでは、飛ばした時と表示しない設定の時にだけ、最新の盤面へすぐ追いつく。

## この決定が決定していないこと

- その場で飛ばす操作の見た目（仕様書とモックで決定する）
- 設定を変更する場所（どの画面に置くか）
- 置き場の表・列と、メッセージの名前

## 影響

- サーバの置き場と通信に、画面の好みを追加する。
- 対戦画面に、その場で飛ばす操作を追加する。仕様書とモックを直す。

## 実装

表示しない設定の置き場と通信（演出の本体より先に実装した分）:

- 置き場の表: `screen_preferences`。列は `identity`（ログインした人。`identities` の行番号で、主キー）と `skip_animations`（0 か 1）。行が無ければ、演出を表示する。
- 置き場のメソッド: `store.ts` の `screenPreferencesOf` と `saveScreenPreferences`。
- サーバから画面へのメッセージ: `{ kind: '画面の好み', preferences: { skipAnimations } }`。ログインした接続に、入った直後（名前を決定する必要があれば、決定した直後）にロビーや盤面より先に送り、保存への返事にも使う。
- 画面からサーバへのメッセージ: `{ kind: '画面の好みを保存する', preferences: { skipAnimations } }`。ログインを持たない立て方では `行えなかった` で断り、形式が違うものは読めないメッセージとして断る。
- 保存した値は、同じ人がいま開いている他の接続へは送らない。次に繋いだ時に同じ値になる。デッキの保存と同じ方式で、今のサーバは 1 人につき 1 つの接続しか覚えていない。
- 古い値を持ったタブで保存し直すと、他のタブでの変更を上書きする。この場面は、設定を変更する画面の PR で検討する。
- 画面の状態: `session.ts` の `screenPreferences`（届いていなければ `undefined`）と、届いていない時に既定の値を返す `screenPreferencesOf`。繋がるたびに `sessionAfterLinkChange` が `screenPreferences` を `undefined` に戻し、その接続で届いた時だけ入れる。

「デプロイの順番」の節のとおり、サーバを先にデプロイする。設定を変更する画面は、まだ無い。
