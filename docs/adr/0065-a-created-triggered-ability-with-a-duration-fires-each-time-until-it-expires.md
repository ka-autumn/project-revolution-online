# 期限を持つ作成された誘発型能力は、期限まで残り、誘発イベントが起きるたびに誘発する

決定日: 2026-11-05。開発者と決定した。

## 背景

EB1.0 の 073・EB1.0 の 082 は、プレイすると「次の相手のターンの終わりまで、あなたのカードがスマッシュゾーンに置かれた時、〜してよい」という誘発型能力を作成する（例は架空のテキスト。以下同じ）。

総合ルール 第4部 第3章 4 は、特別に規定された期限を持つ作成された誘発型能力は、定められた期限まで、誘発イベントが起きるたびに何度でも誘発すると定めている。いまの engine は、作成された誘発型能力を「次に誘発イベントが起こった時に 1 度だけ誘発し、誘発と同時に取り除く」ものとしてだけ実装している（ADR-0057・ADR-0058）。この 2 枚を実装するには、次の 3 つが無い。

- 期限。作成された継続効果の期限（`DURATIONS`）は「ターンの終わりまで」だけで、作成された誘発型能力には期限そのものが無い。
- 誘発イベント「あなたのカードがスマッシュゾーンに置かれた時」。`CREATED_TRIGGERS` はターンの終わりだけである。
- 対象を持たない作成された誘発型能力。いまの 2 種類（対象がスクエアのユニット、対象が捨札のカード）は、どちらも対象を 1 枚必ず受け取る。

後のエキスパンションでは、期限を持つ作成された誘発型能力は BR2.0 に 1 枚ある（「次の自分のターンの終わりまで、次に味方が登場した時、その味方を〜」。1 度だけ誘発し、きっかけのカードを対象にとる）。作成された継続効果の期限「次のターンの終わりまで」は FJ2.0 に 5 枚ある。

作成された誘発型能力のログの行は、ADR-0063 で「いつ、〈対象〉を、何をする」とし、誰の行動かは行頭の持ち主のマークで読むと決定した。期限を持つ能力の「いつ」の言い方は、同 ADR の未決定事項に残っている。

## 決定事項

### 期限は、作成された継続効果と同じ値（`DURATIONS`）で持つ

- **`DURATIONS` に「次の相手のターンの終わりまで」を追加し、作成された継続効果と作成された誘発型能力で共有する。** 作成された誘発型能力は、期限を省略できるプロパティとして持つ。期限を持たない能力の動きは変更しない。
- **期限は、リカバリーフェイズの最初に、「ターンの終わりまで」の効果が終了するのと同時に終了する（総合ルール 第3部 第10章 1）。** 期限が終了したかの判定は 1 つの関数にまとめ、作成された継続効果と作成された誘発型能力の両方に使う。
- 「次の相手のターンの終わりまで」は、作成されたターンより後に来る、支配者の相手のターンのリカバリーフェイズの最初に終了する。支配者のターンに作成されれば、続く相手のターンで終了する。相手のターンに作成されれば、そのターンではなく、その次の相手のターンで終了する。
- このため、作成された継続効果も、作成されたターンを持つ。「ターンの終わりまで」の効果の動きは変更しない。
- 期限が終了した作成された誘発型能力は、盤面から取り除く。取り除いたことはログに出力しない（ADR-0058 と同じ）。

### 期限を持つ能力は、誘発しても取り除かない

- **期限を持つ作成された誘発型能力は、期限まで、誘発イベントが起きるたびに誘発する（総合ルール 第4部 第3章 4 の 2 文目）。** 誘発しても盤面から取り除かない。期限を持たない能力は、いまと同じく、誘発と同時に取り除く。

### 誘発イベント「あなたのカードがスマッシュゾーンに置かれた時」を追加する

- **`CREATED_TRIGGERS` に「あなたのカードがスマッシュゾーンに置かれた時」を追加する。**
- カードは持ち主以外のスマッシュゾーンには置かれない（総合ルール 第2部 第21章 1-2）ので、支配者のスマッシュゾーンにカードが置かれた時に誘発する。
- スマッシュゾーンにカードが置かれる経路は 2 つある。希望ステップで山札の 1 番上のカードが表向きに置かれる時（総合ルール 第3部 第19章 1）と、効果でカードをスマッシュゾーンに置く時である。どちらも、ゾーン移動の共通の関数（`moveToZone`）で検知し、1 枚置かれるたびに 1 回誘発する。2000 のダメージなら希望ステップが 2 回あり、2 回誘発する。
- 誘発した能力は、次に優先権が発生した時にバンクに入る（同 第4部 第3章 2）。

### 対象を持たない作成された誘発型能力を、3 つ目の種類として追加する

- **作成された誘発型能力に、対象を持たない種類（`place: 'なし'`）を追加し、それを作成する関数を別に追加する。** 引数は、誘発イベント・何をするかの文・効果・期限（省略できる）である。効果は対象を受け取らない。
- 対象が無いので、総合ルール 第4部 第3章 4-1（対象がゾーン移動すると消滅する）は適用されない。盤面から無くなるのは、期限が終了した時と、期限を持たずに誘発した時である。
- 既存の 2 種類と、それを作成する関数のシグネチャは変更しない。期限の引数は、対象を持つ種類で期限を持つテキスト（BR2.0 の 1 枚）を実装する時に追加する。

### 「してもよい」は、ADR-0064 の命令に動きの値を 2 つ追加して聞く

- `MAY_ACTIONS` に「1枚引く」と「山札の1番上のカードをエネルギーゾーンにフリーズして置く」を追加する。どちらも対象のカードは 0 枚である。
- ダイアログの聞く文は、対象が無いので「聞く」の言い方だけになる（「1枚引きますか？」「山札の1番上のカードをエネルギーゾーンにフリーズして置きますか？」）。「した」「しなかった」の言い方も、ADR-0064 の表に追加する。
- 答えと記録の形式は ADR-0064 のまま変更しない。

### 作成された誘発型能力の行は、相手の行にだけ主語を書く

ADR-0063 の「誰の行動かは、行頭の持ち主のマークで読む」を、次のとおり変更する。作成された誘発型能力の、作成した時のログの行と、カードの詳細の「誘発待ち」の枠の行のすべてに適用する。

- **支配者が見る人自身の行は、主語を書かない。** 支配者を「自分の」、支配者の相手を「相手の」と言う。
- **支配者が見る人の相手の行は、行頭に主語「相手は、」を書く。** その行の中では、支配者を「自身の」、支配者の相手（見る人自身）を「こちらの」と言う。
- 理由: 主語を省いた日本語は、読む人が主語に読まれやすい。相手の行で主語を省くと、相手の行動が自分の行動に読める。主語を書いた行では、「自分の」「相手の」が主語から見た言い方にも読めるため、主語を指す「自身の」と、読む人の側を指す「こちらの」を使う。
- 例（A の画面。A が支配者の能力と、B が支配者の能力）:
  - 「相手のターンの終わりまで、自分のカードがスマッシュゾーンに置かれるたびに、山札をシャッフルしてもよい」
  - 「相手は、こちらのターンの終わりまで、自身のカードがスマッシュゾーンに置かれるたびに、山札をシャッフルしてもよい」
  - 既存の形では「相手は、自身のターンの終わりに、〈番人〉をエネルギーゾーンにフリーズして置く」。
- ADR-0063 の「カードの詳細の枠は、自分の視点でも相手の視点でも同じ内容を表示する」は、「同じ決まりで、見る人ごとに言い換える」に変更する。
- カードのテキストの「あなた」は、画面の言葉には使わない。
- **何をするかの文（カードの側が渡す文。ADR-0063）には、「自分の」「相手の」を書かない。** 持ち主を言わなくても支配者の行動として読める書き方にする（「手札を1枚捨てる」「山札をシャッフルする」）。engine も画面も文の中身を参照しないので、文に持ち主の言葉があると、上の言い換えが及ばず、相手の行で読み違える。ADR-0063 の例「自分の手札を2枚捨てる」は、「手札を2枚捨てる」と書く。いま何をするかの文を持つ 5 枚（EB1.0 の 015・EB1.0 の 069・トライアルデッキ G の 19・EB1.0 の 073・EB1.0 の 082）は、どれも持ち主を言わずに書ける。

### 期限を持つ能力の「いつ」は、「〈期限〉、〈誘発イベント〉たびに、」と言う

- ADR-0063 の未決定事項「期限を持ち、何度も誘発しうる作成された誘発型能力の『いつ』の言い方」を、次のとおり決定する。
- **誘発イベントは「〜時に」ではなく「〜たびに」と言う。** 期限まで何度でも誘発することを、行を読むだけで分かるようにするため。
- **期限には「次の」を付けず、誰のターンかだけを言う**（「相手のターンの終わりまで」「こちらのターンの終わりまで」）。支配者のターンに作成された能力では、「相手のターン」はこれから来る相手のターンしか指さない。相手のターンに入った後も、そのターンを指すので正しい。
- 支配者の相手のターンに作成された能力では、「相手のターン」が今のターンにも読める。073・082 はストラテジーで、支配者のメインフェイズにしか作成されない。相手のターンに作成する形のテキストを実装する時に、言い方を決定する（「次の」を付ける見込み）。

### 対象を持たない能力は、ログだけで知らせる

- **対象を持たない作成された誘発型能力は、カードの詳細にも盤面にも表示しない。** 作成した時のログの行と、誘発した時のログの行（「誘発：〈作成したカード〉」）だけで知らせる。
- 盤面だけが持ち、通信のデータ（`VisibleCreatedAbility`）には含めない。表示する場所を追加する時に、あわせて追加する。
- プレイヤーの枠に「誘発待ち」のバッジを表示し、押すと一覧が開く形は、別の Issue で検討する。

## 検討した選択肢

### 期限が終了する時点

- **次の相手のターンが終わる時（リカバリーフェイズが済み、次のターンへ移る時）に取り除く。** ADR-0058 の「ターンの終わり」の能力を取り除く所と同じ場所で済む。しかし、同じ「〜まで」の言葉で、作成された継続効果と終了する時点が食い違う。相手のリカバリーフェイズの中でスマッシュゾーンにカードが置かれた時だけ、結果が異なる。採用しない。

### 期限の値の置き場所

- **作成された誘発型能力の期限を、別の一覧に持つ。** 作成された継続効果には手を入れずに済み、使うカードの無い組み合わせ（作成された継続効果 × 次の相手のターンの終わりまで）も生まれない。しかし、同じ「〜まで」の言葉が 2 つの一覧に分かれ、終了する時点の判定も 2 か所になる。FJ2.0 の「次のターンの終わりまで」を実装する時に、両方へ追加するか、まとめ直すことになる。採用しない。

### 対象を持たない能力の作成方法

- **いまの `createTriggeredAbility` の対象を省略できるようにする。** 関数は増えない。しかし、対象を持つ能力の効果も「対象が無いかもしれない」型で受け取ることになり、既存の 3 枚（EB1.0 の 015・EB1.0 の 069・トライアルデッキ G の 19）の効果に、要らない分岐が入る。ADR-0057 の「対象がどこにあるかは種類で決まり、効果が受け取る型もそれで決まる」とも合わない。採用しない。
- **TypeScript のオーバーロードで、1 つの名前のまま対象あり・なしを宣言する。** 呼ぶ側の型は守れるが、実装の中で引数の形を調べて分岐する処理が残る。ADR-0057 で関数の名前で種類を分けたことと合わない。採用しない。

### 相手の行の主語

- **ADR-0063 のとおり、行頭のマークだけで読ませる。** 新しく決定することは無いが、相手の行動が自分の行動に読める問題が残る。採用しない。
- **期限を持つ行にだけ、主語を書く。** 既存の行は変更しないが、同じ種類の行で、主語のあるものと無いものが混ざる。採用しない。
- **カードのテキストどおり、支配者から見た言い方に固定する。** 文言は素直だが、ADR-0063 の「見る人ごとに言い換える」と食い違い、ログのほかの行とも合わない。採用しない。

### 主語を書いた行での、支配者の相手の言い方

- **「あなたの」。** 読む人を指すので主語とは取り違えないが、カードのテキストでは「あなた」は支配者を指す。カードを読み慣れた人ほど、支配者のことに読む。採用しない。
- **「自分の」。** 主語を書いた文では、主語を指すのが自然な読みになる。採用しない。

### 期限を持つ能力の「いつ」

- **カードのテキストどおり「〜時に」と言う。** 1 度だけ誘発する能力の行と見分けがつかない。採用しない。
- **「次のターンの終わりまで」と言う。** 「自分／相手」の言い換えは 1 か所で済むが、主語と「自身の／こちらの」の決まりで同じ問題が解けたので、誰のターンかを言うほうを採用した。

### 対象を持たない能力の表示

- **能力を作成したカードの詳細に「誘発待ち」の枠を表示する。** 新しい部品は要らないが、捨札を開かないと気づけない。作成したカードが捨札を離れると、能力は残るのに表示だけが消える。採用しない。
- **プレイヤーの枠に「誘発待ち」のバッジを表示する。** 盤面を見るだけで気づける。新しい部品で、仕様書とモックを新しく起こす必要があり、スマートフォンの配置も決定する必要がある。この段階には含めず、別の Issue で検討する。

### 何をするかの文の、持ち主の言い方

- **文の中で持ち主を指す所を記号（例: `{支配者}の手札を2枚捨てる`）で書かせ、画面が見る人ごとに言い換える。** 後で作成し直さずに済むが、いま使うカードが無い仕組みを入れることになる。採用しない。

## 未決定事項

- **持ち主を言う必要のある、何をするかの文。** 相手のものを指す文など、持ち主を言わずには書けない文が出てきた時に、見る人ごとに言い換える仕組みと一緒に決定する。
- **支配者の相手のターンに作成された、期限を持つ能力の「いつ」の言い方。** そのテキストを実装する時に決定する。
- **対象を持たない作成された誘発型能力を、画面のどこに表示するか。** 別の Issue で検討する。

## 通信のデータの互換

- 「してもよい」の動きの値を追加したので、開いたままの古い画面に新しい値が届くと、画面の文言表に行が無く、聞く文とログの描画で例外になる。知らない値を「読めなかった」として扱う分岐は実装しない。画面はまだ公開前で、再読み込みで直るためである（ADR-0063 と同じ判断）。
- 作成されたログのできごと（`対象を持たない誘発型能力を作る`）を知らない古い画面は、読めない種類として扱う（#285）。
- サーバを画面より先にデプロイする。

## 既存の決定との関係

- **ADR-0057・ADR-0058。** 期限を持たない作成された誘発型能力の動きは変更しない。ADR-0058 の「この決定は、期限を持つ能力の設計を制約しない」のとおり、期限は誘発イベントとは別のプロパティで持つ。
- **ADR-0063。** 未決定事項のうち「期限を持つ能力の『いつ』の言い方」を決定した。「誰の行動かは行頭のマークで読む」と「カードの詳細の枠は、自分の視点でも相手の視点でも同じ内容」を変更した。そのほかの未決定事項（注記と誘発待ちを両方持つカードの高さ、能力が能力を作成した場合の作成したカード、対象を目的語にしない文、『』の能力を与える継続効果の表示）は、073・082 に関わらない。073・082 は誘発待ちの枠を表示せず、能力を作成する能力を持たず、何をするかの文に対象が無い。
- **ADR-0064。** 「はい／いいえ」で聞く「してもよい」に、対象が 0 枚の動きの値を 2 つ追加する。
- **ADR-0018・ADR-0053。** 追加する値と種類を使うのは 073・082 だけである。期限が終了する判定を作成された継続効果と共有するが、「ターンの終わりまで」の終了する時点は変更しない。このため、記録済みの対戦を打ち直した盤面は変化しない。ログの言い方の変更は、表示だけに及ぶ。
- **ADR-0062。** CPU は「してもよい」を効果の空回しで判断する。新しい判断は追加しない。

## 影響

- engine: `DURATIONS` と `CREATED_TRIGGERS` に値を 1 つずつ追加する。作成された誘発型能力に、期限と、対象を持たない種類が追加される。作成された継続効果が、作成されたターンを持つ。希望ステップでスマッシュゾーンにカードを置く処理から、作成された誘発型能力を誘発させる。`MAY_ACTIONS` に値を 2 つ追加する。
- 非公開側: EB1.0 の 073・EB1.0 の 082 を実装する。
- 画面: 作成された誘発型能力のログの行と、カードの詳細の「誘発待ち」の枠の言い方を、相手の行で変更する。「してもよい」の言い方の表に 2 行追加する。仕様書とモックも直す（ADR-0044）。
- デプロイ: ログの言い方の変更は画面だけで済む。新しいカードはサーバのデプロイ後に遊べる。

## 実装

- 期限の値: `DURATIONS` の `'次の相手のターンの終わりまで'`。終了を判定する関数は `durationEnds`（`effect.ts`）。作成された継続効果は `CreatedContinuousEffect.createdIn` を持つ
- 誘発イベント: `CREATED_TRIGGERS` の `'あなたのカードがスマッシュゾーンに置かれた時'`。`moveToZone`（`zone-move.ts`）が、行き先がスマッシュゾーンの時に、動かした後に `triggerOnSmashZone`（`trigger.ts`）を呼ぶ
- 対象を持たない種類: `CreatedUntargetedAbility`（`place: 'なし'`）、作成する関数 `createUntargetedTriggeredAbility`。盤面の `CreatedAbility.affecting` は、この種類では `undefined`。誘発した能力は `CreatedUntargetedInstance`
- 命令とログ: 命令 `'対象を持たない誘発型能力を作る'`、ログのできごと `'対象を持たない誘発型能力を作る'`（`trigger`・`description`・`duration`）
- 「してもよい」の動き: `MAY_ACTIONS` の `'1枚引く'` と `'山札の1番上のカードをエネルギーゾーンにフリーズして置く'`。対象を持たない動きの一覧は `UNTARGETED_MAY_ACTIONS`。山札が空の時は聞かずに「いいえ」として進む（総合ルール 第1部 第1章 3）
- 画面の言い方: `createdAbilityText`（`view-model.ts`）。「してもよい」の文言表（`may-wording.ts`）の「はい」の行は、対象を持たない動きでは出力しない
