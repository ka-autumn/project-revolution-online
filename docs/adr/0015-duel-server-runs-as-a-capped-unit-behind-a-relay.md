# 対戦サーバは、上限を掛けた常駐単位として中継の後ろに置く

置き場が決まった（ADR-0014）ので、置き方を決める。**束ねた 1 ファイルを運び、専用の利用者で走る常駐単位として立て、使えるメモリに上限を掛け、TLS はそのマシンに元からある中継で終端して WebSocket をそのまま後ろへ渡す。**

置き場そのものについては ADR-0014 の条件だけを前提にする。**どこにあるか、何と同居しているかは、ここには書かない。** 満たすべきことはこの 4 つである。

- 常時動いていて、再起動しても勝手に立ち上がること
- 固定の名前で 443 番に届くこと
- Node 22 以上が載ること（束ねたものはそれ向けに出している）
- 同居するものと独立していられること

## 束ねたものだけを運ぶ

**カードは置き場でビルドさせない**（ADR-0002、ADR-0013、ADR-0014）。束ねるのは手元だけで行い、置き場へ渡すのは出来上がった 1 ファイルにする。置き場がリポジトリを読んでビルドする形にすると、非公開のカードをそこへ渡すことになってしまう。

- `pnpm build:server` — 1 ファイルを書き出す。出力は `dist/` に置き、**リポジトリには入れない**（焼き込んだカードごと追跡してしまう）
- `pnpm deploy:server` — 束ねる・運ぶ・差し替えて立て直す、をまとめて行う

**束ね方は 1 箇所にしか置かない**（`tools/bundle-server.mjs`）。手元で立てたもの（`pnpm serve`）と運ぶものが別物になると、手元で通ったことが置き場で通る保証にならない。

**宛先はリポジトリに書かない。** 引数か環境変数で受け取る。ここに書いてよいのは運び方だけである。

**一度別の名前で置いてから差し替える。** 転送の途中で落ちたものを常駐単位が拾って起動してしまうことがないようにするためである。

## 待つポートは焼き付けない

束ねたものは、焼き付けた既定を環境変数で上書きできるようにしてある。**置き場では、待つポートを常駐の設定の側で決めたい。** 束ね直さずに変えられる余地を残しておく。

## 独立した常駐単位として立てる

ADR-0014 の「他のものと同じマシンに置くなら独立させる」を、次の形にする。

- **専用の利用者で走らせる。** 他のものと同じ利用者で走らせない
- **使えるメモリに上限を掛ける**（256MB）。50 部屋で 84MB なので（ADR-0014）、暴れたときに巻き込む範囲をそこで止められる
- **落ちたら立て直す。** 部屋はメモリにしかない（ADR-0009）ので立て直せば対戦は消えるが、**消えたまま繋がらないよりは良い**
- **運ぶための鍵にできることを絞る。** 中身の差し替えと、その常駐単位の立て直しだけ。同じマシンの他のものには手が届かないようにする

## TLS は中継で終端する

そのマシンに元からある中継（リバースプロキシ）に相乗りし、そこで終端して WebSocket をそのまま後ろへ渡す。対戦サーバ自身に TLS を持たせない。**証明書の更新も、既にそこにある仕組みに任せられる。**

**期限切れの通知先を登録しておく。** 自動更新は失敗しうるし、失敗しても誰も打たれない。**送り続けているものが無いものは、次に使おうとした時にしか壊れていることが分からない**——これは接続についても証明書についても同じである。

### 中継の待ち時間を延ばす

**ADR-0014 の「トンネルを外せばこの制限は来ない」は、半分しか正しくなかった。** 外したのは Cloudflare の 100 秒であって、**待ち時間という性質は中継そのものに付いてくる。** 自前で立てた中継にも既定の読み取り待ちがあり、そちらのほうが短いことすらある。

サーバにもクライアントにも ping / pong が無いので（ADR-0014）、**考え込んでいる間は本当に何も流れない。** 既定のままだと、黙っていた側がそこで落ちる。読み取りと書き出しの待ち時間を、人が考え込む長さより十分に長く取る。

**これは ping / pong の代わりにはならない。** 中継を自分で設定できたので既定を延ばせただけで、間に入る何か（携帯網、家庭用ルータ）が黙って落とす可能性は残っている。

## 影響

- **更新は 1 コマンドになった。** 束ねる・運ぶ・立て直すが一続きで、途中で失敗すればそこで止まる。
- **置き直すと、そのとき進んでいた対戦は消える**（ADR-0009、ADR-0014）。上限も立て直しもそれを変えない。
- **手元の機械は要らなくなった。** 画面は `VITE_SERVER_URL` を固定の `wss` に焼くだけで、作りは変わらない（ADR-0013）。
- **ping / pong が無いことは残ったままである。** 中継の待ち時間を延ばして先送りしただけで、落ちたことに気付くのは次に打とうとした時になる。
- **固定の名前で出し続けることになった。** 張り直すたびに URL が変わることで結果的に人を遠ざけていた性質（ADR-0013）は、もう無い。アカウント認証を作っていないこと（#17）の重みは ADR-0014 が書いたとおりで、ここで軽くはならない。
- **同じ形で 2 台目を立てることはできない。** 部屋がメモリにしかない以上、2 人が同じプロセスに繋がっていなければ対戦が成立しない（ADR-0009、ADR-0014）。増やすときは 1 台を大きくする方向にしかいけない。
