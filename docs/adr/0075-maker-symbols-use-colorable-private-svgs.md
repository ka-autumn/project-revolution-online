# メーカーシンボルを非公開側のSVGで再現し、カード色に合わせて配色する

## 背景

この文書を記録した時点では、メーカーシンボルは略号入りの丸で代替していた。開発者から実カード画像が提供され、記号の文字形と、カード色によって配色が異なることを確認した。固定配色の画像を一つ指定するだけでは、各カードの表示に対応できなかった。

## 決定事項

- 印刷された記号の文字形をSVGの輪郭として再現する。実在の記号・文字形・資料との対応は非公開側で管理し、公開側の説明・モック・テストには架空の記号を使用する。
- 文字形は共通とし、カード色に応じて配色する。画面は、カード面の色を決定する既存処理と同じ値を、ロゴ取得時の `color` に指定する。サーバは受け付ける5色を検証し、SVGのルートへ `data-card-color` を設定する。配色自体はSVGが定義する。
- SVGはフォント・元のカード画像・外部画像に依存させない。縦横比を維持して表示し、読み上げとツールチップにはブロック名を使用する。
- 画像を読み込むまでは丸の代替表示を維持し、成功後に丸と背景を取り除いてSVGへ置き換える。失敗時は代替表示を維持する。
- 小さなSVGは非公開側で読み込み、URLエンコードした埋め込みSVGとして供給する。ビルドに含めるため、サーバ実行ファイルとは別のSVG転送を必要としない。通信のメーカー表には取得URLだけを含める。

## 検討した選択肢

- 実カード画像から色ごとの記号を切り出す方式も検討した。元画像の解像度と背景除去に左右され、色ごとの画像も必要になるため、文字形をSVGで共通化する方式を開発者が選択した。

## 実装

- `makers[].logo` は画像ファイルのパスに加え、`data:image/svg+xml,` にURLエンコードしたSVGを続けた文字列を受け付ける。
- サーバのビルドは `*.svg?raw` をテキストとして読み込む。実在のSVG本文は非公開側でのみ参照する。
- 取得先は `/maker-logos/<記号>?color=<カード色>`。同じ文字形をカード色ごとに取得し、画面は成功した画像の縦横比を表示幅へ反映する。
