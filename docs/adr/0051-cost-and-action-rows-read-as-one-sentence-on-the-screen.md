# コストの支払いと行った手は、画面の側で 1 行の文にまとめる

決定日: 2026-10-22。Issue #331。開発者と決定した。

## 背景

この文書を書いた時点では、コストを支払って行った手が、操作ログで「コストを支払った」の行と「行動した」の行に分かれて並んでいた。ADR-0050 で、並びは「コストの支払い → 行った手」になっている。プレイヤーにとってはひとつの手なのに、2 つの行の関係が読み取りにくかった。

行った手の行は「カードをプレイする：〈カード〉（〈スクエア〉）」のように、行動の名前をそのまま出す形だった。コストの行は「〈カード〉をコストとしてフリーズした」、スマッシュで払った時は「コストとしてスマッシュをフリーズした」だった。

## 決めたこと

ログを行にする時（`view-model.ts`）に、同じプレイヤーの「コストを支払った」が続き、その直後に同じプレイヤーの「行動した」があれば、それらを 1 行の文にまとめる。記録の順（コスト → 行った手）のまま読める形にする。エンジン・通信・記録の形は変えない。

```
〈エネルギーA〉、〈エネルギーC〉をフリーズし、〈ユニットB〉を味方エリアの左ラインにプレイした
```

- 「コストとして」は付けない。何をしたかは動詞（「フリーズし」）で言い、直後に行った手が続くことで、コストの支払いと読める。
- 行った手は、コストを伴わない手も含めて、すべて文の形（「〜をプレイした」）にそろえる。
- コストが 2 枚以上ある時は、同じ動詞の前にまとめ、区切りは「、」にする（#171）。
- スマッシュは持ち主からも名前が見えないので、「スマッシュ1枚」のように枚数で言い、スマッシュ同士はまとめる。名前の見えないコストのカードも、同じく枚数で言う。
- 「勇気」は起動すると必ず自身を捨札にするので、手の言い方の中で「〈カード〉を捨札にして「勇気」を起動した」と言う。
- 自身を捨札にする起動型能力は、捨札にしたことを言わない。
- コストの行の後に行った手の行が続かない時（コストを選んでいる間など）は、コストの行を今の言い方のまま単独で出す。
- 識別子は届いたのに名前が届かなかったカード（届け漏れ）は、これまで「見えていないカード」と出していた。見え方の規則で隠したように読めるので、画面全体で「不明なカード」に改める。名指しが落ちたカードは、これまでどおり名前のところを省く。
- 相手のターンに優先権が来た時の一文（`priorityReason`）には、コストを入れない。打つ手を決める前に 1 度だけ読む文で、直前の手が分かれば足り、コストは操作ログで確かめられるため。

## 検討した選択肢

- **1 行の文にする。** 行数が増えず、記録の順のまま読める。この案を採る。
- **行った手を見出しにし、コストを下に字下げして添える。** 手が先に目に入るが、記録の順と逆になる。ログには手順の中のできごとを字下げする仕組み（#133）があり、それと見分ける印が別に要る。採らない。
- **行った手を先に書き、コストを括弧で添える。** 1 行で手が先頭に来るが、記録の順と逆になる。採らない。
- **エンジンの「行動した」にコストを持たせる。** 記録の側で 1 件になるが、通信の形と、見え方で名指しを落とす処理（`perspective.ts`）を変えることになる。まとめる理由が表示だけなので、採らない。
- **「コストとして」を残し、「フリーズし」を省く**（「〈A〉をコストに、〈B〉をプレイした」）。支払いだと誤読されないが、何をしたかが消える。採らない。

## 影響

自身を捨札にする分は、コストの支払いとしてログに積まれない（`activate.ts` の `payActivationCost` は捨札へ動かすだけで、「コストを支払った」はフリーズだけを表す）。「行動した」は、どの起動型能力を起動したかを持たないので、起動型能力のコストに捨札が含まれるかは画面の側では分からない。言い分けるには記録の形を変えることになる。この決定では扱わず、必要になった時に改めて決める。
