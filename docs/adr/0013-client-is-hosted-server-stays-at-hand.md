# 画面は配り、サーバは手元に置いたまま外へ出す

手元以外の端末から動かして確かめられるように、**画面だけを配り（Vercel）、対戦サーバは手元で立てたまま、外から届く口をトンネル（Cloudflare Tunnel）で生やす。**

この 2 つは必要とするものが違う。画面はビルドした結果を配るだけで、走り続けるものが何も無い。サーバは WebSocket を張りっぱなしにし、部屋をメモリに持ち続ける（ADR-0009）ので、走らせ続けられる場所が要る。**そこを借りるには費用がかかるが、確かめるために要るのは「離れた端末から届くこと」だけで、サーバがどこで走っているかは問われない。** 手元で立てたものに外から届く口を付ければ足りる。

**繋ぎ先は画面が知っている。** 中継は挟まない。WebSocket 1 本を直に張るだけなので（ADR-0009）、同じ出所である必要が無い。どこへ繋ぐかは次の順で決まる（`packages/client/src/main.ts`）。

1. `?server=` — 開く時に差し替える
2. ビルド時の `VITE_SERVER_URL` — 置いた画面の既定
3. 同じホストの 8787 番 — 手元で両方立てている時

トンネルの URL は立てるたびに変わるので、**普段は 1 で足りる**。自分のドメインを使って固定した場合だけ 2 に焼く。

## 影響

- **手元の機械が起きている間だけ繋がる。** 落とせばそこで対戦が消えるが、部屋はもともとメモリにしか無い（ADR-0009）ので、失うものは増えない。
- **画面に掛けた鍵はサーバに掛かっていない。** 配った画面には Basic 認証を掛けられるが（`proxy.ts`）、サーバは WebSocket を受けるだけの口で、そこに挟む場所が無い。トンネルの URL を知っている人は自分で書いた画面から繋げるし、繋げばカードのテキストは渡る。**動かして確かめるためのものであって、公開する形ではない。**
- サーバを本当にどこかへ置くことにしても、画面の側は変わらない。要るのは `wss` で届くことだけで、`VITE_SERVER_URL` を差し替えれば済む。そのときは、カードが非公開である以上（ADR-0002）**置き場でビルドさせず、束ねたものだけを渡す**形になる。
- リポジトリのルートに配る設定が増える（`vercel.json` / `proxy.ts` / `tsconfig.deploy.json`）。**どれもカードを名指ししない。**
- トンネルを張る道具はこのリポジトリの外にある。`pnpm` からは呼ばず、手順として README に書くだけにする。
