# 行った手の行は、コストを支払った後、カードを行き先へ動かした時点で積む

決定日: 2026-10-21。Issue #158。開発者と決定した。

## 背景

この文書を書いた時点では、行った手の行（`行動した`）は `applyLegalAction` が行動を適用する前に積んでいた。名指しを残すかは「そのできごとの前後どちらかで見えていたか」で決まる（`log.ts` の `record`、#129）が、渡っていたのは適用前の盤面だけだった。そのため、手札からエネルギーゾーン・スクエアへ動かした手は、置いた後は誰からも見えているのに、相手のログでは名前が落ちていた。トラップの発動・廃棄、「勇気」の起動も同じ理由で落ちていた。

あわせて、ログの順序が「プレイ → コストの支払い」になっていた。総合ルールは「使用コストを支払って、自分の手札にあるカードをプレイできます」（第3部 第8章 2-1）と書いており、エンジンの中でもコストを支払ってからカードを動かしている。開発者は、ログもコストの支払いが先に並ぶのが正しいと判断した。プレイヤーが操作する順番（プレイするカードを選び、次にコストを選ぶ）は変えない。

## 決めたこと

行った手の行は、行動そのもの（`placeEnergy`・`playCard` など）が積む。積むのは、その行動のコストを支払った後、カードを行き先へ動かした直後で、その手が起こしたこと（解決・誘発）より前である。名指しを残すかは、動かす前と動かした後の見え方で決める。`record` が末尾に足すだけの関数であることは変えない。

動かした先が隠れたままの手（`トラップとしてプレイする`）は、動かした後も相手から見えないので、名指しされないままになる。見え方の規則（`perspective.ts` の `seesFace`）は変えない。

## 検討した選択肢

- **行動の中で、カードを動かした時点に積む。** 位置も見え方も、カードが動いた瞬間の 1 か所で決まる。コストの支払いが手の行より前に並ぶことは、上の理由で正しい順序である。選択を待つ間に画面へ送る盤面（ADR-0008 のやり直しで、答えが尽きた時点の盤面）にも、カードを動かした後であれば手の行が載っている。積む場所が行動ごとに分かれることは受け入れる。この案を採る。
- **適用した後に積み、適用の途中で積まれた行を手の行の後ろへ並べ直す。** 1 か所で済むが、選択を待つ間の盤面には手の行が無くなる。答えが尽きた時点で例外で抜けるためで、それを補うには選択に渡す盤面へ手の行を差し込む手当てが別に要る。適用の途中でログの長さから取る値（`startedAt`・`metAt`）も、最終的なログの位置と 1 つずれる。採らない。
- **適用前に積み、行き先へ動かしただけの仮の盤面で見え方を読む。** 位置は変わらないが、手の種類ごとの行き先を行動の実装とは別にもう 1 度書くことになり、両者がずれうる。コストの順序の違和感も残る。採らない。
- **行動を 2 度適用して、先に適用後の盤面を得る。** 選択の答えは 1 つずつ消費される（`protocol.ts` の `applyWithAnswers`）ので、2 度目は違う答えを受け取る。採らない。
- **適用後に、積んだ行の見え方を書き換える。** `record` が末尾に足すだけである性質を崩す。採らない。

## 影響

コストを支払う手（カードのプレイ、プラン、トラップの発動、起動型能力・「勇気」の起動、追加コストのある移動）では、ログの並びが「コストの支払い → 行った手」に変わる。エネルギー・スクエアに出したユニット・プレイしたストラテジー（リゾルブゾーンは表向き、総合ルール 第2部 第21章 12-2）・発動したトラップ・廃棄したトラップ・起動した「勇気」は、相手のログでも名指しされる。

`legalActions` は候補を試すのに行動を直接呼ぶので、試した盤面にも手の行が積まれる。試した盤面は捨てるので、ログには残らない。

対戦の記録の打ち直し（ADR-0018）は、記録した行動と答えを適用し直すので、作り直した対戦のログは新しい並びになる。選択を求める順番は変えていないので、同じところへ進む。通信の形は変えない。

## 実装

- 行った手を積む関数: `log.ts` の `recordAction`
