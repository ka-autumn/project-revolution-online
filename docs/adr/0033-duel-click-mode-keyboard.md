# クリックモードの盤面とダイアログを、キーボードで操作できるようにする

クリックモードでは、盤面のカードやスクエアをキーボードで押せず、キーボードで操作する人はボタンモードを使う前提になっていた（Issue #251）。ADR-0031 で行き先とダイアログを足し、パネルのボタンがほぼ無くなったので、**クリックモードそのものを、マウスなしで最後まで操作できるようにする**。

**変えるのは、クリックモードの操作の手段だけである。** 何が押せるか・何を送るかは ADR-0031 のまま（ADR-0010）。通信の形・サーバ・ルールの判断は変えない。

**ボタンモードは変えない。** 盤面の区画・矢印キー・DOM の順・スクエアの読み上げは、クリックモードのときだけ掛ける（`DuelElementProps.clickMode`）。「クリックモードか」は、操作のしかたそのもので決める。押せるものがあるか（`picking` の有無）では決めない——相手の番・演出中・切断中も、クリックモードならキーボードの配線は掛かったままにする。ボタンモードの主な利用者はキーボードで打つ人なので、手のボタンまでの Tab の数や止まる先を変えない。

**モック**: [`docs/mocks/duel/`](../mocks/duel/index.html)（押せる山札と、そこにキーボードの手がある状態）。ADR・モック・実装が食い違っていたときの扱いは、ADR-0032 に書いてある。

## 盤面のたどり方（クリックモード）

Tab は**区画ごとに 1 回**だけ止まり、区画の中は矢印キーで移る（ロービング tabindex: 区画の中で `tabIndex=0` を持つのは 1 つだけ。残りは `-1`）。盤面のカードは数が多く、全部を Tab の止まる先にすると、押せるものにたどり着くまでの回数が多すぎるため。

| 順 | 区画 | 中身 |
| --- | --- | --- |
| 1 | 自分の手札 | |
| 2 | 自分の置き場 | エネルギー・スマッシュ・捨札・リムーブ・トラップゾーン・山札 |
| 3 | バトルスペース | 3×3 のスクエア |
| 4 | 相手の置き場 | リムーブ・捨札・スマッシュ・エネルギー・山札・トラップ |
| 5 | 左の列（プレイヤーの枠・操作パネル） | 今のまま、ボタンごとに止まる（パートナーのカードも通常の止まる先） |

- **自分の側から始める。** いちばん多く押すのは手札と自分の置き場なので、盤面に入って最初の Tab でそこに止まるようにする。相手の置き場を押すことは少ない（束を開いて見るくらい）ので、最後に回す。
- DOM の順を、盤面 → 左の列 → 右の列にする（`.duel__left` の `order: -1` と `gridArea` で、画面の位置は変わらない）。盤面の中も、自分の手札 → 自分の置き場 → バトルスペース → 相手の置き場の順に置く（盤面の入れ物 `.duel__center` の行と、置き場の `gridArea` は明示してあるので、画面の位置は変わらない）。Tab の順と読み上げの順は、画面の左上から読む順ではなく、この表の順になる。
- 区画の中の移り方: 矢印キーで 1 つずつ。端で止まり、反対の端へは回らない。Home・End で端へ飛ぶ。**バトルスペースだけは、画面で見える向きのまま上下左右へ**移る（相手の側を点対称に描いていても、矢印は画面の向きに従う）。
- **Tab で区画に入ったときの位置は、いつも区画の中の押せるものの先頭**（押せるものが無ければ区画の先頭）。区画の中で矢印キーで移ったあとも、手が区画から出たら、入口を先頭へ置き直す。
- スクエアは 1 つを 1 つの止まる先にする（ユニットごとには止まらない）。フォーカスしたスクエアにユニットがいれば、右の列にそのユニットの詳細を出す。読み上げには、スクエアの名前・そこにいるユニットの名前・押せるかどうかを合わせて出す。
- 束（捨札・リムーブ）・自分のトラップゾーン・山札・カード・スクエアは、Enter・Space で押す。押すと、**押せるものについては**、マウスで押したときと同じ結果になる。

### 止まる先にしないもの・例外

- **止まる先に加えない**: バンク・誘発した能力（文字の一覧で、押せるものではない。能力の候補はダイアログで選ばせる）、相手の手札（裏向き）、押せない裏向きのカード。
- **操作ログとカードの詳細（右の列）**: 自分では止まる先に加えない。ただし、Chrome は溢れてスクロールする要素を、中に止まる先が無ければ Tab の止まる先にする。長いログ・長いカードのテキストをキーボードで読むのに要るので、**これは外さない**（右の列の例外）。ダイアログが開いている間は、ログだけを `inert` にする。盤面の中のスクロールする一覧（バンク・誘発した能力、カードの文字欄）は、溢れるとブラウザが止まる先にするので、`tabindex=-1` で外す。
- **盤面の中のボタン**: 「この行動をやめる」（コストなど中から選ぶ置き場の札）は、区画の中にあるが、ボタンのままの別の止まる先として残す。区画の「1 つだけ」の例外である。

### 押せない・押せる

- 押せないカード・スクエアを押しても、**何も送らず、選びかけも外さない**。選びかけを外すのは Esc だけ。マウスは、押せないところを押すと選びかけが外れる（ADR-0031）が、Enter・Space で押せないものを押すのは、押したというより、手が置いてあるものに触れただけなので、何も起こさない。
- 読み上げで「（押せません）」と言うのは、**押せるものが盤面に 1 つ以上ある間だけ**、表向きのカードとスクエアに。何も押せない間（相手の番など）は、すべてに付けると耳障りになる。**裏向きのカードには付けない**（数が多く、押せない裏向きのカードは止まる先にもならない）。押せるカードは「（押せます）」、選んでいるカードは「（選択中）」のまま。
- 押せる裏向きのカード（プランのコストのスマッシュなど）も、Tab・矢印で止まり、Enter・Space で押せる。

### スクエアでの Enter・Space

- 光っている行き先なら、そこへ手を行う。
- 押せるユニットがちょうど 1 体なら、そのユニットを押したことになる。
- 押せるユニットが **2 体以上**いるとき（バトル中に支配者の異なる 2 体が同じスクエアにいて、どちらも候補のとき）は、どれを押すのかをスクエアだけでは決められない。**スクエアの中のユニットへフォーカスが入り**、左右の矢印でユニットを移り、Enter・Space で押す。Esc でスクエアへ戻る。
- **光っている行き先に、押せるユニットがいることは無い。**
  - 行える手の場面（移動）: 味方のいるエリアへ味方は移動できない。
  - 効果で選ぶ場面: 1 回の選択の候補は、効果が組む 1 つの一覧である。現在のカードは、`choose`・`chooseAtMostOne` のどの呼び出しも 1 種類の候補（ユニット・手札や捨札のカード・空きスクエア）の一覧を渡しており、カードとスクエアを混ぜる効果は無い（`private/cards` の試験デッキ F・G の呼び出しをすべて読んだ）。混ぜる効果が現れたら、このときの動き（光っているスクエアを優先する、今の `activate`）を見直す。

## 手の置き場所の覚え方（描き直しをまたぐ）

画面は描き直すたびに要素が全部作り直される。**何が同じなら同じものとみなすか**を、ここで 1 か所に決める。並びの位置（何番目か）や、変わりうる値（見出しの枚数）では覚えない。前に並ぶものの数が変わると、別の要素を指してしまう。

| 対象 | 同じとみなす印 |
| --- | --- |
| カード | 識別子（`data-card-id`） |
| スクエア | 画面での位置（行・列） |
| 束・山札・トラップゾーン | 持ち主と置き場の名前（例: 自分の捨札、自分の山札） |
| 押せる裏向きのカード | 置き場所（`WireCardPosition`） |
| 2 体のユニットがいるスクエアの中のユニット | スクエアの位置に加えて、ユニットの識別子。同じユニットが同じスクエアでまだ押せるなら、そこへ戻す。いなければスクエアへ |
| パートナーのカード | 識別子 |
| ボタン（左の列・盤面の中） | 文字 |
| ダイアログの中のボタン | 文字 |
| ダイアログの中の識別子のあるカード | 識別子 |
| ダイアログの中の能力の札・裏向きの候補 | 識別子の無い止まる先のうちの何番目か |
| ダイアログそのもの | `index.ts` が、開いた単位ごとに付ける印。下の「ダイアログ」 |

- 描き直したあとは、同じ印の要素へ手を戻す。もとの要素が無くなっていたら、区画の止まる先なら**同じ区画の入口へ**、区画に入らないもの（パートナー・ボタン）なら**押せるものの先頭へ**（無ければ盤面の入れ物 `tabIndex=-1`）。
- 左の列にも覚える。パートナーのカードは識別子で覚えて戻し、ダイアログの開いたもとにもする（区画には入れない）。左の列と盤面の中のボタンは、同じ文字のボタンへ戻す。
- **手を置き直すのは、直前の操作がキーボードのときだけ**。マウスで操作している人に、描き直しのたびに `focus()` し直すと、フォーカスに連動して差し替わる右の列の詳細が、乗せていないカードに替わる。窓全体で、最後の入力が `keydown` か `pointerdown` かを覚える。ポインタのときは、描き直したあとにも、ダイアログが閉じたあとにも、盤面へ手を置かない。ダイアログを開いたときに中へ移すのは、どちらでも変わらない。
- `focus()` は `preventScroll` 付きで呼ぶ。手札の扇は画面の端から半分だけ出ているので、既定のままだと盤面の入れ物（`.duel`）がスクロールして、盤面全体が動く。Tab で手札に止まったときはブラウザが自分でスクロールさせるので、`.duel` を `overflow: clip` にして、スクロールそのものが起きないようにする（`hidden` はフォーカスによるスクロールを止めない）。

## ダイアログ（行える手の選択・カードの一覧・能力の一覧・捨札／リムーブを見る一覧）

- **開いたときの 1 回だけ**、フォーカスを中へ移す。描き直しても、中で選んでいたフォーカスは同じ要素に残り、先頭へ戻らない。
- **同じダイアログかどうかは、状態の側から渡す印で見分ける**。見出しやボタンの文字では見分けない（続けて届いた選択は、文字が同じになりうる）。
  - 効果で選ぶ一覧: 届いた選択（`stage.choice`）が替わるたびに別のダイアログ。選びかけの付け外しや相手の繋がりの描き直しは、同じ一覧。
  - 手を聞くダイアログ: 選びかけ（`selection`）が替わる（別のカードを選ぶ・行き先を絞る）たびに別のダイアログ。
  - 見る一覧: 開くたびに別の一覧。盤面が届いて枚数が変わっても、同じ一覧の描き直しで、フォーカスはその場所に残る。
  - 効果で選ぶ一覧の箱は、`aria-describedby` で問いの文と結ぶ。続けて別の問いが届くと、読み上げで伝わる。
- **重なったときは、一番上の層だけを操作できる**。「見る」一覧を開いたまま効果で選ぶ一覧が届くと、下の「見る」一覧は開いたまま残る。下の層も含めて、一番上の層と右の列以外に `inert` を付ける（盤面・左の列・演出の層、右の列の中の操作ログ）。右の列（カードの詳細）は、一覧のカードに乗せて詳細を読みながら選べるように、`inert` にしない（ADR-0027）。上の層が閉じたら、フォーカスは下の層の中へ戻す（下の層を開いたもととして扱う）。
- **Esc は、ダイアログが開いている間、手がどこにあっても一番上の層が受ける**（右の列にあっても、`body` に落ちていても）。窓全体の Esc は、開いている層があればその動きに回し、無ければこれまでどおり選びかけを外す。動きはダイアログごとに、押す先のあるボタンと同じにする。
  - 行える手を聞くダイアログ: 「キャンセル」と同じ。
  - 捨札・リムーブを見る一覧: 「閉じる」と同じ。
  - 効果で選ぶ一覧: **選びかけの候補を外すだけ**（選びかけが無ければ何もしない）。行動そのものを取り消す「この行動をやめる」は、Esc 1 回で動かさない。押し間違えたときの代償が大きいため。
- **キーリピートの Enter・Space は受けない**。カードで Enter を押しっぱなしにすると、keydown の中でダイアログが開いて手が最初のボタンへ移り、続くリピートがそのボタンに届いて手が送られる。ダイアログの層と盤面の側（捕捉段）の両方で捨てる。Space は keyup でボタンが押されるので、盤面で Enter・Space を受けたあと、同じキーの keyup を 1 回捨てる。
- **送ったあと**（ボタンを押せなくする前）に、フォーカスをダイアログの箱（`tabIndex=-1`）へ移す。押せなくしたボタンからフォーカスが外れて `body` へ落ちるのを防ぎ、「通信中…」（`role="status"`）が読み上げられる。返事が届くと、ダイアログは閉じる（下）。この間の二重押しの扱いは Issue #253 に任せ、ここでは決めない。

### 閉じたあとのフォーカスの戻し先

- **「キャンセル」「閉じる」・Esc で閉じたときは、開いたもとの要素へ戻す。** 開いたもとは、ダイアログが開く直前にフォーカスのあった要素（盤面の要素、パートナーのカード、盤面や左の列のボタン、下の層）。もとが無くなっていたら、押せるものの先頭へ。
- **手を送って閉じたとき**（効果で選ぶ一覧の「この行動をやめる」も、取り消しを送るのでこちら）は、いま押せるもののうち、区画の順（上の表の順。自分の手札が先）で先頭のものへ移す。押せるものが無ければ盤面の入れ物へ。手を送ると盤面が変わり（手札から場へ出す、捨札へ行く）、もとの場所に意味が無いことが多い。フォーカスを追いかけて動かすと、次に押すものから遠ざかる。
- 層が替わって閉じたとき（手を聞くダイアログを送って、効果で選ぶ一覧が開くなど）は、閉じた層の開いたもとを、新しい層が引き継ぐ。

## 見た目

フォーカスの位置は、ブラウザ標準の `:focus-visible` の枠で見える。ただし、押せる山札は枠そのものを点線で光らせているので、`:focus-visible` のときだけ別の枠（実線・外側）を重ねる。カード・スクエア・トラップゾーンは、光らせ方が枠と別の場所なので、そのまま見える。手札は、フォーカスすると全体が浮き上がる（ADR-0027 の `:focus-within`）。

## やらないこと

- デッキ構築の確認ダイアログ（ADR-0028）。対戦画面の流れではない。毎回フォーカスを置き直す・外へ出られる、という同じ癖があるので、別に扱う。
- 手を送ったあとの二重押しを防ぐ仕組み（Issue #253）。
- 描画コードの自動テスト基盤（Issue #252）。矢印キーの移り先の計算だけは DOM を使わない関数にして、単体テストで確かめた（`board-keyboard.test.ts`）。
- ボタンモードを残すかどうかの判断。クリックモードがキーボードで操作できるようになったので、改めて決める。

## 影響

- `render.ts` が、区画の目印（`data-region`）・フォーカスの印（`data-focus-key`）・スクエアの位置・押せないことの読み上げを付ける。キーボードの配線は `board-keyboard.ts`、ダイアログと描き直しのフォーカスは `dialog-focus.ts`。
- クリックモードでは、盤面の DOM の順が変わる（読み上げの順が変わる）。
- 窓全体の Esc で選びかけを外す処理は、ダイアログが開いている間は、一番上の層の動きに替わる。
