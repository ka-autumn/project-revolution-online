# クリックモードの盤面とダイアログを、キーボードで操作できるようにする

クリックモードでは、盤面のカードやスクエアをキーボードで押せず、キーボードで操作する人はボタンモードを使う前提になっていた（Issue #251）。ADR-0031 で行き先とダイアログを足し、パネルのボタンがほぼ無くなったので、**クリックモードそのものを、マウスなしで最後まで操作できるようにする**。

**変えるのは、操作の手段だけである。** 何が押せるか・何を送るかは ADR-0031 のまま（ADR-0010）。通信の形・サーバ・ルールの判断・ボタンモードは変えない。

## 盤面のたどり方

Tab は**区画ごとに 1 回**だけ止まり、区画の中は矢印キーで移る（ロービング tabindex: 区画の中で `tabIndex=0` を持つのは 1 つだけ。残りは `-1`）。盤面のカードは数が多く、全部を Tab の止まる先にすると、押せるものにたどり着くまでの回数が多すぎるため。

| 順 | 区画 | 中身 |
| --- | --- | --- |
| 1 | 相手の置き場 | リムーブ・捨札・スマッシュ・エネルギー・山札・トラップ |
| 2 | バトルスペース | 3×3 のスクエア |
| 3 | 自分の置き場 | エネルギー・スマッシュ・捨札・リムーブ・トラップゾーン・山札 |
| 4 | 自分の手札 | |
| 5 | 左の列（プレイヤーの枠・操作パネル） | 今のまま、ボタンごとに止まる（パートナーのカードも通常の止まる先） |

- **止まる先にしないもの**: バンク・誘発した能力（文字の一覧で、押せるものではない。能力の候補はダイアログで選ばせる）、操作ログ、カードの詳細（右の列）、相手の手札（裏向き）。右の列は、盤面のカードやスクエアにフォーカスを移すと中身が差し替わる（ADR-0027 の配線）。
- DOM の順を、盤面 → 左の列 → 右の列にする。画面の位置は `style.css` の `order` と `gridArea` で決めているので、見た目は変わらない。Tab の順と読み上げの順が、画面の左上から読む順ではなく、この表の順になる。
- 区画の中の移り方: 矢印キーで 1 つずつ。端で止まり、反対の端へは回らない。Home・End で端へ飛ぶ。**バトルスペースだけは、画面で見える向きのまま上下左右へ**移る（相手の側を点対称に描いていても、矢印は画面の向きに従う）。
- Tab で区画に入ったときの位置は、区画の中の**押せるものの先頭**。押せるものが無ければ区画の先頭。
- スクエアは 1 つを 1 つの止まる先にする（ユニットごとには止まらない）。フォーカスしたスクエアにユニットがいれば、右の列にそのユニットの詳細を出す。読み上げには、スクエアの名前・そこにいるユニットの名前・押せるかどうかを合わせて出す。
- 束（捨札・リムーブ）・自分のトラップゾーン・山札は、これまでどおり Enter・Space で押す。カードとスクエアも Enter・Space で押す。押すと、マウスで押したときと同じ結果になる。

### スクエアでの Enter・Space

- 光っている行き先なら、そこへ手を行う。
- 押せるユニットがちょうど 1 体なら、そのユニットを押したことになる。
- 押せるユニットが **2 体以上**いるとき（バトル中に支配者の異なる 2 体が同じスクエアにいて、どちらも候補のとき）は、どれを押すのかをスクエアだけでは決められない。**スクエアの中のユニットへフォーカスが入り**、左右の矢印でユニットを移り、Enter・Space で押す。Esc でスクエアへ戻る。
- 光っている行き先に押せるユニットがいることは無い（味方のいるエリアへ味方は移動できない）ので、この 2 つは重ならない。

## 押せない・押せる

- 押せないカード・スクエアを押しても、何も送らない（押せるもの以外にはハンドラを付けない）。
- 読み上げで「（押せません）」と言うのは、**押せるものが盤面に 1 つ以上ある間だけ**。何も押せない間（相手の番など）は、すべてに付けると耳障りになる。押せるカードは「（押せます）」、選んでいるカードは「（選択中）」のまま。
- 押せる裏向きのカード（プランのコストのスマッシュなど）も、Tab・矢印で止まり、Enter・Space で押せる。

## ダイアログ（行える手の選択・カードの一覧・能力の一覧・捨札／リムーブを見る一覧）

- **開いたときの 1 回だけ**、フォーカスを中へ移す。描き直しても、中で選んでいたフォーカスは同じ位置の要素に残り、先頭へ戻らない。同じダイアログかどうかは、種類・見出し・ボタンの名前で見分ける。
- **開いている間は、右の列以外に `inert` を付ける**（盤面・左の列・演出の層、右の列の中の操作ログ）。フォーカスが外へ出ず、外のものが読み上げにも出ない。右の列（カードの詳細）は、一覧のカードに乗せて詳細を読みながら選べるように、`inert` にしない（ADR-0027）。
- **Esc は、ダイアログ自身が受ける**（窓全体の Esc＝選びかけを外す、へは渡さない。ダイアログが開いていない間の Esc は、これまでどおり窓全体が受ける）。動きはダイアログごとに、押す先のあるボタンと同じにする。
  - 行える手を聞くダイアログ: 「キャンセル」と同じ。
  - 捨札・リムーブを見る一覧: 「閉じる」と同じ。
  - 効果で選ぶ一覧: **選びかけの候補を外すだけ**（選びかけが無ければ何もしない）。行動そのものを取り消す「この行動をやめる」は、Esc 1 回で動かさない。押し間違えたときの代償が大きいため。
- **送ったあと**（ボタンを押せなくする前）に、フォーカスをダイアログの箱（`tabIndex=-1`）へ移す。押せなくしたボタンからフォーカスが外れて `body` へ落ちるのを防ぎ、「通信中…」（`role="status"`）が読み上げられる。返事が届くと、ダイアログは閉じる（下）。この間の二重押しの扱いは Issue #253 に任せ、ここでは決めない。

### 閉じたあとのフォーカスの戻し先

- **「キャンセル」「閉じる」で閉じたときは、開いたもとの要素へ戻す。** 開いたもとは、ダイアログが開く直前にフォーカスのあった盤面の要素（カードの識別子・スクエアの位置など）。描き直しで要素は作り直されるので、識別子で引き直す。
- **手を送って閉じたとき、またはもとの要素が無くなっていたときは、いま押せるもののうち、区画の順で先頭のものへ**移す。押せるものが無ければ盤面の入れ物（`tabIndex=-1`）へ移す。手を送ると盤面が変わり（手札から場へ出す、捨札へ行く）、もとの場所に意味が無いことが多い。フォーカスを追いかけて動かすと、次に押すものから遠ざかる。

## ダイアログが開いていないときの描き直し

盤面の要素は描き直すたびに全部作り直されるので、フォーカスのあった要素は同じ識別子の要素へ戻す。要素が無くなっていたら、同じ区画の入口へ戻す。盤面のフォーカスがあるときに相手の手で盤面が届いても、Tab で先頭からたどり直さずに済む。

## 見た目

フォーカスの位置は、ブラウザ標準の `:focus-visible` の枠で見える。ただし、押せる山札は枠そのものを点線で光らせているので、`:focus-visible` のときだけ別の枠（実線・外側）を重ねる。カード・スクエア・トラップゾーンは、光らせ方が枠と別の場所なので、そのまま見える。

## やらないこと

- デッキ構築の確認ダイアログ（ADR-0028）。対戦画面の流れではない。毎回フォーカスを置き直す・外へ出られる、という同じ癖があるので、別に扱う。
- 手を送ったあとの二重押しを防ぐ仕組み（Issue #253）。
- 描画コードの自動テスト基盤（Issue #252）。矢印キーの移り先の計算だけは DOM を使わない関数にして、単体テストで確かめた（`board-keyboard.test.ts`）。
- ボタンモード。ボタンモードを残すかどうかは、クリックモードがキーボードで操作できるようになったので、改めて決める。

## 影響

- `render.ts` が、区画の目印（`data-region`）・スクエアの位置・押せないことの読み上げを付ける。キーボードの配線は `board-keyboard.ts`、ダイアログと描き直しのフォーカスは `dialog-focus.ts`。
- 盤面の DOM の順が変わる（読み上げの順が変わる）。`.duel__left` に `order: -1` を付けている。
- Esc を窓全体で受けていた選びかけの解除は、ダイアログが開いている間は届かなくなる。ダイアログの Esc が同じ「選んでいない状態に戻る」を行うので、結果は変わらない。
