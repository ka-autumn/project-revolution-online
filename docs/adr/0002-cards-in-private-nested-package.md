# カード実装をネストした非公開パッケージに置く

カードの名前・能力テキスト・作品名は第三者の著作物であるため、公開リポジトリには置かない。`packages/cards/` を `.gitignore` し、そのディレクトリ自体を独立した非公開の git リポジトリとする。公開リポジトリにはルールエンジンと「カードを記述するための API」だけが入る。

作業ツリー上はパスが揃っているため、定義ジャンプもリファクタリングも単一リポジトリと変わらない。支払うコストはコミットが 2 回になることだけである。

## 検討した選択肢

- **カード実装も公開する** — 開発は最も楽だが、カードの内容を形を変えて公開することになる。
- **完全に別の場所の private リポジトリ** — 境界は最も厳格だが、API が激しく動く初期にバージョン整合の手間が毎回発生する。ネストなら作業ツリー上で一体なのでこれが起きない。

## 影響

- **副次的な効果として、エンジンとカードの間に規律に依存しない壁が立つ。** 公開 API で書けないカードは書けないため、特定カードのための特殊分岐がエンジン本体に漏れる典型的な崩れ方を、構造的に防げる。
- エンジンのテストは実カードではなく架空のテストカードで書くことになる。これは制約ではなく利益と位置づける。
- 公開リポジトリだけを clone した第三者は、ゲームを動かせない。テストは通る。README に明記すること。
