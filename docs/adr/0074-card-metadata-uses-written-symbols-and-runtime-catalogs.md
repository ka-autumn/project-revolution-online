# 作品名とメーカーシンボルをカード表記で渡し、名前とロゴは実行時の対応表で供給する

## 背景

この文書を記録した時点では、メーカーシンボルはカードのルール上の値として存在したが、通信に含まれなかった。作品名とエキスパンションコードも画面へ届かず、構築画面の分類と対戦画面のロゴを同じ入力から表示できなかった。

## 決定事項

- 作品名の並びとルール上のメーカーシンボルを、プールと対戦で共通のカード表記に含める。印刷された記号が異なるカードだけ、その並びを別に指定する。ブロックを別のルール上の項目として重複させず、作品名からも推定しない。
- 記号から名前・読み仮名・ロゴを参照する対応表を、サーバ起動時に非公開側から受け取る。作品名の読み仮名とエキスパンションコードも同じ供給元で管理する。実在する名前・記号・対応・画像を公開側に記録しない。
- 分類の対応表は接続後、ロビーや対戦の表示より先に渡す。デッキ構築を提供しない起動方法でも、対戦の表示に使うため供給する。再接続時にも渡す。
- カード面と詳細は印刷された記号を使用する。ブロックの絞り込みはルール上の記号を使用し、選択肢は名前の読み仮名で五十音順に並べる。同じ項目内の複数選択はOR、別の項目間はANDとする。
- 実カードには作品名とメーカーシンボルがある。非公開側の分類対応表を指定した場合、入力漏れと記号の対応漏れを起動前に検出する。エンジンの架空カードでは、ルールのテストに不要な表記を省略できる。
- 作品名は原本一覧の略称を正式な作品名へ統一する。再録の識別子やカードの同一性は変更しない。主なブロックの自動ラベルは今回追加しない。
- ロゴ未提供時や読み込み失敗時は、半角の略号を入れた丸を表示する。画像は非公開側で指定したファイルだけをサーバが配信し、ローカルパスを通信に含めない。

## 検討した選択肢

- 作品名と印刷された記号をサーバ側のカードキー別の表で保持する方式も検討した。構築・対戦・ログの各経路で添付が必要になるため、カード表記で共通に供給する方式を採用した。
- メーカーを並びで渡す方式も検討した。今回は記号をキーにした表とし、表示順は配列順に依存せず読み仮名から決定する。

## 互換性と反映

保存デッキ・共有レシピ・対戦の記録の形式と、ゲーム上のメーカー判定は変更しない。記録の再生でも、現在のカード定義から同じ表記を供給する。新しい画面は旧サーバから項目が届かなくても既存の一覧・対戦を維持するが、新しい分類・表示は利用できない。旧画面は追加の分類メッセージを無視する。画面とサーバは同じ変更の組として、サーバを先に反映し、その後に画面を反映する。本番反映の承認と進行中の対戦の確認は別途必要となる。

## 実装

- カードの `works`・`makerSymbols`・`printedMakerSymbols` を `WireCardFace` に含める。
- 起動時の `makers`・`workReadings`・`expansions[].code` を `カード分類` メッセージで供給し、画面は場面を移動しても保持する。
- メーカーの `logo` はサーバ側の画像ファイルのパスとし、通信時には `/maker-logos/<記号>` に置き換える。PNG・WebP・SVGを配信する。
