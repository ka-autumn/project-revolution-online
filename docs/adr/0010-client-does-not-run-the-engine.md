# クライアントはルールエンジンを動かさない

クライアントは受け取った盤面を描き、選んだものをサーバへ送るだけにする。ルールの判断はいっさい持たない。**行える手はサーバが盤面と一緒に送り**、盤面に載るカードは番号ではなく**表記のデータ**（名前・レベル・色・種別・ＢＰ・ＳＰ・アイコン・属性）にする。

ADR-0004 は「クライアントも同じルールエンジンを、自分視点の盤面に対して動かす」と決めていたが、これは成り立たない。

**合法手を出せない。** `legalActions` は完全な盤面（`DuelState`）を要求する。クライアントが持てるのは射影（`DuelPerspective`）で、ゾーンは見えているかどうかに分かれ、能力は中身を持たず、相手の権利は落ちている。射影から完全な盤面を作れるようにするのは、**クライアントに持たせてはならないものを持たせること**にほかならない（同 ADR）。

**カードを復元できない。** 番号からカードを引くには、カードの実装が要る。それは非公開のパッケージにあり（ADR-0002）、`packages/client` は公開されるので依存できない。

一方、失うものは小さい。入力の妥当性は、サーバが行える手を送れば**それ以上に確実**に決まる。クライアントが同じ判断を持てば、二重に持つことになる。先読み表示は、最初の完走（#17）に要らない。

## 影響

- **ADR-0004 のうち、クライアントがエンジンを動かすという部分を取り消す。** サーバだけが完全な盤面を持ち、視点ごとに射影して送るという本体は変わらない。
- 通信に載せるカードは番号（`CardNumber`）から表記のデータになる。表記はどれもただの値なので、**エンジンが自分で書き出せる**。カードの実装から番号の付け方を渡してもらう必要がなくなる。能力は関数なので落ちるが、表示には要らない。
- クライアントは**公開リポジトリだけで作れて動かせる**。非公開のカード実装が要るのは、デッキを渡してサーバを立てるところだけになる。
- UI は打てる手だけを並べる。打てない手を描いて断られる、という経路が無くなる。
- 先読み表示（候補手の結果を先に見せる）は行わない。必要になったら、その時に何を見せたいかから決め直す。
