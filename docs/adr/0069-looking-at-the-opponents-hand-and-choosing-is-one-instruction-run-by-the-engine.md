# 相手の手札を見て選ぶ効果は、エンジンが候補を作成し、選んだカードの処置まで 1 つの命令で行う

決定日: 2026-11-11。開発者と決定した（#335）。

この文書は設計として先に書いた。実装した後で、実装で決定した名前を末尾の「実装」の節に追記する。

## 背景

EB1.0 には、能力の支配者が相手の手札を見て、その中から選ぶテキストが 2 枚ある。

- EB1.0 の 055 は、条件に合うカードを 1 枚まで選んで捨てる
  （架空の例: 「相手の手札を見て『機械』のユニットを１枚まで選び、捨てる」）。
- EB1.0 の 075 は、1 枚選んで捨てる（架空の例: 「相手の手札を見て１枚選び、捨てる」）。

相手の手札は非公開情報で（総合ルール 第2部 第23章 2-1）、効果からは取得できないことを型で保証している
（ADR-0004）。「相手の手札を見る」命令は、見たカードを効果に返さない（ADR-0041）。相手が自分の手札から
選んで捨てる命令も、候補と選ばれたカードを効果に返さない（ADR-0052）。どちらの ADR も、支配者が見て選ぶ形を、
別の決定として残していた。

後のエキスパンションには、同じ系統が 10 行ある。選んで捨てる形が 7 行、ゲームから取り除く形が 2 行、
山札の 1 番上に裏向きで置く形が 1 行である。絞り込みを持つのは EB1.0 の 055 だけである。ほかに、相手の手札にある
特定の種別のカードの枚数を効果が使う形が 1 行ある。

## 決定事項

### 効果の命令

- **相手の手札のカードは、見た後も効果に渡さない。** ADR-0004 の保証は変更せず、例外も追加しない。
- **「相手の手札を見て、絞り込みに合うカードを N 枚（まで）選び、処置する」を、1 つの命令として追加する。**
  候補はエンジンが作成し、選ばせ、処置まで行う。ADR-0052 の「候補を効果に見せられない形」と同じ分け方で、
  選ぶ人が支配者になったものである。
- **命令は、効果に何も返さない。** 選ばれたカードを効果が使うテキストは、この系統には無い。
- **絞り込みは、条件の並びとして値で渡す。** 並べた条件をすべて満たすカードが選べる。条件の種類は「種別」と
  「属性」から始める。空の並びは、絞り込まないことを表す。関数にはしない。関数にすると、カードの側の関数が
  相手の手札のカードを受け取ることになるためである。軸が増える時は、条件の種類を 1 つ追加する。
- **処置は種類で持ち、今回は「捨てる」だけを追加する。** 「ゲームから取り除く」「山札の 1 番上に裏向きで置く」は、
  そのカードを実装する時に、種類を 1 つ追加する。

### 選択の要求

- **選択の要求は 1 回で、支配者にだけ届く。** 見せる一覧（ADR-0041）は相手の手札の全部で、絞り込みに合うカード
  だけが候補になる。「見る」確認と「選ぶ」選択を、2 回に分けない。
- **選べるカードが無くても、一覧は届ける。** テキストは見てから選ぶので、見ることは絞り込みの結果によらず起きる。
  「N 枚まで」の形では、選ばないことを候補に含める。候補になるカードが 0 枚なら、確認だけの選択になる。
- **候補が 1 つで断れない時も、聞く。** 聞かずに進めると、一覧が届かない。ADR-0041 の確認の選択と同じ扱いである。
- **相手の手札が 0 枚なら、選択を出さず、ログだけを積む**（ADR-0041 と同じ）。
- **選択の目的を 1 つ追加する。** 画面は、相手の手札から選んでいることを見出しで伝える。文言は `docs/screens/` の
  仕様書で決定する。
- **見た後は、戻せず、取り消せない**（ADR-0041 の決まりがそのままかかる）。

### ログ

- **見たことをログに 1 件積み、見たカードの名前を 2 人に同じ内容で出力する**（ADR-0041 と同じ）。
- **捨てたカードの名前も出力する。** 捨札に表向きで置かれ、2 人に見えるためである。

### CPU

- **CPU が支配者の時は、候補のうち基礎点が最も高いカードを選ぶ。** 「N 枚まで」の形でも、候補があれば必ず選ぶ。
  CPU は人の画面と同じ範囲の情報を受け取る（ADR-0060）。選択の要求に含まれる一覧を参照して選ぶのは、
  人と同じ条件である。
- **使う前の損得の見積もり（ADR-0062）では、この命令を「相手に手札を捨てさせる」と同じく、カード 1 枚分の得 × 枚数と
  する。** 空回しでは相手の手札が空なので、絞り込みに合うカードがあるかは分からない。絞り込みつきの形も、
  同じ値にする。

## 検討した選択肢

**見た後に限って、相手の手札のカードを効果に渡す** — エンジンに追加するものが少なく、手札の中の枚数を使う形も
同じ API で実装できる。しかし、型の保証に例外ができる。「見た後だけ」という条件を型で守る仕組みが別に要り、
CPU の空回し（相手の手札を空として見せる）とも矛盾する。採用しない。

**絞り込みを、今回要るプロパティだけで持つ（ユニットに限るか・属性）** — 最も小さい。しかし、別の種別や別の軸の
絞り込みが出た時に、型を作成し直すことになる。採用しない。

**絞り込みを関数で渡し、エンジンが相手の手札のカードに当てる** — どんな条件でも表現できる。しかし、効果に
渡さないという保証が、型ではなく約束ごとになる。採用しない。

**「見る」確認の後に、別の選択として選ばせる** — 今ある確認の選択をそのまま使える。しかし、支配者の操作が
1 回増え、2 つの選択を結びつける決まりが別に要る。採用しない。

**CPU が絞り込みつきの形の見積もりを割り引く** — 当たらないかもしれない効果を当てにしすぎない。しかし、
割り引く値に根拠が無い。採用しない。

**CPU がランダムに選ぶ** — 実装は軽い。しかし、一覧を見たのに価値の低いカードを捨てさせることがある。採用しない。

## 既存の決定との関係

- **ADR-0002・ADR-0004。** 変更しない。効果が相手の手札の中身を受け取る API は、この決定の後も無い。
  選択の要求と見せる一覧は、支配者にだけ届く。
- **ADR-0041。** 同 ADR が「この決定が決めていないこと」に残した形を、この決定が埋める。見せる一覧・ログ・
  戻れるかどうかの決まりは、そのまま使う。
- **ADR-0052。** 同 ADR が「この決定が決めていないこと」に残した形を、この決定が埋める。命令の分け方は、
  同 ADR の (ii) にそろえた。
- **ADR-0018・ADR-0053。** 記録の形式は変更しない。新しい命令を使うのは新しいカードだけなので、記録済みの対戦を
  打ち直した結果は変化しない。
- **ADR-0038。** 古い画面には、知らない選択の目的と、知らないログの命令として届く。

## この決定が決定していないこと

- **相手の手札にある特定の種別のカードの枚数を、効果が使う形。** 選ばない形で、枚数だけを返す命令が別に要る。
  そのカードを実装する時に決定する。
- **席に着いていない視点（観戦）に、見たカードの名前を表示するか。** ADR-0041 と同じく、観戦を作成する時に決定する。
- **CPU が、カードの種別ごとの価値（ストラテジー・トラップ）を見積もること。** 基礎点の近似のまま選ぶ。

## 影響

- 効果の命令、選択の目的、ログに積む命令が、1 種類ずつ増える。
- 相手の手札の一覧が、行動の途中で支配者の画面に届く。画面の仕様書とモックを、実装の前に直す（ADR-0044）。
- CPU の命令の点数付け（`scoreInstructions`）と、選択への答え方（`scoreChoice`）に、それぞれ 1 件追加する。
  追加しなければ、損得 0・候補の差なしとして扱われる。
- この決定で実装できるようになるカード（EB1.0 の番号）: 055・075。

## 実装

- 効果の命令: `相手の手札を見て選ぶ`（項目は `conditions`・`disposal`・`mayDecline`）。効果から使う関数は `lookAtOpponentHandAndDiscard(conditions, { upTo })` で、`upTo` が「1 枚まで」（選ばないことを選べる）、偽が「1 枚」（必ず選ぶ）。枚数は 1 枚に限った。2 枚以上を選ばせるカードが出た時に、枚数と選ばせ方（1 枚ずつ複数回聞くか、1 回の要求で複数を選ばせるか）を一緒に決める。
- 絞り込みの値: `HandCondition`（軸は `種別`・`属性`。`TriggerFilter` と同じく、軸と値の組で持つ）。属性は、手札のカードに書かれたものを見る。
- 処置の値: `HandDisposal`（いまは `捨てる` だけ）。
- 選択の目的: `相手の手札から選ぶ`。絞り込みに合うカードが無い時は、候補が「確認した」（`CONFIRMATION`）の 1 つだけで、`mayDecline` は偽。
- 通信: `protocol.ts` の 3 か所に、新しい目的を追加した（確認の候補の作成、戻れるかの判定、候補が 1 つでも聞く判定）。戻れるかは、見たことのログが答えの後に積まれるので、ログではなく目的で判定する。
- ログ: 専用の命令は作らず、既にある行で積む。見たことは `相手の手札を見る`、捨てたカードは `ゾーンへ置く`（置き先は相手の捨札）。どちらも答えを受け取ってから積む。選んだ行は積まない。`loggedInstruction` にはこの命令の項を足し、来たら例外にする（`複数を選ぶ` と同じ）。
- 画面: `input-model.ts` の問いの文・見出し・効果の途中の選択の対象に、新しい目的を加えた。合うカードが無い確認だけの選択では、問いの文を「相手の手札に条件に合うカードはありません」にする。仕様書とモックも同じ。
- CPU: `probe.ts` の `scoreInstructions` は、カード 1 枚分の得（相手に手札を捨てさせる命令の 1 枚分と同じ）。`scored-cpu.ts` の `scoreChoice` は、選択の要求が見せる一覧（`shown`）から候補のカードを取得し、基礎点が最も高いカードを選ぶ。盤面の射影には相手の手札のカードが含まれないので、一覧から取得する。`cardBasePoints` は、通信に載せる表記（`WireCardFace`）も受け取る。
