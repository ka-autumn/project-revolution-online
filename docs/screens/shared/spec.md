# 全画面に共通する見た目の仕様

全画面に共通する見た目の決まりと、いくつかの画面で共有する部品（カードの面・アイコン）の仕様を書く。画面ごとの仕様は、それぞれのディレクトリの `spec.md` にある。

**この文書が今の見た目の仕様の正である**（ADR-0044）。仕様書・モック・実装が食い違ったときの扱いは、ADR-0032 と ADR-0044 に書いてある。

理由の記録: ADR-0027・ADR-0028・ADR-0029・ADR-0030・ADR-0034。

## 見た目の基準と、効かせる場所

- **色・角丸・影・見出しの字などの値は、`client` の `style.css` の `:root` の変数に一本化する。** どの画面も同じ変数から引く。将来、プレイヤーごとに背景などを差し替えられるよう、色は変数から引く。
- **変数を使って見た目を変えるセレクタは、画面ごとに、その画面の外枠の内側にだけ書く**（対戦画面 `.duel`、ロビー `.lobby`、名前を決める画面 `.naming`、待機中の画面 `.awaiting`、デッキ構築の画面の外枠）。素の `button` 要素や、画面をまたいで共有しているクラス（`.status`・`.leave`・`.choice__button` など）には、画面の見た目のための規則を書かない。
- **カードの面の見た目は、対戦画面・デッキ構築の画面・ロビーで共有する**（下の「カードの面」）。
- 確認のダイアログと共有のダイアログ（`.confirm`）は、デッキ構築の画面の見た目にする。使っているのはデッキ構築の流れ（削除・変更を捨てる・共有）と、ロビーの「…」から開く窓である。対戦画面は自分の部品を持つ（`duel-dialogs/spec.md`）。

## テーマ

- **テーマは 1 つ。** 明るい地・暗い地の切り替えは持たず、ダークモードには対応しない。各画面の外枠で `color-scheme` を `light` に固定する。
- **地は明るい金・橙の光条。** 中心が白く、外へ向かって金から橙になる放射状のグラデーションに、白い光の筋を重ねる（カードの裏面の雰囲気に寄せたもの）。
- **パネルはクリームの半透明に金の縁。**
- **見出しの字は全画面でゴシック 1 種**（`--heading-font`。`'Yu Gothic UI', 'Yu Gothic', 'Hiragino Sans', 'Noto Sans JP', system-ui, sans-serif`）。外部の字体は読み込まない。見出しの色は焦げ茶。例外は、カードの裏面の丸の中の「R」だけで、紋章の意匠として `Georgia` の欧文にする。
- 角丸はパネル 12px・小さな部品 7px。
- 主ボタンは金の地。

## 画面の中に重ねる

ブラウザ標準のダイアログ（`window.confirm` など）は使わない。確認・選択・窓は、どれも画面の中に重ねる。

## 押せない手を出さない・読み上げ

- 押して断られるだけの手は、押せる形で出さない。何が行えるかを決めるのはサーバで、画面は届いたものから並べる（ADR-0010）。
- 押せる・選んでいる・押せないことは、色だけで区別させない。読み上げに名前と状態を付ける。
- 繋がっていない間は、答えを送らない。

## 描き直しの間の手の置き場

- **変換中の入力欄は、描き直しで壊さない。** 変換が始まってから確定するまでの間は、描き直しを後に回し、確定したら 1 回描き直す。対象はすべての入力欄である。変換中は、ほかの人の操作による切り替わり（切断の表示など）も例外なく待つ。
- 入力欄でないもの（押して選ぶもの・メニュー・タブ・ページ送り・カルーセルなど）にも、描き直した後の手の戻し先を持たせる。対戦画面の手の戻し方は `duel/spec.md` に書く。

## カードの面

対戦画面・デッキ構築の画面・ロビーで共有する。カードの画像は出さず、文字と図で面を組む。

- **地は上が白、下がカードの色のグラデーション。** 白のカードは下を薄い灰色にし、文字を黒にする。将来はこの下にカードのイラストを敷き、このグラデーションを半透明で重ねる想定。
- 左上にレベルアイコン、右上に種別（地はレベルアイコンと同じ色）。
- その下に名前の行。**名前の地の枠は、スター・キーワード能力のアイコンまで含め、アイコンは枠から上下にはみ出させる。**
- 下のほうに、ムーブアイコン（右寄せ）・トリガーアイコン（左寄せ）、属性、BP（左下、半透明の黒の地）・SP（右下、カードの色の地）。BP・SP は数字だけ。トリガーアイコンを左に置くのは、印刷でテキストの左にあるのに合わせるためで、トラップには BP・SP が無いので、左下は空いている。
- **属性の区切りは「 | 」。** 面・詳細・一覧のどこでも同じ。
- **ＢＰとＳＰの間に、ブロックのロゴを置く。** ユニット以外はＢＰ・ＳＰが無いので、ロゴだけを下の真ん中に置く。ロゴの画像は開発者が用意し、届くまでは略号を入れた丸で代える。ブロックのデータ（ADR-0035）が届くまでは出さない（#230）。
- 裏面は、金・橙の光条の中の丸に「R」。
- 複数の色を持つカード・無色のカードの面は考えない（今のカードプールに無い）。無色のカードは黒の面で描く。

### アイコン

- **レベルアイコン**：色ごとに形が違う（赤＝丸、青＝八芒星、白＝六芒星、緑＝五角形、黒＝六角形）。開発者が用意した SVG をそのまま使い、リポジトリに含める。色を表すアイコンとしても、どの画面でもこの形を使う。
- **スターアイコン**：名前の左に ★。スターが 2 以上なら、★ の中に赤い数字を入れる。
- **リバーススターアイコン**：緑を基調にした、逆さの ★。
- **キーワード能力のアイコン**：半透明の宝石の球に、ゴシック体で字を載せる。夢＝サファイア（青）、希望＝ルビー（赤）、幸運＝トパーズ（黄）、苦労＝暗いエメラルド（緑）。**プランゾーンに関わる 4 つ（`PlanKeyword`）だけがこの扱いで、元気・信頼・根性・勇気のような、それ以外のキーワード能力にはアイコンを付けない。** これらはカードの詳細のテキストにそのまま出る。キーワード能力のアイコンは、カードの詳細では名前の右に出す。小さな面のカードの中には出さない。
- **ムーブアイコン**：菱形の中に上下左右の矢印。動ける向きだけ白く、ほかは暗くする。
- **トリガーアイコン**：種類で描き分ける（ADR-0039）。攻撃とスマッシュは、印刷されたアイコンをなぞる。
  - **侵入**：3×3 のスクエア。侵入の対象のスクエアは赤、ほかは濃い灰色。
  - **攻撃**：暗い枠の左上に「Attack」の文字。上に相手のカード（帯が上で、相手の向き）、下に味方のカードを重ね、上から下へ橙の矢印が下りる。
  - **スマッシュ**：暗い枠の左上に「Smash」の文字。縦向き（リリース状態）の相手のカード（帯が上で、上下を逆にする）の上に、横向き（フリーズ状態）のカードを重ね、縦向きから横向きへ曲がった橙の矢印が上る。
  - **攻撃の絞り込み**：枠の左下に文字で書く。メーカーシンボルと属性は値のまま、色は英語で書く（Red・Black・Blue・White・Green）。長い文字は、左下に収まる幅に詰める。読み上げとデッキを組む画面の行には、日本語で書く（「攻撃（色 赤）」など）。
  - **知らない種類**：図を描かず、読み上げに「（表示できないトリガーアイコン）」と書く（ADR-0038）。

どのアイコンも、読み上げに中身を持たせる（「ムーブアイコン：上・左・右」「トリガーアイコン：味方エリア・左…」「トリガーアイコン：攻撃（色 赤）」「スター 2」など）。

### 能力テキストの行頭

- 能力テキストは、届いた行の並びを保ち、空でない各行の頭に「●」を表示する。画面の幅で折り返した続きには付けない。空のテキストや空白だけの行に「●」だけを出さない。
- キーワード能力だけの行、ストラテジー・トラップの効果と発動条件、1 行だけのテキストも対象とする。エキスパンションによる例外は設けない。
- 対戦画面の拡大した面、デッキ構築の詳細の全文、スマートフォンの詳細シートと行き先選択中の帯、ログイン中の共有レシピの詳細で共通にする。デッキ構築の詳細では、面の本文欄は出さない（`deck-builder/spec.md`）。
- 「●」は表示時に足す。カード定義・通信のテキストには書き込まない。記号は読み上げ対象から外し、本文と行の区切りは保つ。
- 運用の注記や「テキストなし」の案内には付けない。注記が指す「n つ目の効果」は、能力テキストの「●」を上から数えた順と一致させる。

### 運用の注記の枠

運用の注記（ADR-0043）を持つカードの詳細には、注記の枠を出す。出す場所は画面ごとに書く（対戦画面・デッキ構築の画面）。

- 枠は、カードの面の外に置く。面は印刷の再現で、注記は印刷されていないためである。
- 青みのある灰色の地に、左に同じ系統の色の線を引き、頭に「注記」の見出しを付ける。画面のほかの部分（紙の色・橙・カードの色・相手の赤）と違う色にして、印刷されたテキストと見分けられるようにする。
- 注記を持たないカードには、枠を出さない。

## スマートフォン

### 縦向きに対応し、横向きでは向きを変えるよう案内する

- **縦向きに対応する。**
- **横向きで開いたとき（横長で、高さが 500px 以下）は、画面全体を覆って「画面を縦向きにしてください」と案内し、操作できないようにする。** 崩れた並べ方を見せないため。どの画面でも同じに出す。覆っている間は、下の画面を Tab や読み上げからも止める（`inert`。覆いが受け止めるのはマウスと指だけなので）。対戦の途中で端末が傾いても、縦に戻せば続きから操作できる（覆うだけで、状態には触らない）。PC の窓を高さ 500px 以下の横長にした場合も、同じ案内が出る。

### スマートフォンの並べ方に切り替える境目は、幅 768px

- **画面の幅が 768px 以下なら、スマートフォンの並べ方にする。** 判定は幅だけで行い、指で操作する端末かどうか（`pointer: coarse`）は見ない。ブラウザの幅を変えるだけで確かめられるようにするため。PC の小さな窓（幅 768px 以下）も、スマートフォンの並べ方になる。タブレットは幅で決まり、専用の並べ方は持たない。
- **PC の大きさ（幅 769px 以上）の並べ方・見た目・キーボード操作は、スマートフォンの並べ方に左右されない。** スマートフォン向けの見た目は、境目のメディアクエリの中にだけ書く。スマートフォンでだけ出す部品は、PC では出さず、PC の並べ方に入り込まない置き方にする。PC での Tab の順・読み上げの順を変えないよう、要素の DOM の順は入れ替えない（例外はデッキ一覧。`deck-list/spec.md`）。

### 指での操作

マウスを乗せて見ていたもの（カードの詳細など）は、指では見られない。**カードを 1 回タップすると、下からせり上がるシートに、カードの詳細と、そのカードで行える手のボタンを出す。**

- シートは、ダイアログと同じく、ほかの部分を暗くした上に重ねる。暗くしたところを押すと閉じる（手を送ったあと、返事が届くまでは閉じない）。
- **閉じる口は、シートの一番下に置く。** 片手の親指が届く位置だから。行える手があれば「キャンセル」、詳細を見るだけなら「閉じる」とする。
- 指で押すボタン・押せる行の高さは 2.75rem（約 44px）以上にする。
- 入力欄の文字は 16px にする。
- マウスを乗せたときだけ出てくるもの（右の列のカードの詳細など）は、スマートフォンでは使わない。
- 画面の真ん中に出す窓（デッキを消す確認・変更を捨てる確認・共有の窓、お知らせの窓など）は、どこから開いても幅いっぱいに出す。

### スマートフォンでは、クリックモードで描く

**幅 768px 以下では、対戦画面の操作のしかたの切り替えを出さず、クリックモードで描く。** ボタンモードのスマートフォン向けの並べ方は持たない。操作のしかたは端末に保存していないので、切り替えた値はそのまま残り、幅が 769px 以上に戻ればその値で描く。

## 持たないもの

- カードの画像。立ち絵も画像は使わない。
- 横向きの並べ方。タブレット専用の並べ方。
- 指で引っ張って置く操作（ドラッグ）や、ピンチでの拡大の制御。
- ホーム画面への追加やオフラインでの起動など、アプリとしての配布。
