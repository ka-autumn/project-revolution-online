# 画面の仕様とモック

各画面の見た目の仕様（`spec.md`）と、それを目で見て確かめるための HTML のモック（`index.html`。実際には動かない見本の画面）を、画面ごとのディレクトリに並べて置く。**見た目の仕様は `spec.md` に文章で書いたものを正とし、モックはそれを目で見て確かめるための見本とする**（ADR-0032・ADR-0044）。仕様書・モック・実装が食い違っていたときの扱いは、ADR-0032 に書いてある（「ADR」を仕様書に読み替える）。

各画面の見た目をなぜそう決めたかは、仕様書の冒頭に挙げた ADR にある。

## 開き方

| ディレクトリ | 画面 | 仕様 | モック |
| --- | --- | --- | --- |
| `naming/` | 名前を決める画面 | [`spec.md`](naming/spec.md) | [`index.html`](naming/index.html) |
| `lobby/` | ロビー | [`spec.md`](lobby/spec.md) | [`index.html`](lobby/index.html) |
| `deck-list/` | デッキ一覧 | [`spec.md`](deck-list/spec.md) | [`index.html`](deck-list/index.html) |
| `deck-builder/` | デッキ構築 | [`spec.md`](deck-builder/spec.md) | [`index.html`](deck-builder/index.html) |
| `waiting/` | 相手を待っている間の画面 | [`spec.md`](waiting/spec.md) | [`index.html`](waiting/index.html) |
| `duel/` | 対戦画面 | [`spec.md`](duel/spec.md) | [`index.html`](duel/index.html) |
| `duel-dialogs/` | 対戦中の確認ダイアログ・選ぶダイアログ | [`spec.md`](duel-dialogs/spec.md) | [`index.html`](duel-dialogs/index.html) |
| `shared/` | 全画面に共通する決まり・カードの面 | [`spec.md`](shared/spec.md) | （各画面のモックで見る） |

モックは、各ディレクトリの `index.html` を、ブラウザで直接開く（`file://` のままでよい）。サーバも `private/` も要らない。

- どの画面のモックも、ブラウザの幅を 768px 以下にして開くと、スマートフォンの並べ方が見られる。
- 横向きの案内は、どの画面のモックでも見られる。横長で高さを 500px 以下にすると、縦向きにするよう案内する画面が全面に出る。
- ブラウザの幅を変えずにスマートフォンの大きさで見るには、[`phone.html`](phone.html) を開く。選んだ画面のモックを、選んだ大きさ（幅 360〜430px の縦向きと、横向き）の枠に入れて見せる。枠の中のモックは、枠の幅を画面の幅として受け取るので、モックそのものの見え方と変わらない。
- 画面の端にある黒い帯は、モックの中の切り替え（本番の画面には無い部分）。1 つの画面の中で見た目が変わる場面（名前を断られたとき、勝敗が決まったときなど）を見るのに使う。
- 実装で別の画面へ移るボタン（「これにする」「対戦部屋を作成する」「デッキ一覧」「編集」「やめてロビーに戻る」など）は、押すと移った先のモックが開く。相手を待っている間の画面から対戦画面へは、押すボタンが無いので、黒い帯の「相手が来た → 対戦へ」から移る。
- 対戦中のダイアログのモックは、ダイアログをどこにどう重ねるかを見るためのもので、後ろの盤面は簡単な枠だけにしてある。盤面の見た目は `duel/` で見る。
- 対戦画面のモックは、URL に `?trap-icons` を付けて開くと、自分の手札がトリガーアイコンの見本（攻撃・絞り込みつきの攻撃 3 種・スマッシュ）の 5 枚に替わる。既定の手札は変わらない。
- ロビー・デッキ一覧・デッキ構築には、まだ作っていない機能（鍵付きの部屋・観戦・お知らせ・自分で選ぶラベル・パートナーカード・ブロックなど）も描いてある。それぞれ別の Issue で作る予定で、実装にまだ無いのはそのためである。仕様書では、それぞれ Issue の番号を添えている。

## 直すとき

- **実装の見た目を変えるプルリクエストでは、そのプルリクエストの中で、対応する画面の仕様書とモックも直す**（ADR-0032・ADR-0044）。
- 見た目の変更で新しい ADR を書くのは、選択肢を比べて方針を決めた時だけである（ADR-0044）。そのときは、仕様書の該当の項から ADR を引く。
- 新しい画面やダイアログは、開発者が採用を決めてから、ディレクトリを作って仕様書とモックを置く。検討の途中で作った案は入れない。
- いくつかの画面で使うモックの部品は `shared/` にある。

| ファイル | 中身 | 使っている画面 |
| --- | --- | --- |
| `shared/card.css` | カードの見た目 | ロビー・デッキ一覧・デッキ構築 |
| `shared/pool-data.js` | 見本のカード（`window.POOL`） | ロビー・デッキ一覧・デッキ構築 |
| `shared/deck-builder.css`・`shared/deck-builder.js` | デッキ一覧とデッキ構築の画面（どちらの画面として開くかは、`index.html` の `window.MOCK_VIEW` で決まる） | デッキ一覧・デッキ構築 |
| `shared/naming-waiting.css` | 名前を決める画面と、相手を待っている間の画面の見た目（横向きの案内も含む） | 名前・待っている間 |
| `shared/star.svg`・`shared/reverse-star.svg`・`shared/level-icons/` | スター・リバーススター・レベルのアイコン（アプリの `packages/client/src/assets/` と同じもの） | ロビー・デッキ一覧・デッキ構築 |

対戦画面と対戦中のダイアログは、CSS とカードをそれぞれの `index.html` の中に持っている。ロビーは、自分の CSS を `index.html` の中に持ち、カードの見た目と見本のカードは `shared/` から読み込む。

`file://` で開けるように、`fetch` や ES モジュールは使わない。CSS・画像・ふつうの `<script src>` だけで作る。

## 見本のカード

実際のカードの名前・能力テキスト・作品名は載せない（ADR-0002）。モックのカードはすべて架空のものである。仕様書の例に出すカードも架空のものにする。

- 名前は「見本・」で始める。実際のカードと取り違えないようにするためである。
- 種類・レベル・色・スター・BP・SP・ムーブアイコン・トリガーアイコンは、実際のカードと同じくらいのばらつきを持たせてある。長い名前や長い能力テキストも混ぜて、レイアウトが崩れないかを確かめられるようにしている。
- 能力テキストは自分で書いた文。「夢」「希望」のようなキーワード能力の名前は総合ルールに出てくる言葉なので使ってよい（ADR-0007）。その説明は「（キーワード能力）」とだけ書いている。
- 属性・作品名（「見本作品Ａ」など）・ブロック（「見本書房」など）・エキスパンション（「見本デッキ A」）も架空のもの。ブロックのロゴは、略号を入れた丸で代わりにしている。
- 実際のカードでモックを見られる仕組みは作らない。

カードを追加したり直したりするときは、コミットする前に、実際のカードの名前・作品名・属性などでこのディレクトリを検索し、1 件も見つからないことを確かめる。公開リポジトリに push したものは取り消せない。
