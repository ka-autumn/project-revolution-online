# 画面のモック

各画面の見た目の決まり（ADR）の図版として置いている HTML のモック。**見た目の決まりの正は ADR の文章で、モックはその図版である**（ADR-0032）。

## 開き方

ブラウザで、各ディレクトリの `index.html` を直接開く（`file://` のままでよい）。サーバも `private/` も要らない。

| モック | 画面 | 見た目の決まり |
| --- | --- | --- |
| [`naming/`](naming/index.html) | 名前を決める画面 | ADR-0030 |
| [`lobby/`](lobby/index.html) | ロビー | ADR-0029 |
| [`deck-list/`](deck-list/index.html) | デッキ一覧 | ADR-0028 |
| [`deck-builder/`](deck-builder/index.html) | デッキ構築 | ADR-0028 |
| [`waiting/`](waiting/index.html) | 待機中の画面 | ADR-0030 |
| [`duel/`](duel/index.html) | 対戦画面 | ADR-0027 |
| [`duel-dialogs/`](duel-dialogs/index.html) | 対戦の確認ダイアログ・選ぶダイアログ | ADR-0031 |

- 画面の右下や上にある黒い帯は、モックの中の切り替え（本番には無い部分）。1 つの画面の中の状態（「断られた」「決着」など）を見るのに使う。
- 実装に画面の移動があるボタン（「これにする」「対戦部屋を作成する」「デッキ一覧」「編集」「やめてロビーに戻る」など）は、押すと移った先のモックを開く。待機中の画面から対戦画面へは押すものが無いので、切り替えの帯の「相手が来た → 対戦へ」から移る。
- 対戦のダイアログのモックは、ダイアログの置き方を見るためのもので、後ろの盤面は簡略な枠にしてある。盤面の見た目は `duel/` を見る。
- ロビー・デッキ一覧・デッキ構築には、別の Issue で作る予定の機能（鍵付きの部屋・観戦・お知らせ・持ち主が選ぶラベル・パートナーカード・ブロックなど）も描いてある。実装にまだ無いのは、その Issue が入っていないためである。

## 直すとき

- **実装の見た目を変える変更では、同じ変更の中で、対応するモックも直す**（ADR-0032）。決まりそのものを変えるなら ADR も直す。
- 新しい画面・ダイアログのモックは、採用が決まってからここに置く。途中の案は持ち込まない。
- 複数の画面で使う部品は `shared/` にある。

| ファイル | 中身 | 使っている画面 |
| --- | --- | --- |
| `shared/card.css` | カードの面の見た目 | ロビー・デッキ一覧・デッキ構築 |
| `shared/pool-data.js` | 見本のカード（`window.POOL`） | ロビー・デッキ一覧・デッキ構築 |
| `shared/deck-builder.css`・`shared/deck-builder.js` | デッキ一覧とデッキ構築の画面（どちらとして開くかは `index.html` の `window.MOCK_VIEW` が決める） | デッキ一覧・デッキ構築 |
| `shared/naming-waiting.css` | 名前を決める画面と待機中の画面の見た目 | 名前・待機中 |
| `shared/star.svg`・`shared/reverse-star.svg`・`shared/level-icons/` | スター・リバーススター・レベルのアイコン（アプリの `packages/client/src/assets/` と同じもの） | ロビー・デッキ一覧・デッキ構築 |

対戦画面と対戦のダイアログは、CSS とカードをそれぞれの `index.html` の中に持っている。ロビーは、自分の CSS を `index.html` の中に持ち、カードの面と見本のカードは `shared/` から読む。

`file://` で開けるように、`fetch` や ES モジュールは使わない。CSS・画像・ふつうの `<script src>` だけで組む。

## 見本のカード

実際のカードの名前・能力テキスト・作品名は置かない（ADR-0002）。モックのカードはすべて架空の見本である。

- 名前は「見本・」で始める。実在のカードと取り違えないため。
- 種類・レベル・色・スター・BP・SP・ムーブアイコン・トリガーアイコンは、実際のカードの値の幅を残してある。長い名前・長い能力テキストも混ぜて、レイアウトの確認に使えるようにしている。
- 能力テキストは自前の文。キーワード能力の名前（夢・希望など）は総合ルールの語なので使ってよい（ADR-0007）。注釈は「（キーワード能力）」とだけ書く。
- 属性・作品名（「見本作品Ａ」など）・ブロック（「見本書房」など）・エキスパンション（「見本デッキ A」）も架空。ブロックのロゴは略号の丸で代えている。
- 実際のカードで見るための仕組みは作らない。

カードを足す・直すときは、コミットする前に、実際のカードの名前・作品名・属性などでこのディレクトリを検索し、当たらないことを確かめる。公開側への push は取り消せない。
